The command palette

One search box for the whole web app. Press ⌘K on any page, type, and open a page, an action, an account or a transaction.

Language Simplified Technical English (ASD-STE100) Source Web redesign, open item 5 Date 2026-10-23
01

What it is

The palette is a dialog with a search field and one list of results. It replaces a click path with a few keys.

The web redesign puts “Search” with ⌘K in the top bar (H1). Open item 5 of that spec says: do not show “Search” until the palette exists. This spec defines the palette. When the palette ships, “Search” goes into the top bar.

The palette finds three types of things:

  • Commands. The pages of the app and the actions that make a new item.
  • Your items. Accounts, goals, budgets, categories and tags, by name.
  • Your transactions. By description or by amount.

The palette does not replace the search field on Transactions (§5.12). The last row of the results opens that list with the same query.

1

Shortcut

⌘K on a Mac, Ctrl K on other systems. Both keys work on every system.

8

Groups

Actions, Go to, Accounts, Goals, Budgets, Categories, Tags and Transactions.

New libraries

The palette uses the Dialog and Autocomplete of Base UI, which the app already has.

02

How it opens

The shortcut opens the palette on every page. The button in the top bar shows on wide screens only.

The button. “Search” sits in the top bar, after the space and before “New transaction”. It shows a search icon, the word “Search” and the shortcut. The shortcut reads ⌘K when the browser runs on an Apple system. On other systems it reads Ctrl K. The server reads the system from the User-Agent header, so the first render is correct.

The shortcut. ⌘K and Ctrl K open the palette, also when the focus is in a field. When the palette is open, the same keys close it. The keys do nothing while a confirmation dialog or a form dialog is open: that dialog owns the keyboard.

Narrow screens. The rules of the redesign spec (§03) apply:

  1. From 1000px: the top bar shows “Search”.
  2. From 760px to 999px: the top bar hides “Search”. The shortcut still opens the palette.
  3. Below 760px: the top bar shows the brand and the avatar only. The shortcut still opens the palette.
03

What it finds

The results come in groups. The groups always have the same order. A group with no match does not show.

Each result is one row: an icon, a title, an optional second line and an optional figure on the right. Each row opens one URL. The palette closes before the navigation.

The palette shows live items only. It does not show archived accounts, archived categories or deleted rows.

Each group shows a maximum of 5 rows. After the transactions, a last row opens /transactions?q=… with the query. That list also matches category and account names, so it can show more rows than the palette.

04

Ranking

A pure function in @saldo/core gives each match a score. A higher score comes first in its group.

Text. The function compares the query and the title after normalizeText: lower case, no accents, single spaces. It uses the first rule that applies:

  1. The title is the query: score 400.
  2. The title starts with the query: score 300.
  3. Each word of the query starts a word of the title: score 200. The order of the words is free.
  4. The title contains the query: score 100.
  5. The title contains each word of the query: score 50.

No rule applies: the row is not a match.

Amounts. A query with digits and no letters is also an amount. The function removes currency symbols and spaces. A separator with 1 to n digits after it is the decimal separator, where n is the number of decimals of your currency. All other separators group thousands. Thus 12,50, 12.50 and € 12,50 are the same amount, and 1.234 is one thousand two hundred thirty-four euros.

  • A whole number, such as 12, matches 12.00 with score 300, and 12.01 to 12.99 with score 200.
  • A number with decimals matches that amount only, with score 300.

A transaction gets the higher of its text score and its amount score. If two rows have the same score, the newer date comes first. Rows with no date keep the order of their page (the order you set on Accounts or Categories).

05

How results load

The browser ranks the commands. The server ranks your data. Each request reads the data of the signed-in user only.

Commands. The (app) layout gives the palette the translated labels of the pages and the actions. The browser ranks them at each key, with the same core function. They show without a request.

Your data. The palette calls the Server Action searchAction(query) 150ms after the last key. The action:

  1. Reads the session with requireWebUser. A Server Action is a public endpoint, so the action checks the session itself.
  2. Loads the data with loadUserData(user.id). The id comes from the session, never from the request.
  3. Ranks the items and the transactions with rankSearch of @saldo/core.
  4. Sends back the rows: titles, formatted figures and URLs. It sends no other field.

The palette keeps the last rows on screen while a new request runs. It drops an answer for a query that is not the current query.

Why not the layout

The layout already loads your data, but it cannot send all transactions to the browser on each page. The rows of the action are a maximum of 30, whatever the size of the ledger.

06

The keyboard

The focus stays in the search field. The arrows move the highlight in the list.

The first row is always highlighted. When the results change, the highlight goes back to the first row. When the palette closes, the focus goes back to the element that had it before: the “Search” button, or the page.

The single-key shortcuts of the shell, such as N, do nothing while the palette is open. The palette is a dialog, and ignoresShortcut already gives a dialog all the keys.

KeyEffect
⌘K / Ctrl KOpens the palette. When it is open, closes it.
↑ ↓Moves the highlight to the previous or next row, across the groups.
EnterOpens the highlighted row and closes the palette.
EscCloses the palette. The query is not kept.
TabStays in the dialog.
07

States

The palette has four states: empty query, results, searching and no results.

Position. The dialog is 640px wide and starts at 12% of the screen height. Below 760px it fills the width, with 8px at each side, and starts 8px from the top. The list scrolls inside the dialog.

Searching. While a request runs, the list keeps the last rows and the field shows “Searching…” on its right. The first request of a query shows the commands at once.

No results. The palette says “Nothing matches “…”.” and why. The row “See all for “…” in Transactions” stays, because that list searches more fields.

Error. If the action fails, the palette shows “The search did not work. Try again.” The commands stay.

The footer. It shows the keys. It does not show on a touch screen.

08

Access and motion

The palette follows the combobox pattern of WAI-ARIA. Base UI gives the roles, and the app gives the names.

  • The dialog has the name “Search Saldo”. The field has the same name.
  • The field is a combobox. It points to the list with aria-controls, and to the highlighted row with aria-activedescendant.
  • The list is a listbox. Each group is a group with its label. Each row is an option.
  • A status region says “Searching…”, the error, or “Nothing matches”. A screen reader reads it.
  • The “Search” button has aria-keyshortcuts="Meta+K Control+K". The visible ⌘K is hidden from screen readers.
  • The dialog uses the tokens of @saldo/ui, so it follows the light and the dark theme.

Motion. The dialog fades in and moves 4px down in 150ms, with --motion-easing. It closes without motion. With prefers-reduced-motion: reduce, the dialog only fades.

09

Open questions

Each question has a default. The plan uses the default. Change it in a later spec if necessary.

  1. A touch entry below 1000px. The redesign spec gives no button below 1000px. A tablet with no keyboard cannot open the palette. Default: follow the redesign spec. Transactions keeps its own search field.
  2. Archived items. Default: the palette does not show them. Accounts and Categories have their archive pages.
  3. Admin pages. Default: not in the palette. The Profile menu shows them to an admin.
  4. Recent items. A list of recent rows with an empty query needs storage. Default: no recent items. The empty query shows the commands.
  5. Search in notes, tags and category names of a transaction. Default: no. The palette matches the title and the amount. The Transactions list matches more fields, and the last row opens it.
  6. Ctrl K on a Mac. In a macOS text field, Ctrl K deletes to the end of the line. Default: the palette takes the key on every system, because one rule is simpler to learn.
