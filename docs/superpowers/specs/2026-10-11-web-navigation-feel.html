Saldo web · Navigation · Spec

Every click shows its result at once

A click on a tab, a chip, a period arrow or a panel changes the screen in the frame of the click. The server still renders the data. The browser shows a pending state until the data arrives.

Language Simplified Technical English (ASD-STE100) Source Spec §17.1.7 · TODO «Web app: a UI pass» · spec 2026-10-07 Plan 2026-10-11-web-navigation-feel.md Date 2026-10-11
01

Problem and scope

The user reported on 2026-10-11 that a click on a tab, a chip, a period arrow or a panel feels slow.

The 2026-10-07 spec made the panels of Transazioni open in place. The other clicks still show nothing until the server answers.

The code shows three causes. Nobody has measured them yet. The plan measures them before it changes the code (section 07).

  1. No page has a loading.tsx. Thus a click shows nothing until the server sends the whole page.
  2. The server waits on a chain of four steps: the session, isRevoked, loadUserData and, in the layout, isAdmin.
  3. Every panel outside Transazioni is still a navigation. Each open and each close of a panel waits for the server.
Out of scope

This spec does not change the production region (fra1::iad1). A loading state hides the wait. It does not make the wait shorter. The region stays as its own item in TODO.md.

02

Decisions

The user made these decisions on 2026-10-11. Each decision has a reason that the code supports.

DecisionReason
Keep next/linkA plain <a> loads the whole page again and removes the mounted shell. Today there is no large prefetch to remove: with no loading.tsx, Next.js has almost nothing to prefetch.
No dialogsThe panel beside the list is decision §17.1.7 of the POC spec. A dialog does not remove the wait for the server. Keep dialogs for short confirmations only.
Server componentsPages stay server components. A client fetch adds a round trip after the JavaScript loads, and it repeats the query. Use streaming: first the shell and a skeleton, then the data.
Filters stay navigationsA filter, the period and the search go to the server. They show a pending state. Only a panel changes in place.
Panels in place everywhereThe panel in place applies to every page with a panel: Conti, all Profilo sections and all Admin sections.
Some forms navigateA form that needs data that only the server calculates for one row stays a navigation. Examples: the edit form of a transaction, and possibly the edit form of an account.
03

Feedback in the frame of the click

A change of page shows the shell and a skeleton at once. A change on the same page shows a thin bar after 150 ms.

AppLink. Every link that navigates uses AppLink. It is next/link with one child, LinkPending. Only AppLink.tsx imports the Link of next/link. NavPending.tsx imports only useLinkStatus from it. A test makes sure of this.

LinkPending. It calls useLinkStatus. This hook works only in a child of the <Link>. Thus LinkPending must be inside the link. It renders null, so it adds no node and no layout.

NavPendingProvider. The (app) layout mounts it. It keeps a count of the navigations that wait for the server. Each pending link adds 1. When the navigation ends, the link removes 1. It keeps a second count for the skeletons on the screen (see loading.tsx below).

The bar. When the count is more than 0, the provider shows a bar of 2px at the top of the page. A CSS delay of 150 ms hides the bar for a quick answer. The bar grows slowly and never reaches the end, because nobody knows the duration of the wait.

The status text. The provider always renders a hidden role="status" element. A screen reader often does not read a live region that arrives with its text. When a navigation waits or a skeleton shows, a timer of 150 ms starts. After the timer, the text is common.loading: «Loading…». When nothing waits, the provider stops the timer and the text is empty. Thus a quick navigation says nothing, as it shows nothing.

useNavTransition. Some navigations start from code with router.push: the search, the list keys, the close of a panel, the N shortcut and «Record the expense» when a goal closes. They call router.push inside a transition from useNavTransition. The transition reports to the same count.

loading.tsx. Six files add Suspense boundaries: one in each tab (home, transactions, stats, accounts), one in profile and one in admin. The layout stays mounted. Thus a change of page shows the shell and PageSkeleton at once. The sub-navigation of Profilo and Admin also stays on the screen. PageSkeleton holds SkeletonPending, a client part that renders nothing. It adds 1 to the count of skeletons while the skeleton is on the screen.

Do not put a loading.tsx in (app). It wraps the admin layout too. The notFound() of that layout then streams after the shell, and a member gets the status 200 for /admin, not 404.

Note

A change of query on the same page does not show loading.tsx. Examples: a chip, the period arrows, the search. These clicks use the bar.

04

A shorter chain

Today a page waits for four steps, one after the other. After the change, the chain has two database reads.

Today authenticate reads the session, then reads the user row again for isRevoked. Then readPage calls loadUserData. The layout reads the user row a third time for isAdmin. The layout and the page run in parallel, but each one starts after the session.

The admin plugin of Better Auth already puts role and banned on session.user. getSession reads the database on each call, because the app sets no cookie cache. Thus role and banned on session.user are as fresh as the two extra reads.

  1. authenticate returns null when session.user.banned is true. It does not call isRevoked.
  2. AuthenticatedUser gets role. The layouts use isAdminUser(user) for a page render.
  3. readPage starts searchParams together with the session.
Caution

A mutation must not trust a role from the render. Server Actions and requireWebAdmin keep their call to isAdmin(db, id).

05

The panel in place on every page

The state machine of TransactionsPanels becomes a shared controller. Every page with a panel uses it.

The controller. usePanelController keeps the URL as the state. It changes the URL with history.pushState and keeps a list of the URLs that it wrote. A URL that is not on the list comes from a navigation. The controller then follows that URL. On popstate (Back, Forward) it reads the panel from the URL. A close plays the exit for 150 ms. After the close, the focus goes back to the element that opened the panel.

The panel key. A key is the string that names what the URL opens: new, tag:ID, a:ID, archived. Each page declares its flags (?new) and its values (?tag=ID). A flag wins over a value, unless the page gives an order. Conti and Categories give one, because they let a value win over archived. panelOnlyChange compares two URLs. If only the panel parameters change, it gives the new key. Otherwise it gives null, and the click is a navigation.

PanelSwitch. The page renders the body of every panel on the server, as Transazioni does with the details. The page gives PanelSwitch a map from key to panel. A click only selects the panel to show. A key that has no entry in panels is a navigation.

PanelLink. The rows and the «New» links use PanelLink. A plain click goes to the controller. A click with ⌘, Ctrl or Shift keeps the behaviour of a link.

SlotPortal. Profilo and Admin show the panel in the #profile-panel slot of SubnavLayout. SlotPortal is the portal part of SlotPanel, so PanelSwitch can use it.

Load and save. A load of a URL with a key opens the page with the panel open. A save stays a navigation, so the list shows the new values.

06

Accessibility and motion

This spec adds no new motion to the panels. The bar and the skeleton follow the «reduce motion» setting.

The rules of the 2026-10-07 spec for motion, focus and Esc still apply. This spec applies them to more pages.

PartNormalReduce motion on
BarShows after 150 ms. Grows from 5% to 90% of the width over 8 s.Shows after 150 ms at full width. It does not grow.
SkeletonThe blocks pulse slowly (1.4 s).The blocks do not pulse.
Status textA hidden role="status" element says «Loading…» 150 ms after a navigation starts to wait or a skeleton shows, until nothing waits. A quicker answer says nothing. The bar itself has aria-hidden="true".
Skeleton for a screen readerPageSkeleton has aria-hidden="true". It says nothing about the content. The link stops being pending when the skeleton shows. Thus SkeletonPending keeps «Loading…» until the page replaces the skeleton.
Bar during a skeletonThe bar does not show. The skeleton already shows that the page loads, and two signals for one wait add motion with no new information.
PanelsAs on Transazioni: the pointer gets the entrance and the exit. The keyboard and Esc change the panel on the next frame. The focus returns to the opener after a close.
07

How to measure

A script measures four inputs on a production build, before the change and after each part of the plan.

The script measure-nav opens a signed-in page at 1440px. Chrome runs with the CPU four times slower. For each input the script records two times from the click:

  1. feedback: the first frame with a change on the page. A MutationObserver on document.body records the time.
  2. settled: the first moment when the URL is new and main holds no skeleton. The root of a skeleton has the attribute data-skeleton. The script checks this in the same callback as «feedback», and in each frame. Only the Accounts page has a main h1, so the script does not use a new title.

Before the change, «feedback» is equal to «settled», because nothing shows before the new page. After part A, «feedback» for a tab must be less than about 50 ms. For a chip or a period arrow, «feedback» is about 150 ms (the delay of the bar) when the server is slower than that.

pnpm --filter web measure:nav http://localhost:3100

The plan also counts the queries for one request on /transactions, before and after part B. A temporary counter in getDb writes each query to the log. The plan does not commit the counter.

08

Risks

Five risks are known. Each one has a check or a fallback.

RiskWhat to do
useLinkStatus and prefetchuseLinkStatus can stay false when Next.js prefetched the link and the navigation is quick. This is correct: nothing waits.
banned on session.userThe type comes from the admin plugin. betterAuth infers it only when the plugins are a tuple. Thus auth.ts passes them through pluginTuple (plan Task 6). If getSession gets a cookie cache, banned can be late. A comment at the getSession call says this. In session.test.ts, the test of the settings is the guard: it fails when auth.ts gets a cookieCache or a secondaryStorage. The ban tests with live session rows prove the ban check itself.
The size of the responsePart C renders every panel of a page in one response. Transazioni does this today (47 KB for 12 rows). Conti and the Profilo lists are shorter. If a page becomes too large, keep its panel a navigation: give it no entry in panels.
A redirect under a loading.tsxA redirect() in a page under a boundary streams after the shell and the skeleton. The status is 200, and the browser follows the redirect in the page. This applies to readPage → /onboarding on the four tabs and the Profilo sections. next.config.ts redirects /profile and /admin with a 307 before any render. /budgets has no boundary, and it keeps its 307. A notFound() in a layout above the boundary keeps its 404: a member gets 404 for /admin and /admin/accounts.
A form with state in a hidden panelPanelSwitch mounts only the open panel. The new form of Transazioni is different: it uses <Activity>. A change from one key to another key starts a new form, because of the key on Panel.
09

Words

The meaning of the special words in this document.

WordMeaning
NavigationThe browser asks the server for the page with the new URL.
In placeThe screen changes in the browser, with no request to the server.
PendingA navigation started and the server did not answer yet.
BarThe thin line at the top of the page that shows a pending navigation.
SkeletonGrey blocks in the shape of a page. They show while the server works.
ShellThe top bar, the tab bar and the sub-navigation. They stay mounted during a navigation.
Panel keyThe string that names the open panel, for example tag:ID.
FlagA query parameter with no value that opens a panel, for example ?new.
StreamingThe server sends the shell first and the data later, in the same response.
FrameOne image on the screen. At 60 Hz a frame is 16.7 ms.
CPU 4×Chrome makes the CPU four times slower, to show a slower computer.
