The panel opens in the frame of the click

On the web Transazioni page, «New transaction» and the detail of a row open and close without a request to the server. The list makes room for the panel with one movement.

Language Simplified Technical English (ASD-STE100) Source Spec §17.1.7 · TODO «Web app: a UI pass» Plan 2026-10-07-web-panel-feel.md Date 2026-10-07
01

What changes

Today each panel on Transazioni is a navigation. The screen does not change until the server answers. This spec makes the panel a client state.

The user reported that the web UI feels slow, for example when the panel opens to add a transaction. The cause is not the loading of the page. The cause is the time between the click and the first change on the screen.

This spec changes three things on Transazioni at 1024px and wider, and two things below 1024px:

  1. The panel opens and closes in the frame of the click. The browser sends no request.
  2. At 1024px and wider, the list narrows in one movement while the panel enters. The amounts slide. They do not jump.
  3. The close removes the panel from the layout at once. No empty column stays on the screen.

Below 1024px the panel is a full screen or a sheet over the list. The list does not change width there, so only items 1 and 3 apply.

03

The panel state

The panel has four states. The URL still tells which state is open, so a reload, a shared link and Back work.

A client component, TransactionsPanels, keeps the state. When the user changes only the panel, the component sets the state and then calls history.pushState. Next.js syncs that URL into useSearchParams and does not ask the server.

When the URL changes for another reason (a navigation, Back, a save), the component reads the new URL in the same render and shows that panel.

The server renders the new form and the detail of every row in the list, in one response. Thus the client has the content of each panel before the click.

Exception

«Edit» stays a navigation. The edit form needs the balances without the edited row. One form for each row would repeat the accounts, categories and tags for each row. The detail stays on the screen while the edit form loads.

04

In place or navigation

A link changes the panel in place only when the page already has what the link shows.

The rule compares the current URL and the target URL. It ignores the three panel parameters: t, new and edit. If the path and all other parameters are equal, the change is in place. Otherwise it is a navigation, as today.

Thus a filter, a period, a delete toast (?deleted=) or the prefill of «Set aside» always go to the server. The toast and the prefill belong to the page that the server rendered. An in-place change must not leave them on the screen.

The top bar's «New transaction», the FAB and N work on every page. They first send a cancelable event, saldo:new-transaction, on window. Transazioni cancels the event and opens the form in place. On the other pages nobody cancels it, and the link goes to /transactions?new.

05

The list makes room

At 1024px and wider, the list and the panel share a grid. The second track grows from 0 to the panel width with a CSS transition.

The list reflows on each frame of the transition. Thus the amounts slide to their new position. A click during the movement reverses it from the current position, because a CSS transition starts from the current value.

The panel's column clips its content while it grows. The panel stays at the trailing edge of the column. Thus the panel appears from the side where it stays.

On close, the track goes back to 0 at once, while the panel plays its exit. The panel leaves the DOM after its exit. No empty column stays.

Why not a View Transition

A View Transition animates snapshots. The text of the list stretches while its box changes size, and the page ignores input until the animation ends. The track transition has neither problem. Its cost is a layout on each frame. The plan measures the longest frame, and adds content-visibility: auto to the day sections if that frame is longer than 50 ms at CPU 4×.

06

Motion rules

The pointer gets motion. The keyboard does not. Every movement starts at the input, never after a wait.

A person presses N and the arrow keys many times a day. Motion on those keys makes the app feel slower each time. Thus the keyboard opens and closes the panel on the next frame, with no transition.

The pointer gets a short entrance and a shorter exit. The values are those that Panel already uses.

Each opening of «New transaction» mounts a new form: the draft of the last form does not come back. An opening during the exit of the same form reverses the exit and keeps the draft.

07

The screens

The screens do not change. Only the time between the input and the screen changes.

Below 1024px the FAB opens «New transaction» as a sheet over the list. The sheet rises in the frame of the tap. The scrim and the sheet leave together on close.

08

What stays the same

The URL is still the state that a person can share. These behaviours must not change.

CaseBehaviour
Reload?t=id opens the detail, ?new opens the form, on the first render of the server.
A link from Home/transactions?t=id opens the detail, also for a row of another period.
Back and ForwardBack closes a panel that a click opened. Forward opens it again.
JavaScript offEach row, ✕ and «Cancel» is a link to a page.

DeleteA navigation. The toast with «Undo» shows. While it shows, a click on a row is a navigation.

Conti, ProfiloNo change. They use Panel without the new props.
