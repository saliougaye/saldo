Saldo 0.8a · apps/site · Spec

The marketing site: the landing page

One static page tells a visitor what Saldo is. It shows the app, and it sends the visitor to the code or to the self-hosting guide. It runs no server code and sends nothing to a third party.

Language Simplified Technical English (ASD-STE100) Design mockups/2026-10-18-marketing-site-product.html Roadmap 0.8 Decisions D41–D52 Date 2026-10-18
01

Scope

This spec covers one landing page in English, in a new static app. The docs library comes in a later plan.

The page is for two groups of people. The first group leaves the paid tier of Spendee. The second group runs its own servers. The page gives both groups the same two actions: read the code, or read the self-hosting guide.

The page lives in apps/site. It is an Astro app with static output (D42). It is separate from apps/web, so an instance build has no marketing in it (D35).

In scope

The landing page at /. Its metadata, social image, robots.txt and sitemap.xml. The phone screens drawn from tokens. The carousel. The theme toggle. The Vercel project. The check that keeps the screens in step with the app strings.

Not in scope

The docs library (0.8b). Languages other than English (D43). A blog, a changelog page, a pricing page. Analytics of any kind. A form, a newsletter or a contact address. Any server code.

Source of truth

On the landing page, this spec wins over the POC spec. Where this spec is silent, the mockup docs/superpowers/mockups/2026-10-18-marketing-site-product.html shows the look and the behaviour.

03

Design tokens

Every colour, radius and font size comes from @saldo/ui. The site adds two tokens there and none in its own code.

The layout calls tokensCss() at build time. The result goes into one <style> element in <head>. Components read the custom properties, for example var(--color-surface) and var(--radius-card).

The site does not write a hex value, a radius or a font size in a component. Lengths for layout, such as a card width, are not tokens and stay in the component.

Fonts

The site loads Geist from the @fontsource/geist-sans and @fontsource/geist-mono packages. The files are part of the build, so the page asks no other host for a font. The layout points --font-family at «Geist Sans», as the web app points it at its own font variable.

04

Phone screens

The site draws each phone screen in HTML and CSS from the tokens. It does not show a screenshot (D44).

A screen follows the theme of the page. A screen changes language when a second locale comes. A screenshot can do neither, and it gets old when the app changes.

Each screen is drawn at 390 × 844 points, the size of the phone. The Phone component then scales it with transform: scale() to the width of its slot. Thus a screen uses the same sizes as the app: card padding 16, row height 44, icon box 32.

One object for each language

A screen reads two things. The first is the app strings, from the en catalog of @saldo/i18n. The second is the sample data, from apps/site/src/content/en.ts. The site copy is in the same file as the sample data.

The type SiteContent is the shape of the English object. Thus the type checker stops an Italian object with a missing field. The registry LOCALES maps a locale code to its object.

05

The carousel

The browser scrolls the carousel and stops it on a card. A small script adds the buttons, the keys and the progress.

The scroller is a native horizontal scroll box with scroll-snap-type: x mandatory. Touch, trackpad and wheel use the scrolling of the browser. The script has no pointer code, so the page always scrolls up and down.

The script src/scripts/carousel.ts is about 60 lines. There is no mouse drag, no rubber band and no spring. The user decided so on 2026-10-19 (D52).

RuleValue
StopsFor each card: scroll-snap-align: start, with the scroll padding of the alignment rule. The last cards stop at the end of the scroll box.
AlignmentThe track padding and the scroll padding are max(pagePaddingWeb, (100cqi − contentWide) / 2), and 20 px below 760 px. The first and the last card align with the page grid.
Card width264 px, gap 24 px. Below 760 px: 232 px, gap 16 px, so about one and a half cards show.

08

Theme

The page follows the system theme. A toggle can force light or dark. The first paint already has the right colours (D47).

The toggle has three states: System, Light, Dark. It stores the choice in localStorage under saldo-site-theme. System removes the key.

An inline script in <head> runs before the first paint. It reads the key and sets data-theme on <html>. tokensCss() already gives [data-theme] priority over prefers-color-scheme.

Caution

Do not move the theme script to the end of <body> and do not make it a module. A deferred script runs after the first paint, and the page then flashes from dark to light.

11

Deploy

The site is its own Vercel project with the root directory apps/site. The domain comes from an environment variable (D45).

  1. Create a Vercel project from the repository.
  2. Set the root directory to apps/site. Keep «Include files outside the root directory» on, because the site imports packages/*.
  3. Vercel finds Astro and pnpm by itself: build with the build script, output dist. The site has no vercel.json. Set the Node.js version to 22 or later in the project settings.
  4. Add the domain to the project. SITE_URL is optional: set it to the public URL, for example https://saldo.example, only when the canonical URL is wrong.

Without SITE_URL, the build uses https:// + VERCEL_PROJECT_PRODUCTION_URL, which Vercel sets. Outside Vercel, it uses http://localhost:4321.

The other project

The root vercel.json stays for the web app. It builds pnpm --filter web build. The site project does not read it, because its root directory is apps/site.

13

Decisions

The numbers continue from D40 in the POC spec. The POC spec lists them with a pointer to this file.

#DecisionReason
D41The first release of 0.8 is the landing page only. The docs library is a separate plan, 0.8b.The page is what a release note or a forum post links to. The docs library needs its own tooling decision.
D42apps/site is an Astro app with static output, not a Next.js app.Astro sends no JavaScript by default, and this page needs three small scripts only. Astro imports TypeScript from workspace packages, so the build reads the @saldo/ui tokens and the en.ts keys. Starlight, the Astro docs framework, can fit 0.8b: a glob loader may read the Markdown in docs/ in place. This is to verify in the docs plan. Next.js adds a React runtime and hydration to a static page, with no advantage for docs. The earlier choice of Next.js did not compare Astro.
D43English only at the start. The site copy is in a site-local object for each locale, not in @saldo/i18n. The app strings on the screens come from @saldo/i18n.The parity test of @saldo/i18n needs every key in seven catalogs. Marketing copy there would need six translations before launch, and the phone and the web would carry it. The screens must say what the app says, so they read the app catalog.
D44The phone screens are HTML from the tokens, not screenshots.They follow the theme, they can change language, and they are small. Screenshots showed Italian demo data in English and stayed light in the dark theme.
D45The public URL comes from SITE_URL at build time. The fallback is VERCEL_PROJECT_PRODUCTION_URL, then http://localhost:4321.The domain is not known yet. No code changes when it is.
D46Client JavaScript is three small scripts: theme, carousel, copy buttons. There is no scroll reveal.A static page needs no framework. Content that waits for a script can stay hidden when the script fails.
D47The theme follows the system. A toggle forces light or dark and stores the choice. An inline script sets it before the first paint.No flash, and no server is needed to know the choice.
D48Two new tokens in @saldo/ui: fontSize.siteDisplay (72) and palettes.*.deviceIsland (#000000).AGENTS.md forbids font sizes and colours in apps. The marketing headline and the phone status bar need one value each.
D49Biome lints .astro files with html.experimentalFullSupportEnabled. The client scripts are .ts files.Without the option, Biome 2.5 reports template variables as unused and skips <script>. With it, the repository lint stays clean. A .ts file gets the full lint even if the option changes. One style rule, noDescendingSpecificity, is off for apps/site/src/styles/** only: the two stylesheets are a flat port of the mockup, and their cascade order is intended.
D50The two calls to action go to the repository and to the self-hosting guide on GitHub. The URLs live in one module.The docs library does not exist yet. One module makes the later change one line.
D51apps/site uses TypeScript 6 for astro check. The rest of the repository keeps TypeScript 7.@astrojs/check 0.9.10 accepts TypeScript 5 or 6 only. pnpm installs a separate version for the one package.
D52The site has no automated tests and no carousel physics. The carousel is a native scroll box with CSS scroll-snap.The user decided on 2026-10-19: this is a simple marketing site. The type checker, the build and a look at the page are enough. Mouse drag with momentum is not worth hundreds of lines of script and tests.
14

Open questions

These questions do not stop the plan. Each one has an owner decision before the site goes live.

  1. Domain. Which domain, and who owns the Vercel project? The build only needs SITE_URL.
  2. Italian and the other languages. When does a second locale come, and who writes the copy? The app has seven catalogs; the site starts with one.
  3. Docs tooling for 0.8b. Can Starlight with a glob loader read docs/*.md in place, with the repository links intact? To verify in the docs plan.
  4. Node version. Astro 7 needs Node 22.22.0 or later. CI and Vercel use the latest Node 22. Pin .nvmrc to 22.22?
  5. TypeScript. When @astrojs/check accepts TypeScript 7, remove the pin of D51.
  6. Self-hosting guide. Closed. Commit d4903b86 fixed the clone URL and added SETTINGS_ENCRYPTION_KEY to the Docker block. The site shows the same commands, line for line.
  7. Social image. A committed PNG is simple. Should the build make it instead?
  8. Biome option. html.experimentalFullSupportEnabled is experimental. Keep it, or drop it and turn off two rules for *.astro?
  9. Vercel analytics. The page says «Nothing reported». Keep Vercel Web Analytics and Speed Insights off on the site project?
