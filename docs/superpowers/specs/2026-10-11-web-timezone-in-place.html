The time zone list opens in place

On Profile › Preferences, the row «Time zone» opens its list in the frame of the click, as the other four rows do. The browser calculates the hour in each zone. The server still checks the zone that a person saves.

Language Simplified Technical English (ASD-STE100) Source TODO «Web app: a UI pass» · spec 2026-10-11 «web navigation feel» §05 Plan 2026-10-11-web-timezone-in-place.md Date 2026-10-11
01

Problem and scope

The time zone panel is the only panel of Preferences that is still a navigation.

The 2026-10-11 work made the panels of Preferences open in place. It kept edit:timeZone a navigation for two reasons:

  1. The list has 418 zones. Each row has the city, the name of the zone and the hour there. The list adds 38 KB to the RSC response of the page.
  2. The server calculates the hours at the render. If the server renders the list with every load of the page, the hours are old when a person opens the panel later.

Thus a click on «Time zone» sends one RSC request and waits for the server. The other four rows open with no request.

Out of scope

This spec covers only the time zone panel. The edit form of a transaction (?t=ID&edit) and of an account (?a=ID&edit) stay navigations. A separate review decides about them. This spec does not change their code.

02

Decisions

The browser makes the list from static tables. The server sends only the saved zone, the language and the minute of the render.

The names of the zones and of the cities do not change at run time. They are static tables in @saldo/i18n (timeZones.generated.ts and timeZoneCities.ts). The hour in a zone is wallClock, which uses Intl.DateTimeFormat. Every browser has it. Three designs were compared.

DesignCostResult
A. Keep the navigation1 RSC request and 38 KB (6.8 KB with gzip) for each open, and again after each save while the panel is open.Rejected. The click waits for the server.
B. The server renders the list with every load, without the hoursAbout 33 KB (6 KB with gzip) in each response of the page, also when nobody opens the panel. The browser adds the hours.Rejected. Each load and each router.refresh pays for a list that is rarely opened.
C. The browser makes the listThe client code of the page gets the tables once: 52 KB minified, 12.8 KB with gzip. The browser keeps the file in its cache. The response of the page grows by less than 1 KB.Chosen. No request at the click, and no list in the response.
DecisionReason
A subpath @saldo/i18n/timeZonesA client component must not import the root of @saldo/i18n, because the root holds the seven catalogs (clientImports.test.ts). timeZones.ts imports no catalog.
The same functions as beforeThe rows use timeZoneCity, timeZoneName, wallClock and formatWallTime, as timeZoneOptions did on the server. Thus the text of each row does not change.
The same orderThe rows are sorted by city with Intl.Collator(locale). This is the comparison that localeCompare(b, locale) made on the server.
edit:timeZone is always in panelsPanelSwitch mounts only the open panel. Thus the browser makes the list only when the panel shows.
The hours tickThe panel reads the current minute. A timer starts a new render at each new minute while the panel is open. Thus the hours are never old.
The server check stayssaveSetting still refuses a zone that Intl does not know (isTimeZone), and it still stores the CLDR id (canonicalTimeZone). This spec does not change the action.
03

The panel in the browser

A click on «Time zone» only selects a panel that the page already has. The browser then makes the rows.

The server. The page puts edit:timeZone in panels with every render. The body is TimeZonePanel with four props: saved, locale, renderedAt (the minute of the render) and strings. It has no list.

The browser. timeZoneRows(locale, saved) gives the rows: each zone of TIME_ZONES, plus the saved zone when the table does not hold it. Each row has the zone, the city and the name of the zone. zoneTimes(zones, now) gives the hour of each row. Both functions are pure and live in src/features/profile/timeZoneRows.ts.

The device zone. listedZone reads the aliases from TIME_ZONE_ALIASES of the static table. The server does not send them now.

A load of ?edit=timeZone. The server renders the panel as before, so the HTML holds the list. The rows of the HTML have the hours of renderedAt. The browser then shows the hours of its own minute.

04

The hours

The panel reads the minute through useSyncExternalStore. Thus the hydration matches the server, and the hours are right after it.

useMinute(renderedAt) gives the current minute as a number: Math.floor(Date.now() / 60000). It has three parts:

  1. getServerSnapshot gives renderedAt. The server render and the hydration render use it. Thus the text of the hours is the same in the two renders, and React reports no mismatch.
  2. getSnapshot gives the minute of the browser. After the hydration, React renders again with it when it differs. A panel that a click opens uses it in the first render.
  3. subscribe starts a timer for the next minute, then one timer for each minute. The timer stops when the panel closes.

The rows and their order do not depend on the minute. Only the hours change at each minute.

Cost

wallClock makes one Intl.DateTimeFormat for each zone, and keeps it. In Chrome with the CPU 4× slower, the first 418 formatters took 70 ms. The plan measures the first open with and without a warm-up in idle time. It keeps the warm-up only if it makes the median shorter by more than 20 ms.

05

Correctness and security

The change moves only the display of the list. The save and its checks stay on the server.

PropertyHow it holds
The zone that is savedThe browser sends a zone id. saveSetting refuses an id that Intl does not know, and it stores the CLDR id. The tests in settings.test.ts do not change.
The text of the rowsThe same functions of @saldo/i18n make the city, the name and the hour. A unit test fixes the rows at one instant for two languages.
The hoursThey are the hours of the browser at the current minute. They are never the hours of an old render.
Data in the responseThe response holds the saved zone of the person who reads the page, as before. It holds no other person's data and no secret. The tables are public data.
Motion, focus, Esc, BackThe rules of the 2026-10-07 spec, through PanelSwitch, as for the other four panels.
PrefetchThe row is a SummaryRow, which renders a PanelLink. In a PanelSwitch it has prefetch={false}.
06

How to measure

A temporary script measures a production build on port 3101, before and after the change.

The script signs a person in with a session row, as measure-nav does. It opens /profile/preferences at 1440px. Chrome runs with the CPU four times slower. The script records the time from the pointerdown on «Time zone» to the first frame with a visible row of the list. It also counts the RSC requests that are not prefetches. Each value is the median of 7 clicks.

The script also fetches the RSC response and the HTML of the page, with and without ?edit=timeZone. It saves the text of the 418 rows, and screenshots at 1440px and 500px in the light and the dark theme. The hours are hidden in the screenshots, because they change each minute.

07

Risks

Four risks are known. Each one has a check or a rule.

RiskWhat to do
A different order in the browserThe server render and the hydration sort with two collators: the one of Node and the one of the browser. If they disagree on two cities, React reports a hydration mismatch on a load of ?edit=timeZone, and it renders the panel again in the browser. The plan checks the console and the order in Chromium. The CLDR root collation is the same in both.
The size of the client codeThe page loads 12.8 KB more with gzip once. The browser keeps it in its cache until the next deployment. Only the Preferences page imports it.
The first open on a slow deviceThe first 418 formatters take time (section 04). The plan measures it and decides about a warm-up.
A browser with another Intl nameA browser can report a zone with another id (Asia/Kolkata). listedZone maps it with TIME_ZONE_ALIASES, as before.
08

Words

The meaning of the special words in this document.

WordMeaning
NavigationThe browser asks the server for the page with the new URL.
In placeThe screen changes in the browser, with no request to the server.
ZoneAn IANA time zone id, for example Europe/Rome.
CLDRThe Unicode data for the names of cities and zones in each language.
HydrationReact connects the HTML of the server to the code in the browser.
FrameOne image on the screen. At 60 Hz a frame is 16.7 ms.
CPU 4×Chrome makes the CPU four times slower, to show a slower computer.
