# Phase 09c — CSV import

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CSV from another app — Spendee first, since that is the one we have a real file for — becomes
transactions, with the accounts, categories and tags it needs, and importing the same file twice changes nothing the
second time.

**Architecture:** Parsing, mapping and planning are pure functions in `@saldo/core/io`, tested against the anonymised
fixture. The planner never writes: it returns what *would* happen (rows to create, things to create first, duplicates
to skip, per-row errors) so the preview screen and the import itself read the same answer. `apps/mobile/src/io`
applies a plan in one SQLite transaction.

**Why not PapaParse:** §11.3 named it, but the parser is ~50 lines against `toCsv`'s own rules and putting a
dependency inside `@saldo/core` — the package that may not even import Node — buys nothing here. The plan writes one
and tests it against the real file's quirks. Update §11.3 to say so.

**Tech Stack:** `expo-document-picker` and `expo-file-system` (already installed by 09a), existing Zod schemas.

**Spec:** §11.3, §6.31.

### Task 1: A CSV parser

**Files:** `packages/core/src/io/csvParse.ts`, `csvParse.test.ts`

- [ ] **Step 1: Tests first.** Cover: a plain file; quoted fields holding the delimiter, a doubled quote and a
newline; `\r\n` and `\n`; a leading BOM; `;` and `\t` detected from the header line; a trailing newline producing no
empty row; a last line without a newline; ragged rows kept as they are (the planner reports them, the parser does
not guess).

```ts
expect(parseCsv('a,b\r\n1,2\r\n')).toEqual({ delimiter: ',', rows: [['a', 'b'], ['1', '2']] });
expect(parseCsv('﻿a;b\n1;2')).toEqual({ delimiter: ';', rows: [['a', 'b'], ['1', '2']] });
expect(parseCsv('a,b\n"x,y","say ""hi"""\n')).toEqual({
  delimiter: ',',
  rows: [['a', 'b'], ['x,y', 'say "hi"']],
});
```

- [ ] **Step 2: Write it.** A single pass over the characters with an `inQuotes` flag. The delimiter is whichever of
`,`, `;`, `\t` appears most often in the first line *outside* quotes; ties go to `,`.

- [ ] **Step 3: Run the tests. Commit.**

### Task 2: Fingerprints

**Files:** `packages/core/src/io/fingerprint.ts`, `fingerprint.test.ts`

- [ ] **Step 1: Tests.** `normalizeText` lowercases, strips accents (NFD + combining marks), collapses runs of
whitespace and trims — `"  Caffè   Corretto "` → `caffe corretto`. Emoji survive (they are not accents) but are not
what the fingerprint leans on. `transactionFingerprint({ date, amount, kind, description, accountName })` joins the
five with `|`, and two rows that differ only in description casing or spacing collide on purpose.

- [ ] **Step 2: Write it.**

```ts
export function normalizeText(value: string): string {
  return value
    .normalize('NFD')
    .replace(/\p{Diacritic}/gu, '')
    .toLowerCase()
    .replace(/\s+/g, ' ')
    .trim();
}

export function transactionFingerprint(input: {
  date: LocalDate;
  amount: MinorUnits;
  kind: TransactionKind;
  description: string;
  accountName: string;
}): string {
  return [
    input.date,
    String(input.amount),
    input.kind,
    normalizeText(input.description),
    normalizeText(input.accountName),
  ].join('|');
}
```

- [ ] **Step 3: Commit.**

### Task 3: Presets and mapping

**Files:** `packages/core/src/io/importMapping.ts`, `importMapping.test.ts`

- [ ] **Step 1: The shape.**

```ts
export type ImportField =
  | 'date' | 'amount' | 'type' | 'account' | 'category' | 'description' | 'note' | 'tags'
  | 'currency';

export type DateFormat = 'iso' | 'dmy' | 'mdy' | 'dmy-dots';

export interface ImportMapping {
  /** Field → column index, or null when the file has no such column. */
  columns: Record<ImportField, number | null>;
  dateFormat: DateFormat;
  decimalSeparator: '.' | ',';
  /** How the kind is decided when there is no usable `type` column. */
  signConvention: 'negative-is-expense' | 'type-column';
  /** Values of the `type` column, lowercased, that mean each kind. */
  typeValues: { expense: string[]; income: string[] };
  tagSeparator: string;
  /** Used when there is no account column, or the cell is empty. */
  defaultAccountName: string | null;
}
```

- [ ] **Step 2: `SPENDEE_PRESET`** — from the real file (§11.3):

```ts
export const SPENDEE_HEADERS = [
  'date', 'wallet', 'type', 'category name', 'amount', 'currency', 'note', 'labels', 'author',
];
```

with `columns` pointing `account` at `wallet`, `tags` at `labels`, `description` at `note`,
`dateFormat: 'iso'`, `decimalSeparator: '.'`, `signConvention: 'type-column'`,
`typeValues: { expense: ['expense'], income: ['income'] }`, `tagSeparator: ','`.

**The user must be able to move `account` onto the labels column** — in the sample every row has the same wallet
while the labels hold the real account — so the mapping step edits `columns`, and the preset is only its starting
point. Nothing in the planner assumes the preset's choice.

- [ ] **Step 3: `SALDO_PRESET`** — our own export of §11.2, matched by its header, mapping every column including
`to_account` being absent from `ImportField` (transfers are not imported; see Task 4).

- [ ] **Step 4: `detectPreset(headers)`** — lowercase and trim the header cells, then compare as sets. Tests: the
fixture's header detects `spendee`; our own CSV header detects `saldo`; anything else is `generic`.

### Task 4: The planner

**Files:** `packages/core/src/io/importPlan.ts`, `importPlan.test.ts`

- [ ] **Step 1: The shape.**

```ts
export interface PlannedTransaction {
  rowNumber: number;          // 1-based, header excluded, for the error list
  date: LocalDate;
  kind: 'expense' | 'income';
  amount: MinorUnits;         // positive
  accountName: string;
  categoryName: string | null;
  description: string;
  note: string | null;
  tagNames: string[];
  fingerprint: string;
}

export interface ImportRowError {
  rowNumber: number;
  /** Why, as a key the UI can translate, plus the offending value. */
  reason: 'date' | 'amount' | 'type' | 'currency' | 'account' | 'columns';
  value: string;
}

export interface ImportPlan {
  transactions: PlannedTransaction[];
  duplicates: number;
  errors: ImportRowError[];
  /** Names that do not exist yet, in first-seen order. */
  newAccounts: string[];
  newCategories: { name: string; direction: 'expense' | 'income' }[];
  newTags: string[];
}

export function planImport(
  rows: readonly (readonly string[])[],
  mapping: ImportMapping,
  context: {
    currency: CurrencyCode;
    accounts: readonly Account[];
    categories: readonly Category[];
    tags: readonly Tag[];
    existingFingerprints: ReadonlySet<string>;
  },
): ImportPlan;
```

- [ ] **Step 2: Tests, against the fixture.** `packages/core/src/io/__fixtures__/spendee.csv` is read with
`node:fs` **in the test only** — core itself never touches Node.

```ts
const csv = readFileSync(new URL('./__fixtures__/spendee.csv', import.meta.url), 'utf8');
```

Assert, at minimum:
- all 11 rows plan, with no errors;
- `2026-08-12T16:23:13+00:00` → `2026-08-12` (the first ten characters: the offset's own local date);
- `-5.00000000` → `500` minor units and kind `expense`; `70.00000000` with type `Income` → `7000`, `income`;
- `newCategories` holds `Bills, Fees & Subscriptions` (the quoted one) with direction `expense`, and
  `Money Back` with direction `income`;
- with the preset as-is, `newAccounts` is `['My Money']` and `newTags` holds the three labels;
- with `columns.account` moved to the labels column and `defaultAccountName: 'Contanti'`, `newAccounts` holds the
  three labels plus nothing else, the row with an empty label lands on `Contanti`, and `newTags` is empty;
- a second `planImport` with the first run's fingerprints in `existingFingerprints` yields
  `transactions: []` and `duplicates: 11`;
- two identical rows *inside the same file* count as one plus one duplicate;
- a row whose `Currency` is `USD` while settings say `EUR` is an error with reason `currency` and value `USD` —
  no conversion (§11.3);
- an unknown `Type` is an error with reason `type` and the value, **not** a guess: `Transfer` never appeared in the
  sample, so transfers are out of this phase;
- a short row (fewer cells than the mapping needs) is an error with reason `columns`.

- [ ] **Step 3: Write it.** Notes that matter:
  - Dates: `iso` takes `slice(0, 10)` and validates with `isLocalDate`; `dmy`/`mdy`/`dmy-dots` split on `/` or `.`
    and pad. Anything else is a `date` error carrying the original text.
  - Amounts go through `parseDecimalAmount` (never a float) and are stored positive; the kind comes from the type
    column, or from the sign when `signConvention` is `negative-is-expense`.
  - A category is matched case-insensitively **within the row's direction**, so "Money Back" as income and an
    expense category of the same name can coexist. New ones are `icon: 'tag'`, `colorIndex: 9` (§11.3).
  - Accounts and tags are matched with `normalizeText` too, so `Fineco🏦` twice is one account.
  - Fingerprints are computed against the *resolved* account name, and the set grows as the plan is built so a
    duplicate inside the file is caught.

- [ ] **Step 4: Run the tests. Commit.**
