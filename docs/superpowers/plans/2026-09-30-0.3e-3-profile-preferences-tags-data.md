# 0.3e-3 — Profilo: Preferenze, Tag, Dati, and the end of the dev sign-in route

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** from the web a user changes the synced preferences (language, theme, currency with confirmation, cycle start
day, time zone), manages tags (new, rename, merge, delete) and exports their data (backup JSON, CSV). The temporary
`GET /api/dev/sign-in` route is deleted, which closes 0.3e.

**Architecture:** as 0.3e-1/2/2b. Writes are `writeInTransaction` modules in `apps/web/src/server/write/` with a `basis`
on every row read; forms are client components rendered into Profilo's slot through `ProfilePanel`; the URL carries the
state (`/profile/preferences?edit=currency`, `/profile/tags?new`, `?tag={id}`). The export is two route handlers that
read the projection and call `@saldo/core`'s `buildBackup`, `csvRows` and `toCsv` — the functions the phone's export
calls — so a file from the web restores on the phone.

**Tech Stack:** as 0.3e-2.

Categorie were in this plan's original scope (0.3e-1's split table) and were built in 0.3e-2b.

---

## Decisions

1. **Preferences save on choice, as the phone** (`repos.settings.update` on tap): language, theme, cycle day and time
   zone write at once and the panel stays open showing the new selection; **currency asks first** with the phone's dialog
   (`profile.currencyConfirmTitle`, `currencyConfirmBody`, or `currencyConfirmScale` with `formatMoney(184260, …)` before
   and after when the two currencies' `minorDigits` differ, §5.1). Changing the currency reformats, never converts.
2. **The period panel is the phone's «Inizio del ciclo»**: the 1–28 grid and the preview range
   (`periodContaining` + `formatCycleRange`). The phone offers no way to change `periodKind` after onboarding, so neither
   does the web; read `apps/mobile/app/profile.tsx` for whether the row shows for non-cycle kinds and mirror it.
3. **The time zone is validated on the server with `isTimeZone`** (`@saldo/i18n`) and stored canonical
   (`canonicalTimeZone`); the list and search are core's `timeZonePicker` (read how the phone's `TimeZoneList` uses it).
   The currency list is core's `currencyPicker` (as `/onboarding` already does).
4. **A language or theme change must show at once**: after the write, `router.refresh()` re-renders the root layout,
   which puts `lang` and `data-theme` on `<html>`. Verify in the browser that the whole shell changes language.
5. **Tags follow §5.10 and the phone's `adminService`**: names unique case-insensitively on create and rename
   (`canCreateTag`); rename keeps the id; merge replaces the source id with the target in every transaction's `tagIds`
   (deduplicated) **and every recurrence template's** if templates carry `tagIds` (read the schema), then tombstones the
   source; delete removes the id from them, then tombstones. One batch each, no duplicate `(entity, id)`. The list is
   sorted by usage desc, «N usi» (`tags.uses`). The tag **view** (totals, split) is not built: a row's «Vedi transazioni»
   links to `/transactions?tag={id}`, the filter 0.3d built.
6. **`createTag` moves** from `write/transactions.ts` to `write/tags.ts` (the transaction form's action keeps calling it).
7. **Export.** `GET /api/export/backup` and `GET /api/export/csv?range=all|period&p=<date>`, cookie session
   (`requireWebUser`-equivalent for a route handler: read how `app/api/me/route.ts` and the pages resolve the web
   session), `Content-Disposition: attachment` with the phone's file names (`saldo-backup-{today}.json`,
   `saldo-transactions-{today}.csv`), `Cache-Control: no-store`. The pure part of the phone's `exportService.ts` moves to
   core (`io/exportFiles.ts`: `backupFile(data, options)`, `csvFile(data, options)` with the same sort — newest first,
   id as tie-break — and names), the phone calls it with what its repos collect, and its tests stay green. The backup
   holds the attachment **rows** (metadata), not their bytes: a ZIP with the bytes stays the phone's (§17.1.9), and the
   page says so. No settings → 409 (the phone's `NothingToExportError`). `/profile/data` is two download links (plain
   `<a href download>`), «Tutto» and «Periodo corrente» for the CSV. Restore, CSV import and «Elimina tutti i dati»
   stay on the phone (§17.1.7).
8. **The dev sign-in route goes last**, after the acceptance run and the review fixes, because it is how the UI is
   checked. After it, a browser check needs a real passkey; the plan's last note says so.

## Rules

Same as 0.3e-2b: grep every i18n key (new keys in all seven catalogs, only where the phone's `profile.*`, `settings.*`,
`tags.*`, `export.*`/`data.*` keys have none), tokens only in CSS, no `any`/`!`, `'use client'` never imports the
`@saldo/i18n` root, stage by full path, read the gates (`rtk proxy pnpm lint|typecheck|test`), never stage
`docs/superpowers/plans/README.md`, never kill a server you did not start (own port, no broad `pkill`).

     phone and the same panel re-renders without a save (the row's link clicked again), the panel shows the web's last
     choice, not the stored one, until it is reopened. Clear the override once `value` has moved.
  2. A choice made while a save is pending is dropped without a sign (`if (pending) return`); the options could be
     `aria-disabled`/dimmed while the write and refresh run.
