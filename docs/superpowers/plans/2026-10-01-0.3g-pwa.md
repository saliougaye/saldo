# 0.3g — PWA: manifest, icons, offline page

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** the web app can be installed to the home screen (manifest, icons, `display: standalone`) and, with no
network, a navigation shows a localized «you are offline» page instead of the browser's error. Nothing else is
available offline: the web app is online-only by decision (roadmap 0.3, spec §17.1.7).

**Architecture:** all PWA logic is pure code in `apps/web/src/pwa/` with unit tests; the Next entry points are thin.

| Piece | File | Notes |
|---|---|---|
| Manifest builder | `src/pwa/manifest.ts` | `buildManifest(name)`; colours from `@saldo/ui` palettes |
| Manifest route | `app/manifest.ts` | dynamic; name = resolved instance name, `Saldo` if the database is unreachable |
| Offline page | `src/pwa/offlinePage.ts` + `app/offline/route.ts` | self-contained HTML (inline token CSS, no JS, no chunks), locale from `Accept-Language` |
| Service worker | `src/pwa/serviceWorker.ts` + `app/sw.js/route.ts` | hand-written, no Workbox; `Cache-Control: no-cache` |
| Registration | `src/pwa/RegisterServiceWorker.tsx` | client component, production only |
| Icons | `public/icons/*.png`, `app/icon.png`, `app/apple-icon.png` | derived from `apps/mobile/assets/icon.png` with `sips` |
| Strings | `web.offline.*` in all seven locale catalogs | parity test enforces |

## Decisions (spec silent)

1. **Icons come from the phone's mascot icon**, resized with macOS `sips` (no dependency). The maskable one is the
   same art at 80% on the icon's own `#FAFAF9` background (the safe zone is the central 80% circle).
2. **Manifest colours:** `background_color` and `theme_color` are `palettes.light.surface` (`#FAFAF9`, the icon's
   background, so the splash is seamless). The `<meta name="theme-color">` has a light and a dark variant by media
   query (`palettes.{light,dark}.bg`); the user's in-app theme override is not reflected there.
3. **Manifest name** is the resolved instance name (`INSTANCE_NAME` / panel / `WEBAUTHN_RP_NAME`) so two instances
   on one phone are told apart; `short_name` is the same truncated to 12 characters. The manifest is not localised.
4. **The offline page is a route handler, not a page**, so it carries no layout, session lookup, scripts or hashed
   assets that would also have to be precached. Its text follows `Accept-Language` (it is shown with no session
   to read a preference from); it is cached at install, and re-fetched on every activate.
5. **Service worker policy:** precache `/offline` and `/icons/icon-192.png`. Only *navigation* requests are
   intercepted: network first, on failure the cached `/offline`. Everything else (API, Server Actions, assets, RSC
   fetches) is never touched and never cached. Cache name `saldo-offline-<APP_VERSION>`; activate deletes every other
   `saldo-offline-*` cache. `skipWaiting` + `clients.claim`, safe because the worker holds no state of the app.
6. **`/sw.js` is generated by a route handler** from `APP_VERSION`, with `Content-Type: application/javascript;
   charset=utf-8` and `Cache-Control: no-cache`. Scope `/` (served from the root), so no `Service-Worker-Allowed`.
7. **CSP:** the `default-src 'self'` fallback already covers workers and the manifest; `worker-src 'self'` and
   `manifest-src 'self'` are added explicitly so a later change of `default-src` cannot break installation.
8. **No auth guard in the way:** the guards live in the `(app)` layout, not in a middleware, so `/sw.js`,
   `/manifest.webmanifest`, `/offline` and the icons answer without a session (checked with `curl` after the build).
9. **The Docker image now copies `public/`.** The standalone output does not, so the icons (and the mascot at
   `/rocky/idle.png`) would have been 404 in the image.
