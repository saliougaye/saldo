# 0.3a — User data projection and the user's time zone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Server code reads a user's rows through one typed projection (`loadUserData`), and every place that computes «today» for a user — the server now, the web, MCP and AI later — knows that user's time zone, which the phone fills at onboarding and the user changes in Profile.

**Architecture:** `@saldo/core` gains the `UserData` shape (moved out of the backup), a lenient reader for the `settings` row and an optional `settings.timeZone`. `@saldo/i18n` gains the time-zone data (generated from Node's CLDR, like the currency names) and the `Intl` helpers that turn an instant into a wall clock in a zone — shared by the server's «today» and the phone's time-zone screen. `apps/web/src/server/userData/` is the projection: it loads live `sync_rows`, parses each with `entitySchemas` (skipping and logging what does not parse), reads `settings` with defaults, and wraps the load in React's `cache()`. The phone stores the zone in a new SQLite column, fills it at onboarding and on boot, and shows it in Profile as mockup variant «Viaggio + ora».

**Tech Stack:** TypeScript strict, Zod 4, Vitest (core, i18n, web), Drizzle (Postgres via PGlite in tests; SQLite on the phone), Jest + React Native Testing Library (mobile), Expo Router.

**Spec:** `docs/superpowers/specs/2026-09-10-saldo-poc-spec.md` §4.1 (`timeZone`), §6.8 (Fuso orario), §17.1.2, §17.1.5, D37. **Roadmap:** `ROADMAP.md` 0.3a. **Mockup:** `docs/superpowers/mockups/2026-09-26-timezone-variants.html`, variant «Viaggio + ora» (`?variant=travelTime`).

## Decisions taken while writing this plan

These fill gaps the spec leaves to the plan, or correct it. Task 14 writes them back into the spec.

1. **`UserData.settings` is `Settings | null`.** `null` means no live row (never onboarded, or a tombstone after «Elimina tutti i dati»). The backup keeps its stricter shape: `BackupData` is `UserData` with `settings` required.
2. **The lenient settings reader lives in `@saldo/core`** (`readSettings`), next to `UserData`, so MCP and AI read settings the same way. `entitySchemas` stays strict.
3. **The fallback variable is `DEFAULT_TIME_ZONE`, not `TZ`.** `TZ` is reserved on Vercel (it is AWS Lambda's own variable) and cannot be set there; and in Node, `TZ` also moves the process's local time zone, which the server must not depend on. Default `UTC`.
4. **The instant → wall-clock conversion lives in `@saldo/i18n`**, not in `apps/web` as §17.1.5 says: the phone's time-zone screen needs the same conversion to show each zone's local time, and `@saldo/i18n` is already the package allowed to use `Intl`. Core still has no `Intl`.
5. **`loadAttachment` returns a status** (`found` / `missing` / `invalid`) instead of throwing. `attachments/row.ts` keeps `requireAttachment` as the HTTP wrapper that turns the status into the existing 404 / 422, so no route and no route test changes.
6. **Time zone names are generated, city names are a short hand-written list.** Hermes has no `Intl.DisplayNames` and its support for `timeZoneName: 'longGeneric'` is not something to rely on, so the generic names («Ora dell’Europa centrale») are generated from Node's CLDR into `timeZones.generated.ts`, deduplicated per locale. CLDR's exemplar cities are not reachable through `Intl` at all, so a short list of common cities is translated by hand and every other zone shows IANA's English city.
7. **Existing phones are backfilled on boot**: a settings row with no `timeZone` gets the device's, but **only when the row is synced**. A pending row may be one that `yieldSettingsToAccount` stamped with the oldest HLC so the account's settings win; writing it would give it a fresh HLC and flip that. The next boot after the sync tries again.
8. **Times are shown as `HH:MM` in every locale**, 24-hour, as the rest of the app shows no clock times at all yet. Revisit if en-US users ask.
9. **The top group does not repeat in «Tutti»**, as the currency picker's «Comuni» does not repeat in «Tutte».

```ts
import { z } from 'zod';
import {
  accountSchema,
  attachmentSchema,
  budgetSchema,
  categorySchema,
  type EntityName,
  recurrenceSchema,
  type Settings,
  settingsSchema,
  tagSchema,
  transactionSchema,
} from './entities';
import { SETTINGS_ID } from './ids';

/**
 * Everything one user has, typed (§17.1.2). The backup (§11.1) and the server's projection share
 * this shape, and so will MCP and AI: one type crosses all of them. `settings` is null until the
 * user onboards, and again after «Elimina tutti i dati».
 */
export const userDataSchema = z.object({
  settings: settingsSchema.nullable(),
  accounts: z.array(accountSchema),
  categories: z.array(categorySchema),
  tags: z.array(tagSchema),
  transactions: z.array(transactionSchema),
  recurrences: z.array(recurrenceSchema),
  budgets: z.array(budgetSchema),
  attachments: z.array(attachmentSchema),
});

export type UserData = z.infer<typeof userDataSchema>;

type Collection = Exclude<keyof UserData, 'settings'>;

/** Which collection of `UserData` holds each entity; `settings` is a singleton, not a list. */
export const USER_DATA_COLLECTIONS = {
  account: 'accounts',
  category: 'categories',
  tag: 'tags',
  transaction: 'transactions',
  recurrence: 'recurrences',
  budget: 'budgets',
  attachment: 'attachments',
} as const satisfies Record<Exclude<EntityName, 'settings'>, Collection>;

export function emptyUserData(): UserData {
  return {
    settings: null,
    accounts: [],
    categories: [],
    tags: [],
    transactions: [],
    recurrences: [],
    budgets: [],
    attachments: [],
  };
}

/** What a settings field falls back to when the stored value cannot be read (§17.1.2). */
export const SETTINGS_DEFAULTS = {
  periodKind: 'month',
  cycleStartDay: 27,
  currency: 'EUR',
  language: 'system',
  theme: 'system',
} as const satisfies Pick<
  Settings,
  'periodKind' | 'cycleStartDay' | 'currency' | 'language' | 'theme'
>;

const EPOCH = '1970-01-01T00:00:00.000Z';
const shape = settingsSchema.shape;

/**
 * `settingsSchema`, with every field that fails replaced by its default instead of failing the row.
 * Read-only: push still validates with the strict schema, and this one never reaches storage.
 */
const lenientSettingsSchema = z.object({
  id: z.literal(SETTINGS_ID).catch(SETTINGS_ID),
  createdAt: shape.createdAt.catch(EPOCH),
  updatedAt: shape.updatedAt.catch('0'),
  deletedAt: shape.deletedAt.catch(null),
  periodKind: shape.periodKind.catch(SETTINGS_DEFAULTS.periodKind),
  cycleStartDay: shape.cycleStartDay.catch(SETTINGS_DEFAULTS.cycleStartDay),
  currency: shape.currency.catch(SETTINGS_DEFAULTS.currency),
  language: shape.language.catch(SETTINGS_DEFAULTS.language),
  theme: shape.theme.catch(SETTINGS_DEFAULTS.theme),
  onboardingCompletedAt: shape.onboardingCompletedAt.catch(null),
  timeZone: shape.timeZone.catch(null),
});

/**
 * The settings row as the server reads it (§17.1.2): **never skipped**. Skipping an unreadable row
 * would look like «never onboarded», and onboarding would then write a new `settings` over the real
 * one. A field this build cannot read gets its default; the rest of the row is kept.
 */
export function readSettings(data: unknown): Settings {
  const object = typeof data === 'object' && data !== null && !Array.isArray(data) ? data : {};
  return lenientSettingsSchema.parse(object);
}
```

```ts
import { normalizeText } from './filters';

/** The two runs of the time-zone screen (§6.8 Fuso orario). */
export interface TimeZoneGroups {
  /** The saved zone, then the phone's when it differs. */
  top: string[];
  /** Every other zone that matches, in the order given. */
  all: string[];
}

/**
 * What the time-zone screen lists for a search (§6.8). The saved zone is always on top, and the
 * phone's zone under it when they differ: travelling must not bury the check under «R». A zone in
 * `top` is not repeated in `all`, as «Comuni» is not repeated in the currency picker.
 *
 * A zone matches on its IANA id or any label the caller gives it (city, zone name), ignoring case
 * and accents. The caller sorts `zones`, because only it knows the city names it shows.
 */
export function groupTimeZones(input: {
  query: string;
  saved: string | null;
  device: string;
  zones: readonly string[];
  labelsOf: (zone: string) => readonly string[];
}): TimeZoneGroups {
  const needle = normalizeText(input.query);
  const matches = (zone: string) =>
    needle === '' ||
    [zone, ...input.labelsOf(zone)].some((value) => normalizeText(value).includes(needle));
  const top = [...new Set([input.saved ?? input.device, input.device])].filter(matches);
  return { top, all: input.zones.filter((zone) => !top.includes(zone) && matches(zone)) };
}
```

```js
/**
 * Regenerates `src/timeZones.generated.ts` from the CLDR data bundled with Node's Intl.
 *
 * Run with: pnpm --filter @saldo/i18n generate:time-zones
 *
 * Generated rather than asked of the phone, like the currency names: Hermes cannot be relied on for
 * `timeZoneName: 'longGeneric'`. The zones are `Intl.supportedValuesOf('timeZone')` plus `UTC`.
 * Names repeat a lot (every zone in central Europe is «Ora dell’Europa centrale»), so each locale
 * stores its distinct names once and one index per zone.
 */
import { writeFileSync } from 'node:fs';
import { dirname, join } from 'node:path';
import { fileURLToPath } from 'node:url';

const OUT = join(dirname(fileURLToPath(import.meta.url)), '..', 'src', 'timeZones.generated.ts');

/** App locale → the CLDR locale to read. Keep in step with `SUPPORTED_LOCALES` in `src/format.ts`. */
const LOCALES = [
  ['it', 'it'],
  ['en', 'en'],
  ['fr', 'fr'],
  ['de', 'de'],
  ['sv', 'sv'],
  ['es', 'es'],
  ['pt', 'pt-PT'],
];

const zones = [...new Set([...Intl.supportedValuesOf('timeZone'), 'UTC'])].sort();

/** January, so the generic name is taken outside any daylight-saving switch. */
const AT = new Date(Date.UTC(2026, 0, 15, 12));

function genericName(zone, locale) {
  const name = new Intl.DateTimeFormat(locale, { timeZone: zone, timeZoneName: 'longGeneric' })
    .formatToParts(AT)
    .find((part) => part.type === 'timeZoneName')?.value;
  if (name === undefined || name === '') throw new Error(`No ${locale} name for ${zone}`);
  return name;
}

const quote = (value) => `'${value.replace(/\\/g, '\\\\').replace(/'/g, "\\'")}'`;

const tables = LOCALES.map(([key, locale]) => {
  const names = [];
  const index = new Map();
  const of = zones.map((zone) => {
    const name = genericName(zone, locale);
    if (!index.has(name)) {
      index.set(name, names.length);
      names.push(name);
    }
    return index.get(name);
  });
  return `  ${key}: {
    names: [
```

```ts
import { type LocalDate, makeLocalDate } from '@saldo/core';
import type { AppLocale } from './format';
import { CITY_NAMES } from './timeZoneCities';
import { TIME_ZONE_GENERIC_NAMES, TIME_ZONES } from './timeZones.generated';

export { TIME_ZONES };

const POSITION = new Map(TIME_ZONES.map((zone, index) => [zone, index]));

/** «Roma», «Zürich», «Los Angeles»: the city a zone is named after, in the app's language. */
export function timeZoneCity(zone: string, locale: AppLocale): string {
  const translated = CITY_NAMES[locale][zone];
  if (translated !== undefined) return translated;
  return (zone.split('/').at(-1) ?? zone).replaceAll('_', ' ');
}

/** «Ora dell’Europa centrale»; undefined for an id CLDR does not list. */
export function timeZoneName(zone: string, locale: AppLocale): string | undefined {
  const position = POSITION.get(zone);
  if (position === undefined) return undefined;
  const table = TIME_ZONE_GENERIC_NAMES[locale];
  const index = table.of[position];
  return index === undefined ? undefined : table.names[index];
}

/** The date and time a clock on the wall shows in a zone. */
export interface WallClock {
  year: number;
  /** 1-12 */
  month: number;
  day: number;
  /** 0-23 */
  hour: number;
  minute: number;
}

const formatters = new Map<string, Intl.DateTimeFormat | null>();

/**
 * One formatter per zone, built once: building them is the expensive part, and the time-zone
 * screen asks for every zone at once. `null` remembers a name `Intl` refused.
 */
function formatterFor(zone: string): Intl.DateTimeFormat | null {
  const cached = formatters.get(zone);
  if (cached !== undefined) return cached;
  let formatter: Intl.DateTimeFormat | null;
  try {
    formatter = new Intl.DateTimeFormat('en-US', {
      timeZone: zone,
      hourCycle: 'h23',
      year: 'numeric',
      month: 'numeric',
      day: 'numeric',
      hour: 'numeric',
      minute: 'numeric',
    });
  } catch {
    formatter = null;
  }
  formatters.set(zone, formatter);
  return formatter;
}

export function isTimeZone(zone: string): boolean {
  return zone.length > 0 && formatterFor(zone) !== null;
}

/**
 * The wall clock in `zone` at `now`, or null if `Intl` does not know the zone (§17.1.5). This is
 * where an instant becomes a day: the server's «today» and the phone's time-zone screen both read it.
 */
export function wallClock(zone: string, now: Date): WallClock | null {
  const formatter = zone.length > 0 ? formatterFor(zone) : null;
  if (formatter === null) return null;
  const parts = formatter.formatToParts(now);
  const read = (type: Intl.DateTimeFormatPartTypes) =>
    Number(parts.find((part) => part.type === type)?.value);
  const clock = {
    year: read('year'),
    month: read('month'),
    day: read('day'),
    hour: read('hour'),
    minute: read('minute'),
  };
  return Object.values(clock).every(Number.isInteger) ? clock : null;
}

export function localDateOf(clock: WallClock): LocalDate {
  return makeLocalDate(clock.year, clock.month, clock.day);
}

const pad2 = (value: number) => String(value).padStart(2, '0');

/** `07:04`, 24-hour in every language: the app shows no other clock time to be consistent with. */
export function formatWallTime(clock: WallClock): string {
  return `${pad2(clock.hour)}:${pad2(clock.minute)}`;
}

/** The zone this device or browser runs in, or UTC if it reports nothing usable. */
export function systemTimeZone(): string {
  const zone = new Intl.DateTimeFormat().resolvedOptions().timeZone;
  return typeof zone === 'string' && isTimeZone(zone) ? zone : 'UTC';
}
```

```ts
import type { LocalDate, Settings } from '@saldo/core';
import { isTimeZone, localDateOf, wallClock } from '@saldo/i18n';

/**
 * The zone the server computes a user's day in (§17.1.5): theirs, or the instance's fallback when
 * they have none yet or it names a zone `Intl` does not know (renamed, or edited by hand).
 */
export function resolveTimeZone(saved: string | null | undefined, fallback: string): string {
  return saved !== null && saved !== undefined && isTimeZone(saved) ? saved : fallback;
}

/**
 * «Today» for a user, as a `LocalDate` to inject into core like the phone injects its own
 * (§17.1.5). `fallback` is `env().defaultTimeZone`, which `readEnv` has already validated.
 */
export function todayFor(
  settings: Pick<Settings, 'timeZone'> | null,
  fallback: string,
  now: Date = new Date(),
): { today: LocalDate; timeZone: string } {
  const timeZone = resolveTimeZone(settings?.timeZone, fallback);
  const clock = wallClock(timeZone, now) ?? wallClock('UTC', now);
  if (clock === null) throw new Error('Intl cannot read UTC');
  return { today: localDateOf(clock), timeZone };
}
```

```ts
import {
  type EntityName,
  emptyUserData,
  entitySchemas,
  readSettings,
  USER_DATA_COLLECTIONS,
  type UserData,
} from '@saldo/core';
import { and, asc, eq, isNull } from 'drizzle-orm';
import { syncRows } from '../db/schema';
import type { ServerDatabase } from '../db/types';
import { log, shortId } from '../log';

const isEntityName = (value: string): value is EntityName => Object.hasOwn(entitySchemas, value);

/**
 * The projection (§17.1.2): a user's live rows from `sync_rows`, each parsed with its entity
 * schema, as one typed `UserData`. **The only way server code reads a row's contents**; push and
 * pull move envelopes without looking inside.
 *
 * A row that fails its schema is skipped and logged, never fatal: push already refuses such rows,
 * so a stored one fails only when the schema changed under it (a server rolled back, a field added
 * without `.optional()`, a hand edit). `settings` is the exception, read with defaults by
 * `readSettings`, because skipping it would send the user to onboarding over their real settings.
 *
 * Loads everything, every time, as the phone does from SQLite. A known limit, not an oversight; see
 * §17.1.2 for what to do when it starts to show.
 */
export async function readUserData(db: ServerDatabase, userId: string): Promise<UserData> {
  const rows = await db
    .select({ entity: syncRows.entity, id: syncRows.id, data: syncRows.data })
    .from(syncRows)
    .where(and(eq(syncRows.userId, userId), isNull(syncRows.deletedAt)))
    .orderBy(asc(syncRows.entity), asc(syncRows.id));

  const data = emptyUserData();
  let skipped = 0;
  for (const row of rows) {
    if (!isEntityName(row.entity)) {
      skipped += 1;
      log('userData', 'skipped a row of an unknown entity', { user: shortId(userId), entity: row.entity });
      continue;
    }
    if (row.entity === 'settings') {
      data.settings = readSettings(row.data);
      continue;
    }
    const parsed = entitySchemas[row.entity].safeParse(row.data);
    if (!parsed.success) {
      skipped += 1;
      log('userData', 'skipped a row that does not parse', {
        user: shortId(userId),
        entity: row.entity,
        id: shortId(row.id),
        issues: parsed.error.issues.map((issue) => `${issue.path.join('.')}: ${issue.message}`),
      });
      continue;
    }
    // `entitySchemas[row.entity]` and `USER_DATA_COLLECTIONS[row.entity]` are keyed by the same
    // entity, but TypeScript cannot correlate the two lookups through a union.
    (data[USER_DATA_COLLECTIONS[row.entity]] as unknown[]).push(parsed.data);
  }
  if (skipped > 0) log('userData', `loaded with ${skipped} rows skipped`, { user: shortId(userId) });
  return data;
}
```

Zod issue messages carry no row contents (they say «Expected string, received number»), which keeps
`log.ts`'s rule of never logging a row's contents.

```ts
import { syncRows } from '../db/schema';
import type { ServerDatabase } from '../db/types';

export type AttachmentLookup =
  | { status: 'found'; attachment: Attachment }
  | { status: 'missing' }
  | { status: 'invalid' };

/**
 * One attachment row, for the upload and download endpoints (§10). Part of the projection
 * (§17.1.2) rather than a query of its own: loading the whole `UserData` to check one blob would be
 * absurd, but reading a row's contents still happens here and nowhere else.
 */
export async function loadAttachment(
  db: ServerDatabase,
  userId: string,
  id: string,
): Promise<AttachmentLookup> {
  const [row] = await db
    .select({ data: syncRows.data })
    .from(syncRows)
    .where(
      and(
        eq(syncRows.userId, userId),
        eq(syncRows.entity, 'attachment'),
        eq(syncRows.id, id),
        isNull(syncRows.deletedAt),
      ),
    )
    .limit(1);
  if (row === undefined) return { status: 'missing' };
  const parsed = attachmentSchema.safeParse(row.data);
  return parsed.success ? { status: 'found', attachment: parsed.data } : { status: 'invalid' };
}
```

```ts
import type { Attachment } from '@saldo/core';
import type { ServerDatabase } from '../db/types';
import { ApiError } from '../http/errors';
import { loadAttachment } from '../userData/attachment';

/**
 * The attachment row this upload or download is about (§10). Its absence is what enforces the
 * ordering the sync needs: **the row is pushed before its bytes**, so blobs can never arrive for
 * something the server has never heard of — and a row belonging to somebody else is simply not
 * found, rather than refused in a way that would confirm it exists.

export async function requireAttachment(

  userId: string,
  id: string,

}
```

```ts
import { eq } from 'drizzle-orm';
import type { Repositories } from './repositories';
import { type RepositoryDatabase, SYNCED } from './repositories/support';
import { settings } from './schema';

/**
 * Gives a phone that onboarded before `settings.timeZone` existed its device's zone (D37), so the
 * server stops falling back to `DEFAULT_TIME_ZONE` for it. Returns whether it wrote.
 *
 * Only a **synced** row is touched. A pending one may be the row «Porta nell’account» stamped with
 * the oldest HLC so the account's settings win (`yieldSettingsToAccount`); updating it would give it
 * a fresh HLC and make the phone's settings win instead. After the sync, the next boot fills it.
 */
export function backfillTimeZone(
  db: RepositoryDatabase,
  repos: Repositories,
  zone: string,
): boolean {
  const [row] = db
    .select({ timeZone: settings.timeZone, syncState: settings.syncState })
    .from(settings)
    .where(eq(settings.id, 'settings'))
    .all();
  if (row === undefined || row.timeZone !== null || row.syncState !== SYNCED) return false;
  repos.settings.update({ timeZone: zone });
  return true;
}
```

```tsx
import { groupTimeZones } from '@saldo/core';
import {
  formatWallTime,
  TIME_ZONES,
  timeZoneCity,
  timeZoneName,
  wallClock,
} from '@saldo/i18n';
import { useMemo, useState } from 'react';
import { useTranslation } from 'react-i18next';
import { View } from 'react-native';
import { PrimaryButton } from '../../components/Button';
import { Card } from '../../components/Card';
import { IconBox } from '../../components/ListRow';
import { SectionDivider } from '../../components/SectionDivider';
import { TextField } from '../../components/TextField';
import { useAppLocale } from '../../i18n/useAppLocale';
import { Text } from '../../theme/Text';
import { useTheme } from '../../theme/ThemeProvider';
import { OptionRow } from './SettingScreen';

export interface TimeZoneListProps {
  /** The zone in the synced settings; null only on a phone the backfill has not reached yet. */
  saved: string | null;
  /** The zone the phone runs in now. */
  device: string;
  /** Captured once by the screen: the times are read when it opens, not ticked. */
  now: Date;
  onSelect: (zone: string) => void;
}

/**
 * §6.8 Fuso orario, mockup variant «Viaggio + ora». The saved zone on top, and the phone's under it
 * when they differ, with a notice: travelling is the one moment when the web and the phone disagree
 * about today (D37). Each row shows the local time, not the GMT offset — people look for «where it
 * is 10:45», not for «GMT−4».
 */
export function TimeZoneList({ saved, device, now, onSelect }: TimeZoneListProps) {
  const { t } = useTranslation();
  const theme = useTheme();
  const locale = useAppLocale();
  const [query, setQuery] = useState('');

  const zones = useMemo(
    () =>
      [...TIME_ZONES].sort((a, b) =>
        timeZoneCity(a, locale).localeCompare(timeZoneCity(b, locale), locale),
      ),
    [locale],
  );
  const labelsOf = (zone: string) => [timeZoneCity(zone, locale), timeZoneName(zone, locale) ?? ''];
  const groups = groupTimeZones({ query, saved, device, zones, labelsOf });
  const time = (zone: string) => {
    const clock = wallClock(zone, now);
    return clock === null ? undefined : formatWallTime(clock);
  };
  const current = saved ?? device;
  const away = current !== device;

  const rows = (list: string[]) => (
    <Card padded={false}>
      <View style={{ paddingHorizontal: theme.layout.cardPadding, paddingVertical: 8 }}>
        {list.map((zone) => (
          <OptionRow
            key={zone}
            label={timeZoneCity(zone, locale)}
            subtitle={timeZoneName(zone, locale)}
            detail={time(zone)}
            selected={zone === current}
            onPress={() => onSelect(zone)}
          />
        ))}
      </View>
    </Card>
  );

  return (
    <>
      {away ? (
        <Card style={{ gap: 12 }}>
          <View style={{ flexDirection: 'row', gap: 12, alignItems: 'flex-start' }}>
            <IconBox name="plane" colour={theme.palette.textMuted} small />
            <Text style={{ flex: 1 }}>
              {t('timeZone.notice', {
                city: timeZoneCity(device, locale),
                time: time(device) ?? '',
                saved: timeZoneCity(current, locale),
              })}
            </Text>
          </View>
          <PrimaryButton
            label={t('timeZone.use', { city: timeZoneCity(device, locale) })}
            onPress={() => onSelect(device)}
          />
        </Card>
      ) : null}
      <TextField
        label={t('timeZone.search')}
        placeholder={t('timeZone.search')}
        value={query}
        onChangeText={setQuery}
        autoCorrect={false}
        autoCapitalize="none"
        clearButtonMode="while-editing"
      />
      {groups.top.length > 0 ? (
        <>
          <SectionDivider label={t(away ? 'timeZone.currentAndPhone' : 'timeZone.current')} />
          {rows(groups.top)}
        </>
      ) : null}
      {groups.all.length > 0 ? (
        <>
          <SectionDivider label={t('timeZone.all')} />
          {rows(groups.all)}
        </>
      ) : null}
      {groups.top.length === 0 && groups.all.length === 0 ? (
        <Text color="textMuted">{t('timeZone.noResults')}</Text>
      ) : null}
    </>
  );
}
```
