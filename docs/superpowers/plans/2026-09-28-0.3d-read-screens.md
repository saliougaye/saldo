# 0.3d — Read screens on the web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the web app shows what the phone shows — Home, Transazioni, Statistiche, Conti and Profilo — computed by the
same `@saldo/core` functions, to the cent.

**Architecture:** every page is a Server Component. It calls `requireWebUser()`, `loadUserData(user.id)` and
`todayFor(...)`, hands the arrays to `@saldo/core`, and renders. Nothing reads `sync_rows` outside the projection, and
no number is computed in `apps/web`: where the phone holds a calculation in `apps/mobile/src/features/**`, that module
**moves into `@saldo/core`** and the phone is refactored onto it with its tests unchanged (as 0.3c did with
`ringGeometry`). The URL carries the state a page needs to be shareable and reloadable — the period (`?p=`), the
filters (`?q=`, `?account=`, `?direction=`, `?tag=`), the selected row (`?t=`, `?a=`, `?g=`) — so a page needs no
client state to be correct; client components exist only where a keystroke or a pointer must be heard.

**Layout:** two shapes of every screen, as §17.1.7 decided. At and above `--layout-breakpoint-web` (1024px) a top bar
and the open, two-column pages of the mockups; below it the phone's shape — a bottom tab bar, one column, cards. One
set of components, one CSS Module each, with the breakpoint as a media query. No JavaScript decides which shape is
drawn; the server renders both and CSS picks.

**Tech Stack:** Next 16 App Router (Server Components, `force-dynamic`), CSS Modules over the token custom properties
of `tokensCss()`, Base UI for anything with behaviour (menu, dialog, popover), `@saldo/core` for every number,
`@saldo/i18n` for every string and every format, `@saldo/ui` for icons, tokens and chart geometry. Tests: Vitest in
`apps/web` (pure functions and route/page helpers over PGlite), Jest + RNTL in `apps/mobile` for the refactors, Vitest
in `packages/core` for everything that moves there.

**What this phase does not do:** no writes. Every form, `/onboarding`, the «Nuova transazione» button's sheet and the
account form belong to 0.3e; where the design shows one, this phase renders the affordance disabled with the line that
says so, or does not render it at all (stated per task). Recurrences and attachments are shown, never edited (§17.1.9).

## Decisions taken while writing this plan

1. **Conti is in this phase** (decided with the user, 2026-09-28). The roadmap's 0.3d row predates Conti joining the
   0.3 screens (§17.1.7, 2026-09-27). Its read side — the list, the pockets, the goals, the account, credit-card and
   goal detail panels — ships here; the account form ships with the other forms in 0.3e.
2. **Both layouts from the start** (decided with the user, 2026-09-28): every screen is built wide *and* narrow in the
   same task, rather than a wide-only pass followed by a responsive one.
3. **Three phone view-models move into `@saldo/core`**: `budgetViews`, `goalViews` and `transactionRow`. They are
   already pure and already only depend on core; leaving them in `apps/mobile` would mean writing them a second time
   in `apps/web`, which is exactly what §17.1.2 forbids. `transactionRow` loses its `IconName` and `SignDisplay`
   imports — core depends on no other workspace package — and returns `icon: string` and its own `AmountSign` union,
   which both apps narrow at the edge.
4. **The period lives in the URL as the range's start** (`?p=2026-09-27`), not as an offset. An offset means "three
   periods before *now*", which changes meaning at midnight and cannot be shared; a start is the range itself once
   `def` is known, and `describePeriod` turns it back into a `PeriodView`.
5. **`settings === null` does not send anybody to `/onboarding` in this phase**, because `/onboarding` is built in
   0.3e. Every page renders its empty state with one line — «Finisci la configurazione dal telefono» — and Home links
   to nothing. Task 26 replaces that line with the redirect in one place (`requireOnboarded`).
6. **Hidden mode and the lock do not exist on the web** (§17.1.6: device-local state on the phone has no web
   counterpart in 0.3). Every figure is rendered plainly. The chart geometry's `hidden` parameter is always `false`.
7. **The theme comes from `settings.theme`**: the `(app)` layout sets `data-theme` on `<html>`… which a nested layout
   cannot do. It is set on the shell's own wrapper element instead, and `tokensCss()`'s `[data-theme="light"]` block
   already matches any element, not only the root. `system` sets no attribute and leaves the media query to decide.
8. **No number is formatted in a Client Component.** A client component receives strings, as 0.3b established. The one
   exception is `AmountText`'s parts, which arrive as a `MoneyParts` object, not as a `minor` to format.

```ts
// apps/web/src/features/shell/nav.ts

/** A destination of the shell: the same list drives the top bar, the tab bar and the avatar menu. */
export interface NavItem {
  key: 'home' | 'transactions' | 'stats' | 'accounts' | 'admin';
  href: string;
  /** An icon of `@saldo/ui`'s set, narrowed to `IconName` where it is rendered. */
  icon: string;
  /** A dotted path for `t()`; the shell resolves it, so this stays a pure list. */
  labelKey: string;
  /** Sits on the trailing side of the top bar, and outside the tab bar (§17.1.7). */
  trailing?: true;
}

const TABS: NavItem[] = [
  { key: 'home', href: '/home', icon: 'house', labelKey: 'tabs.home' },
  { key: 'transactions', href: '/transactions', icon: 'list', labelKey: 'tabs.transactions' },
  { key: 'stats', href: '/stats', icon: 'activity', labelKey: 'tabs.stats' },
  { key: 'accounts', href: '/accounts', icon: 'wallet', labelKey: 'tabs.accounts' },
];

/**
 * §17.1.7: the four tabs of the phone, plus Admin for the `admin` role. Admin is `trailing`, which is
 * what keeps it out of the bottom tab bar on a narrow screen — it is reached from the avatar there.
 */
export function navItems(admin: boolean): NavItem[] {
  return admin
    ? [...TABS, { key: 'admin', href: '/admin', icon: 'settings', labelKey: 'admin.title', trailing: true }]
    : [...TABS];
}

/** Whether a nav item owns the path being rendered: its section, and anything under it. */
export function isCurrent(href: string, path: string): boolean {
  const [pathname = ''] = path.split('?');
  return pathname === href || pathname.startsWith(`${href}/`);
}
```

```tsx
// apps/web/app/(app)/layout.tsx
import { readSettings } from '@saldo/core';
import type { ReactNode } from 'react';
import { userI18n } from '../../src/i18n/server';
import { isAdmin } from '../../src/server/auth/admin';
import { requireWebUser } from '../../src/server/auth/currentUser';
import { getDb } from '../../src/server/db/client';
import { loadUserData } from '../../src/server/userData/load';
import { navItems } from '../../src/features/shell/nav';
import { TabBar } from '../../src/ui/TabBar';
import { TopBar } from '../../src/ui/TopBar';
import styles from './shell.module.css';

export const runtime = 'nodejs';
export const dynamic = 'force-dynamic';

/**
 * §17.1.7: a top bar on wide screens, the phone's tab bar on narrow ones — both rendered, CSS picks.
 * The theme is set here rather than on `<html>`, which a nested layout cannot touch; `tokensCss()`
 * writes `[data-theme="light"]` as an attribute selector, so any element carries it.
 */
export default async function AppLayout({ children }: { children: ReactNode }) {
  const user = await requireWebUser();
  const [data, admin, { t }] = await Promise.all([
    loadUserData(user.id),
    isAdmin(getDb(), user.id),
    userI18n(user.id),
  ]);
  const settings = readSettings(data.settings);
  const items = navItems(admin).map((item) => ({ ...item, label: t(item.labelKey) }));
  return (
    <div
      className={styles.shell}
      data-theme={settings.theme === 'system' ? undefined : settings.theme}
    >
      <a className={styles.skip} href="#content">
        {t('web.shell.skipToContent')}
      </a>
      <TopBar
        items={items}
        user={{ name: user.displayName, email: user.email }}
        strings={{
          newTransaction: t('web.shell.newTransaction'),
          openMenu: t('web.shell.openMenu'),
          profile: t('profile.title'),
          signOut: t('sync.signOut'),
          working: t('common.loading'),
          notYet: t('web.shell.comingIn0_3e'),
        }}
      />
      <main className={styles.content} id="content">
        {children}
      </main>
      <TabBar items={items.filter((item) => item.trailing !== true)} />
    </div>
  );
}
```

```tsx
// apps/web/src/ui/AmountText.tsx
import type { AmountSign } from '@saldo/core';
import { type CurrencyCode, type AppLocale, formatMoneyParts } from '@saldo/i18n';
import styles from './AmountText.module.css';

/**
 * Which of the three colours an amount takes. Only a **signed** amount is ever coloured: an expense
 * list is all expenses, and painting every row red says nothing (the phone's rule, §5.3).
 */
export function amountClass(minor: number, sign: AmountSign): 'positive' | 'negative' | 'neutral' {
  if (sign !== 'always') return 'neutral';
  if (minor > 0) return 'positive';
  if (minor < 0) return 'negative';
  return 'neutral';
}

interface Props {
  minor: number;
  currency: CurrencyCode;
  locale: AppLocale;
  sign?: AmountSign;
  /** `hero` is the 56px figure of a band, `body` a row's trailing amount. */
  size?: 'hero' | 'title' | 'body' | 'footnote';
  muted?: boolean;
}

/**
 * The design's amount: the fraction and the symbol at 50% opacity, the integer at full. Hidden mode
 * is a phone-only, device-local state (§17.1.6), so there is nothing to mask here.
 */
export function AmountText({
  minor,
  currency,
  locale,
  sign = 'negative',
  size = 'body',
  muted = false,
}: Props) {
  const parts = formatMoneyParts(minor, currency, locale, sign);
  const symbol = <span className={styles.dim}>{parts.symbol}</span>;
  return (
    <span
      className={`${styles.amount} ${styles[size]} ${styles[amountClass(minor, sign)]} ${
        muted ? styles.muted : ''
      }`}
    >
      {parts.sign}
      {parts.symbolPosition === 'prefix' ? symbol : null}
      {parts.integer}
      {parts.fraction === '' ? null : (
        <span className={styles.dim}>
          {parts.decimalSeparator}
          {parts.fraction}
        </span>
      )}
      {parts.symbolPosition === 'suffix' ? <> {symbol}</> : null}
    </span>
  );
}
```

```ts
// apps/web/src/features/period/periodParams.ts
import {
  canShiftPeriod,
  type DateRange,
  describePeriod,
  isLocalDate,
  type LocalDate,
  type PeriodDef,
  periodContaining,
  type PeriodView,
  shiftPeriod,
} from '@saldo/core';

/** The query parameter that carries the period, on every screen that has one. */
export const PERIOD_PARAM = 'p';

/**
 * The period a request is reading. `?p=` holds a **date inside** the range rather than an offset: an
 * offset means «three periods before now», which changes meaning at midnight and cannot be shared,
 * while a date is the same period whenever it is opened.
 *
 * Anything unreadable, and anything after the current period (the phone's `MAX_PERIODS_AHEAD`),
 * falls back to the period containing `today` — a hand-typed URL must not be able to show a page a
 * tap could not reach.
 */
export function periodFromParam(
  def: PeriodDef,
  today: LocalDate,
  param: string | undefined,
): PeriodView {
  const current = periodContaining(def, today);
  if (param === undefined || !isLocalDate(param)) return describePeriod(current, today);
  const range = periodContaining(def, param);
  if (range.start > current.start) return describePeriod(current, today);
  return describePeriod(range, today);
}

/** `?p=` for a range, or the bare path when it is the period containing `today`. */
export function periodHref(
  path: string,
  range: DateRange,
  def: PeriodDef,
  today: LocalDate,
  others: Record<string, string> = {},
): string {
  const params = new URLSearchParams(others);
  if (range.start !== periodContaining(def, today).start) params.set(PERIOD_PARAM, range.start);
  const query = params.toString();
  return query === '' ? path : `${path}?${query}`;
}

export interface PeriodSteps {
  previous: string;
  /** `null` while the current period is on screen: there is nothing after it (§6.15). */
  next: string | null;
}

/** The ‹ › of the period header, as links — so they work with no JavaScript and can be opened in a tab. */
export function periodSteps(
  def: PeriodDef,
  range: DateRange,
  today: LocalDate,
  path: string,
  others: Record<string, string> = {},
): PeriodSteps {
  return {
    previous: periodHref(path, shiftPeriod(def, range, -1), def, today, others),
    next: canShiftPeriod(def, range, 1, today)
      ? periodHref(path, shiftPeriod(def, range, 1), def, today, others)
      : null,
  };
}
```

```ts
import {
  type CurrencyCode,
  type LocalDate,
  type PeriodDef,
  type PeriodView,
  readSettings,
  type Settings,
  type UserData,
} from '@saldo/core';
import { periodFromParam, PERIOD_PARAM } from '../../features/period/periodParams';
import { todayFor } from '../userData/today';

export interface PageState {
  settings: Settings;
  /** `false` when there is no `settings` row: the account has never onboarded (§17.1.2). */
  onboarded: boolean;
  def: PeriodDef;
  currency: CurrencyCode;
  today: LocalDate;
  timeZone: string;
  period: PeriodView;
}

/**
 * Everything a read screen needs before it looks at a single transaction, in one place so no page
 * invents its own «today» or its own period. Pure: the caller supplies the projection and the clock.
 */
export function pageState(input: {
  data: UserData;
  now: Date;
  fallbackTimeZone: string;
  params: Record<string, string | undefined>;
}): PageState {
  const settings = readSettings(input.data.settings);
  const { today, timeZone } = todayFor(settings, input.fallbackTimeZone, input.now);
  const def: PeriodDef = { kind: settings.periodKind, startDay: settings.cycleStartDay };
  return {
    settings,
    onboarded: input.data.settings !== null,
    def,
    currency: settings.currency,
    today,
    timeZone,
    period: periodFromParam(def, today, input.params[PERIOD_PARAM]),
  };
}
```

```ts
// apps/web/src/features/home/homeView.ts
import {
  type BudgetAdvice,
  type BudgetCardStatus,
  type BudgetTargetInput,
  type BudgetView,
  budgetAdvice,
  budgetCardStatus,
  budgetEventIds,
  budgetViews,
  featuredTarget,
  type GoalAdvice,
  type GoalCardStatus,
  type GoalTargetInput,
  type GoalView,
  goalAdvice,
  goalCardStatus,
  goalEventIds,
  goalViews,
  isUpcoming,
  type LocalDate,
  type PeriodDef,
  type PeriodSummary,
  type PeriodView,
  rankBudget,
  rankGoal,
  summarizePeriod,
  type Transaction,
  type TransactionKind,
  type TransactionRow,
  type TransactionRowDeps,
  transactionRow,
  type UserData,
  upcomingUntil,
} from '@saldo/core';

/** How many rows «In arrivo» and «Ultime transazioni» show before «Vedi tutte» (§6.2). */
export const HOME_ROWS = 5;

export interface HomeRow extends TransactionRow {
  id: string;
  date: LocalDate;
  /**
   * `transactionRow` returns title, subtitle, icon, colorIndex and amount — **no badge**: the phone's
   * screens add the ↻ themselves from `recurrenceId`. Both apps decide it the same way, so it is
   * carried here rather than recomputed in the page.
   */
  recurring: boolean;
}

/**
 * «In arrivo» (§6.1): the rows the card shows, and how many there are.
 *
 * The two travel together because they are not the same number past five rows, and a page reading
 * `rows.length` for the header would be quietly wrong exactly when the card matters most. `count`
 * is also what decides the card exists at all: the phone hides it at zero.
 */
export interface HomeUpcoming {
  rows: HomeRow[];
  /** Every row «In arrivo», not the five shown. */
  count: number;
}

export interface HomeBudgets {
  items: BudgetView[];
  featuredId: string | null;
  /** The budgets over their limit that are not the featured one: a row each (§5.13). */
  eventIds: string[];
  status: BudgetCardStatus;
  advice: BudgetAdvice | null;
}

export interface HomeGoals {
  items: GoalView[];
  featuredId: string | null;
  /** Expired then reached, the featured one excluded: a row each (§5.13). */
  eventIds: string[];
  status: GoalCardStatus;
  advice: GoalAdvice | null;
}

export interface HomeView {
  summary: PeriodSummary;
  upcoming: HomeUpcoming;
  /** «Ultime transazioni». No count beside it: its header says «Tutte le transazioni», not a number. */
  recent: HomeRow[];
  budgets: HomeBudgets;
  goals: HomeGoals;
}

export interface HomeViewInput {
  data: UserData;
  today: LocalDate;
  def: PeriodDef;
  period: PeriodView;
  /** `t('kinds.<kind>')`, injected so this stays pure; the page passes its translator. */
  kindLabel?: (kind: TransactionKind) => string;
}

/**
 * Home, as numbers (§6.2). Every figure comes from `@saldo/core`; nothing is computed here but the
 * slicing and the lookups, which is the point — if the phone and the web disagree, one of them is
 * not calling this.
 */
export function homeView({ data, today, def, period, kindLabel }: HomeViewInput): HomeView {
  const txs = data.transactions;
  const summary = summarizePeriod(txs, period.range, today);
  const upcomingEnd = upcomingUntil(def, period.range, today);

  const categories = new Map(data.categories.map((category) => [category.id, category]));
  const accounts = new Map(data.accounts.map((account) => [account.id, account]));
  const deps: TransactionRowDeps = {
    category: (id) => categories.get(id),
    accountName: (id) => accounts.get(id)?.name ?? '',
    kindLabel: kindLabel ?? ((kind) => kind),
    // Home is not about one account, so a transfer here carries no sign (§5.3).
    viewpointAccountId: null,
  };

  // The order the phone's query returns: date, then creation, then id, all descending.
  const byDateDesc = [...txs].sort(
    (a, b) =>
      b.date.localeCompare(a.date) ||
      b.createdAt.localeCompare(a.createdAt) ||
      b.id.localeCompare(a.id),
  );
  const row = (tx: Transaction): HomeRow => ({
    ...transactionRow(tx, deps),
    id: tx.id,
    date: tx.date,
    recurring: tx.recurrenceId !== null,
  });

  // «In arrivo» reaches into the next period while this one is current; everything else is
  // filtered by the period itself (§5.12, §6.15).
  const upcomingAll = byDateDesc.filter((tx) => isUpcoming(tx, today) && tx.date <= upcomingEnd);
  const recent = byDateDesc
    .filter((tx) => !isUpcoming(tx, today) && tx.date >= period.range.start)
    .slice(0, HOME_ROWS)
    .map(row);

  const budgetItems = budgetViews({
    budgets: data.budgets,
    categories: data.categories,
    transactions: txs,
    period: period.range,
    def,
    today,
  });
  const budgetInputs: BudgetTargetInput[] = budgetItems.map((view) => ({
    id: view.budget.id,
    progress: view,
    pace: view.pace,
  }));
  // `featuredTarget`'s second argument is the item featured last time, which the phone keeps
  // device-locally so the card does not change face at every transaction. The web has nowhere to
  // keep it in 0.3d and passes null: the hysteresis never applies, which is correct-but-jumpier,
  // and is the same answer on a page rendered once per request.
  const featuredBudgetId = featuredTarget(budgetInputs.map(rankBudget), null);
  const featuredBudget = budgetItems.find((view) => view.budget.id === featuredBudgetId);

  const goalItems = goalViews(data.accounts, txs, today, def);
  const goalInputs: GoalTargetInput[] = goalItems.map((view) => ({
    id: view.account.id,
    progress: view.progress,
  }));
  // Same `null`, same reason as the budgets above.
  const featuredGoalId = featuredTarget(goalInputs.map(rankGoal), null);
  const featuredGoal = goalItems.find((view) => view.account.id === featuredGoalId);

  return {
    summary,
    upcoming: { rows: upcomingAll.slice(0, HOME_ROWS).map(row), count: upcomingAll.length },
    recent,
    budgets: {
      items: budgetItems,
      featuredId: featuredBudgetId,
      eventIds: budgetEventIds(budgetInputs, featuredBudgetId),
      status: budgetCardStatus(budgetInputs),
      advice:
        featuredBudget === undefined
          ? null
          : // As on the phone: the budget's own range decides whether it is open, and `daysLeft`
            // excludes today while the advice spends today too.
            budgetAdvice(
              featuredBudget,
              featuredBudget.pace,
              featuredBudget.open,
              featuredBudget.daysLeft + 1,
            ),
    },
    goals: {
      items: goalItems,
      featuredId: featuredGoalId,
      eventIds: goalEventIds(goalInputs, featuredGoalId),
      status: goalCardStatus(goalInputs),
      advice: featuredGoal === undefined ? null : goalAdvice(featuredGoal.progress),
    },
  };
}
```

`featuredTarget`'s second argument is «the item featured last time», which the phone keeps device-locally so the card
does not change face at every transaction. The web has nowhere to keep it in 0.3d and passes `null`: the hysteresis
then never applies, which is correct-but-jumpier, and is the same answer on a page that is rendered once per request.
Said so in a comment at both call sites.

Three things the first draft of this task left out, and which Task 10 needs: `upcoming` is `{ rows, count }` because
the header shows every row «In arrivo», not the five it renders, and hides the card at zero; `budgets.eventIds` and
`goals.eventIds` come from `budgetEventIds`/`goalEventIds` so each card can show a row per exception between the
featured item and «Vedi tutte», as the phone does; and `goals.advice` comes from `goalAdvice`, so the two cards are
symmetric. `budgetAdvice` takes the **budget's** `open` and `daysLeft + 1`, not the period's `isCurrent` and
`daysLeft` — that is what the phone passes, and the two differ for any budget whose `period` is not `'period'`.

```ts
// apps/web/src/features/transactions/listParams.ts
import { EMPTY_FILTERS, type TransactionFilters } from '@saldo/core';

const DIRECTIONS = new Set<TransactionFilters['direction']>([
  'all',
  'expense',
  'income',
  'transfer',
]);

function direction(value: string | undefined): TransactionFilters['direction'] {
  return value !== undefined && DIRECTIONS.has(value as TransactionFilters['direction'])
    ? (value as TransactionFilters['direction'])
    : 'all';
}

/** The filters of §5.12, read out of a URL. Anything unreadable reads as «not filtered». */
export function filtersFromSearch(
  params: Record<string, string | undefined>,
): TransactionFilters {
  const tags = params.tag === undefined || params.tag === '' ? [] : params.tag.split(',');
  return {
    ...EMPTY_FILTERS,
    query: params.q ?? '',
    accountId: params.account ?? null,
    categoryId: params.category ?? null,
    direction: direction(params.direction),
    tagIds: tags,
    onlyExcluded: params.excluded === '1',
  };
}

/** The other way: only what is set, so an unfiltered list has a clean URL. */
export function searchFromFilters(filters: TransactionFilters): Record<string, string> {
  const out: Record<string, string> = {};
  if (filters.query !== '') out.q = filters.query;
  if (filters.accountId !== null) out.account = filters.accountId;
  if (filters.categoryId !== null) out.category = filters.categoryId;
  if (filters.direction !== 'all') out.direction = filters.direction;
  if (filters.tagIds.length > 0) out.tag = filters.tagIds.join(',');
  if (filters.onlyExcluded) out.excluded = '1';
  return out;
}

export interface Toggle {
  direction?: TransactionFilters['direction'];
  accountId?: string;
  tagId?: string;
  excluded?: boolean;
}

/**
 * Where a chip links: the same list with that one filter flipped. The selected row (`?t=`) is
 * dropped, because a row that does not match the new filters would leave the panel showing something
 * the list no longer holds; the period is kept, because it is not a filter.
 */
export function toggleHref(
  path: string,
  filters: TransactionFilters,
  toggle: Toggle,
  others: Record<string, string | undefined> = {},
): string {
  const next: TransactionFilters = { ...filters };
  if (toggle.direction !== undefined) {
    next.direction = filters.direction === toggle.direction ? 'all' : toggle.direction;
  }
  if (toggle.accountId !== undefined) {
    next.accountId = filters.accountId === toggle.accountId ? null : toggle.accountId;
  }
  if (toggle.tagId !== undefined) {
    next.tagIds = filters.tagIds.includes(toggle.tagId)
      ? filters.tagIds.filter((id) => id !== toggle.tagId)
      : [...filters.tagIds, toggle.tagId];
  }
  if (toggle.excluded !== undefined) next.onlyExcluded = toggle.excluded;

  const params = new URLSearchParams(searchFromFilters(next));
  if (others.p !== undefined) params.set('p', others.p);
  const query = params.toString();
  return query === '' ? path : `${path}?${query}`;
}
```

```ts
// apps/web/src/features/transactions/listView.ts
import {
  filterTransactions,
  groupByDay,
  hasActiveFilters,
  type LedgerTx,
  type ListTotals,
  type LocalDate,
  type PeriodDef,
  type PeriodView,
  splitUpcoming,
  totalsOf,
  type TransactionFilters,
  type TransactionRow,
  transactionRow,
  upcomingUntil,
  type UserData,
} from '@saldo/core';

export interface ListRowView extends TransactionRow {
  id: string;
  date: LocalDate;
  /** The ↻ badge: `transactionRow` does not return one, the screens read `recurrenceId` (§5.9). */
  recurring: boolean;
}

export interface DayView {
  date: LocalDate;
  /** Expenses only, excluded rows left out — the phone's day header (§5.12). */
  expenseTotal: number;
  rows: ListRowView[];
}

export interface ListView {
  days: DayView[];
  upcomingDays: DayView[];
  upcoming: { count: number; net: number };
  totals: ListTotals;
  filtered: boolean;
}

interface Input {
  data: UserData;
  filters: TransactionFilters;
  today: LocalDate;
  def: PeriodDef;
  period: PeriodView;
  kindLabel?: (kind: 'expense' | 'income' | 'transfer') => string;
}

/**
 * The list of §5.12: the period's rows, filtered by core, split into what has happened and what is
 * dated ahead, then grouped by day. The rows are `transactionRow`'s, so the phone and the web title
 * and colour a transfer, a recurrence and an excluded row identically.
 */
export function listView({ data, filters, today, def, period, kindLabel }: Input): ListView {
  const end = upcomingUntil(def, period.range, today);
  const inRange = (data.transactions as unknown as LedgerTx[])
    .filter((tx) => tx.date >= period.range.start && tx.date <= end)
    .sort((a, b) => (a.date === b.date ? b.id.localeCompare(a.id) : b.date.localeCompare(a.date)));

  const categories = new Map(data.categories.map((category) => [category.id, category]));
  const accounts = new Map(data.accounts.map((account) => [account.id, account]));
  const lookup = {
    accountName: (id: string) => accounts.get(id)?.name ?? '',
    categoryName: (id: string) => categories.get(id)?.name ?? '',
    categoryParentId: (id: string) => categories.get(id)?.parentId ?? null,
  };
  const filteredTxs = filterTransactions(inRange, filters, lookup);
  const split = splitUpcoming(filteredTxs, today);

  const deps = {
    category: (id: string) => {
      const found = categories.get(id);
      return found === undefined
        ? undefined
        : { name: found.name, icon: found.icon, colorIndex: found.colorIndex };
    },
    accountName: lookup.accountName,
    kindLabel: kindLabel ?? ((kind: string) => kind),
    viewpointAccountId: filters.accountId,
  };
  const toDays = (txs: LedgerTx[]): DayView[] =>
    groupByDay(txs).map((group) => ({
      date: group.date,
      expenseTotal: group.expenseTotal,
      rows: group.items.map((tx) => ({
        ...transactionRow(tx, deps),
        id: tx.id,
        date: tx.date,
        recurring: tx.recurrenceId !== null,
      })),
    }));

  return {
    days: toDays(split.settled),
    upcomingDays: toDays(split.upcoming),
    upcoming: { count: split.upcoming.length, net: split.upcomingNet },
    totals: totalsOf(split.settled),
    filtered: hasActiveFilters(filters),
  };
}
```

```ts
// apps/web/src/features/transactions/detailView.ts
import { isUpcoming, type LedgerTx, type LocalDate, type UserData } from '@saldo/core';

export interface DetailFact {
  kind: 'account' | 'category' | 'from' | 'to' | 'date' | 'tags' | 'note';
  label: string;
  /** Where the fact leads, when it leads anywhere: an account, and nothing else in 0.3d. */
  href: string | null;
}

export interface DetailView {
  id: string;
  kind: LedgerTx['kind'];
  amount: number;
  date: LocalDate;
  title: string;
  facts: DetailFact[];
  tagNames: string[];
  /** The recurrence this row is an occurrence of; shown, never edited (§17.1.9). */
  recurrenceId: string | null;
  attachmentCount: number;
  excluded: boolean;
  upcoming: boolean;
}

/**
 * The trailing panel of §17.1.7. It reads the projection it is given — no second load — and returns
 * `null` for an id that is not there, which is what a stale `?t=` in a shared link looks like.
 */
export function detailView(input: {
  data: UserData;
  id: string;
  today: LocalDate;
}): DetailView | null {
  const tx = input.data.transactions.find((row) => row.id === input.id);
  if (tx === undefined) return null;
  const accounts = new Map(input.data.accounts.map((account) => [account.id, account]));
  const categories = new Map(input.data.categories.map((category) => [category.id, category]));
  const tags = new Map(input.data.tags.map((tag) => [tag.id, tag]));

  const accountFact = (kind: DetailFact['kind'], id: string | null): DetailFact | null =>
    id === null
      ? null
      : { kind, label: accounts.get(id)?.name ?? '', href: `/accounts?a=${id}` };

  const facts: DetailFact[] =
    tx.kind === 'transfer'
      ? ([accountFact('from', tx.accountId), accountFact('to', tx.toAccountId)].filter(
          (fact): fact is DetailFact => fact !== null,
        ) as DetailFact[])
      : ([
          accountFact('account', tx.accountId),
          tx.categoryId === null
            ? null
            : { kind: 'category' as const, label: categories.get(tx.categoryId)?.name ?? '', href: null },
        ].filter((fact): fact is DetailFact => fact !== null) as DetailFact[]);
  facts.push({ kind: 'date', label: tx.date, href: null });

  return {
    id: tx.id,
    kind: tx.kind,
    amount: tx.amount,
    date: tx.date,
    title: tx.description ?? categories.get(tx.categoryId ?? '')?.name ?? '',
    facts,
    tagNames: tx.tagIds.map((id) => tags.get(id)?.name ?? '').filter((name) => name !== ''),
    recurrenceId: tx.recurrenceId,
    attachmentCount: tx.attachmentIds?.length ?? 0,
    excluded: tx.excludeFromTotals,
    upcoming: isUpcoming(tx, input.today),
  };
}
```

The `date` fact carries the raw `LocalDate`; the panel formats it with `formatLongDate(fact.label, locale)`. Keeping
the value unformatted is what lets this stay pure and testable.

```tsx
'use client';

import { useRouter } from 'next/navigation';
import { useState } from 'react';
import { TextField } from './TextField';

interface Props {
  value: string;
  /** The URL to go to, with `{q}` where the query belongs. */
  template: string;
  label: string;
  placeholder: string;
}

/**
 * The one field on this page that must be heard as it is typed. It navigates on submit rather than on
 * every keystroke: a Server Component page re-renders on navigation, and a request per character
 * would re-read the whole projection each time.
 */
export function SearchField({ value, template, label, placeholder }: Props) {
  const router = useRouter();
  const [text, setText] = useState(value);
  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        router.push(template.replace('{q}', encodeURIComponent(text.trim())));
      }}
      role="search"
    >
      <TextField
        label={label}
        placeholder={placeholder}
        value={text}
        onChange={(event) => setText(event.target.value)}
        type="search"
        autoComplete="off"
      />
    </form>
  );
}
```

```ts
// apps/web/src/features/stats/navigatorView.ts
import {
  accountBalances,
  type CashflowValues,
  type DateRange,
  forecastPeriods,
  type LedgerTx,
  type LocalDate,
  netWorth,
  type PeriodDef,
  previousPeriods,
  shiftPeriod,
  summarizePeriod,
  type UserData,
} from '@saldo/core';

/**
 * §17.1.7: six closed periods on the web, where the phone shows three — D29 kept six columns because
 * of 320px, and the desktop has the room for ten.
 */
export const WEB_CLOSED_COLUMNS = 6;

export interface NavigatorColumn {
  range: DateRange;
  kind: 'closed' | 'current' | 'forecast';
  selected: boolean;
  values: CashflowValues;
}

export interface NavigatorView {
  columns: NavigatorColumn[];
  selected: NavigatorColumn | null;
}

/**
 * The chart that is also the period picker. Every column carries the values `cashflowColumns` needs,
 * so the renderer stays geometry-only, and the three forecast ones carry the band `forecastPeriods`
 * computed — or nothing, when there is too little history for one (`forecastPeriods` answers null).
 */
export function navigatorView(input: {
  data: UserData;
  def: PeriodDef;
  today: LocalDate;
  selected: DateRange;
}): NavigatorView {
  const { data, def, today } = input;
  const txs = data.transactions as unknown as LedgerTx[];
  const current = previousPeriods(def, shiftPeriod(def, input.selected, 0), 0).at(0) ?? input.selected;
  void current;

  const currentRange = periodOfToday(def, today);
  const closed = previousPeriods(def, currentRange, WEB_CLOSED_COLUMNS);
  const forecast = forecastPeriods({
    txs,
    recurrences: data.recurrences,
    def,
    period: currentRange,
    today,
    balance: netWorth(data.accounts, accountBalances(data.accounts, txs, today)),
  });

  const columns: NavigatorColumn[] = [];
  for (const range of [...closed].reverse()) {
    const summary = summarizePeriod(txs, range, today);
    columns.push({
      range,
      kind: 'closed',
      selected: range.start === input.selected.start,
      values: { income: summary.income, expenses: summary.spent },
    });
  }
  const summary = summarizePeriod(txs, currentRange, today);
  columns.push({
    range: currentRange,
    kind: 'current',
    selected: currentRange.start === input.selected.start,
    values: { income: summary.income, expenses: summary.spent },
  });
  for (let ahead = 1; ahead <= 3; ahead += 1) {
    const range = shiftPeriod(def, currentRange, ahead);
    const period = forecast?.[ahead - 1];
    columns.push({
      range,
      kind: 'forecast',
      selected: range.start === input.selected.start,
      values:
        period === undefined
          ? { income: 0, expenses: 0 }
          : {
              income: period.income,
              expenses: period.expenses,
              forecast: { min: period.expensesMin, max: period.expensesMax },
            },
    });
  }
  return { columns, selected: columns.find((column) => column.selected) ?? null };
}

function periodOfToday(def: PeriodDef, today: LocalDate): DateRange {
  const [range] = previousPeriods(def, shiftPeriod(def, { start: today, end: today }, 0), 1);
  return range ?? { start: today, end: today };
}
```

```ts
// apps/web/src/features/stats/statsView.ts
import {
  averageSeries,
  categorySpendHistory,
  committedSpend,
  dailyCumulative,
  deltaPercent,
  isWithin,
  type LedgerTx,
  type LocalDate,
  median,
  type PeriodDef,
  periodHistory,
  periodSpendHistory,
  type PeriodView,
  projectEndOfCycle,
  rollupToParents,
  spendingByCategory,
  summarizePeriod,
  tagTotals,
  type TagTotals,
  upcomingExpenses,
  type UserData,
} from '@saldo/core';

/** The phone's constants, kept identical so both read the same history (§5.16). */
const USUAL_PERIODS = 3;
const HISTORY_PERIODS = 6;
const MIN_DAYS_LEFT = 3;

export interface StatsFigures {
  kind: 'current' | 'closed';
  income: number;
  spent: number;
  net: number;
  /** A running period only: where it ends up if it carries on (§5.16). */
  projection: number | null;
  /** A closed period only: what was already committed of what was spent. */
  committed: number | null;
  committedShare: number;
}

export interface SplitRow {
  categoryId: string;
  amount: number;
  share: number;
  /** Against the median of the same category over the last six periods; `null` with no baseline. */
  delta: number | null;
}

export interface StatsView {
  figures: StatsFigures;
  split: { total: number; rows: SplitRow[]; excludedCount: number };
  tags: TagTotals;
  trend: { current: number[]; usual: number[]; median: number | null };
}

export function statsView(input: {
  data: UserData;
  def: PeriodDef;
  today: LocalDate;
  period: PeriodView;
  direction: 'expense' | 'income';
}): StatsView {
  const { data, def, today, period, direction } = input;
  const txs = data.transactions as unknown as LedgerTx[];
  const summary = summarizePeriod(txs, period.range, today);
  const committed = committedSpend(txs, period.range, today);
  const daysLeft = Math.max(0, period.length - period.elapsed);
  const history = periodHistory(txs, def, period.range, HISTORY_PERIODS);
  const cycleMedian = median(periodSpendHistory(history, today));

  const amounts = rollupToParents(
    spendingByCategory(txs, period.range, today, direction),
    data.categories,
  );
  const total = [...amounts.values()].reduce((sum, value) => sum + value, 0);
  const pastByCategory = categorySpendHistory(history, data.categories, today);
  const rows: SplitRow[] = [...amounts.entries()]
    .map(([categoryId, amount]) => ({
      categoryId,
      amount,
      share: total === 0 ? 0 : Math.round((amount / total) * 100),
      delta: deltaPercent(
        amount,
        median(pastByCategory.map((entry) => entry.get(categoryId) ?? 0)),
      ),
    }))
    .sort((a, b) => b.amount - a.amount);

  const usualHistory = periodHistory(txs, def, period.range, USUAL_PERIODS);
  const current = dailyCumulative(txs, period.range, today);

  return {
    figures: {
      kind: period.isCurrent ? 'current' : 'closed',
      income: summary.income,
      spent: summary.spent,
      net: summary.income - summary.spent,
      projection:
        period.isCurrent && daysLeft >= MIN_DAYS_LEFT && cycleMedian !== null
          ? projectEndOfCycle({
              spent: summary.spent,
              committed,
              elapsed: period.elapsed,
              length: period.length,
              upcoming: upcomingExpenses(txs, period.range, today),
            })
          : null,
      committed: period.isCurrent ? null : committed,
      committedShare: summary.spent === 0 ? 0 : Math.round((committed / summary.spent) * 100),
    },
    split: {
      total,
      rows,
      excludedCount: txs.filter(
        (tx) =>
          tx.excludeFromTotals &&
          tx.kind === direction &&
          isWithin(period.range, tx.date) &&
          tx.date <= today,
      ).length,
    },
    tags: tagTotals(txs, period.range, today),
    trend: {
      current,
      usual: averageSeries(
        usualHistory.map((entry) => dailyCumulative(entry.txs, entry.period, today)),
        Math.max(1, current.length),
      ),
      median: cycleMedian,
    },
  };
}
```

```ts
// apps/web/src/features/accounts/accountsView.ts
import {
  type Account,
  accountBalances,
  bankBalance,
  isPocket,
  type LedgerTx,
  type LocalDate,
  netWorth,
  type PeriodDef,
  pocketsOf,
  spendableTotal,
  type UserData,
} from '@saldo/core';

/** The phone's rule: only these two types are «Risparmi e investimenti» (§6.6). */
const SAVINGS_TYPES = new Set<Account['type']>(['savings', 'investment']);

export interface PocketView {
  account: Account;
  saved: number;
  target: number;
  ratio: number;
}

export interface AccountRowView {
  account: Account;
  /** The account and its open pockets together, which is what the phone's row shows. */
  balance: number;
  /** The account's own money, under the pockets: «libero». */
  free: number;
  pockets: PocketView[];
}

export interface AccountsView {
  netWorth: number;
  spendable: number;
  spending: AccountRowView[];
  savings: AccountRowView[];
  archivedCount: number;
}

export function accountsView(input: {
  data: UserData;
  today: LocalDate;
  def: PeriodDef;
}): AccountsView {
  const { data, today } = input;
  const txs = data.transactions as unknown as LedgerTx[];
  const balances = accountBalances(data.accounts, txs, today);

  const live = data.accounts.filter(
    (account) => account.archivedAt === null && !isPocket(account),
  );
  const row = (account: Account): AccountRowView => ({
    account,
    balance: bankBalance(data.accounts, balances, account.id),
    free: balances.get(account.id) ?? 0,
    pockets: pocketsOf(data.accounts, account.id).map((pocket) => {
      const saved = balances.get(pocket.id) ?? 0;
      const target = pocket.goalTarget ?? 0;
      return { account: pocket, saved, target, ratio: saved / Math.max(1, target) };
    }),
  });

  return {
    netWorth: netWorth(data.accounts, balances),
    spendable: spendableTotal(data.accounts, balances),
    // The phone's order inside the first group: the spendable ones, then the rest.
    spending: [
      ...live.filter((a) => !SAVINGS_TYPES.has(a.type) && a.includeInSpendable),
      ...live.filter((a) => !SAVINGS_TYPES.has(a.type) && !a.includeInSpendable),
    ].map(row),
    savings: live.filter((account) => SAVINGS_TYPES.has(account.type)).map(row),
    archivedCount: data.accounts.filter(
      (account) => account.archivedAt !== null && !isPocket(account),
    ).length,
  };
}
```

```ts
// apps/web/src/features/accounts/detailView.ts
import {
  type Account,
  accountBalances,
  bankBalance,
  creditCardDue,
  type CreditStatement,
  creditStatementAccrued,
  creditStatementDue,
  type GoalProgress,
  goalProgress,
  isPocket,
  type LedgerTx,
  type LocalDate,
  monthEndBalances,
  type PeriodDef,
  periodContaining,
  summarizePeriod,
  type UserData,
} from '@saldo/core';

/** The phone's sparkline window (§6.7). */
const SPARK_MONTHS = 8;

export interface AccountDetailView {
  account: Account;
  balance: number;
  free: number;
  series: number[];
  /** A credit card only: what is owed today, and the statement it comes from. */
  due: number | null;
  accrued: number | null;
  statement: CreditStatement | null;
  /** A pocket only. */
  goal: GoalProgress | null;
  period: { income: number; spent: number };
}

export function accountDetail(input: {
  data: UserData;
  id: string;
  today: LocalDate;
  def: PeriodDef;
}): AccountDetailView | null {
  const { data, id, today, def } = input;
  const account = data.accounts.find((row) => row.id === id);
  if (account === undefined) return null;
  const txs = data.transactions as unknown as LedgerTx[];
  const balances = accountBalances(data.accounts, txs, today);
  const own = balances.get(account.id) ?? 0;
  const range = periodContaining(def, today);
  const mine = txs.filter((tx) => tx.accountId === account.id || tx.toAccountId === account.id);
  const summary = summarizePeriod(mine, range, today);

  const card =
    account.type === 'credit_card'
      ? {
          due: creditCardDue(own),
          accrued:
            account.creditCloseDay === null
              ? null
              : creditStatementAccrued(account.id, account.creditCloseDay, txs, today),
          statement: creditStatementDue(account, txs, today),
        }
      : { due: null, accrued: null, statement: null };

  return {
    account,
    balance: bankBalance(data.accounts, balances, account.id),
    free: own,
    series: monthEndBalances({
      accountId: account.id,
      openingBalance: account.openingBalance,
      txs,
      today,
      months: SPARK_MONTHS,
    }),
    ...card,
    goal:
      isPocket(account) && account.goalTarget !== null && account.goalStartDate !== null
        ? goalProgress(
            {
              id: account.id,
              openingBalance: account.openingBalance,
              goalTarget: account.goalTarget,
              goalDeadline: account.goalDeadline,
              goalStartDate: account.goalStartDate,
            },
            txs,
            today,
            def,
          )
        : null,
    period: { income: summary.income, spent: summary.spent },
  };
}
```

```ts
// apps/web/src/features/profile/profileRows.ts
import { getCurrency, type Settings } from '@saldo/core';
import { type AppLocale, canonicalTimeZone, LANGUAGE_NAMES, timeZoneCity } from '@saldo/i18n';

export interface PreferenceRow {
  key: 'cycle' | 'currency' | 'language' | 'theme' | 'timeZone';
  /** A dotted i18n path for the label; the page resolves it. */
  labelKey: string;
  /** Already-resolved value where it is a name or a symbol; a raw number where the page formats it. */
  value: string;
  /** False in 0.3d: the settings form is 0.3e. The row still shows what is set. */
  editable: false;
}

/**
 * Profilo's preferences (§6.28): the same five rows as the phone, reading the same synced `settings`,
 * so a change made on the phone is what the web shows on its next request.
 */
export function preferenceRows(settings: Settings, locale: AppLocale): PreferenceRow[] {
  const zone = canonicalTimeZone(settings.timeZone ?? 'UTC');
  return [
    {
      key: 'cycle',
      labelKey: 'profile.cycleStart',
      value: String(settings.cycleStartDay),
      editable: false,
    },
    {
      key: 'currency',
      labelKey: 'profile.currency',
      value: `${getCurrency(settings.currency).symbol} ${settings.currency}`,
      editable: false,
    },
    {
      key: 'language',
      labelKey: 'profile.language',
      value: settings.language === 'system' ? '' : LANGUAGE_NAMES[settings.language],
      editable: false,
    },
    { key: 'theme', labelKey: 'profile.theme', value: settings.theme, editable: false },
    {
      key: 'timeZone',
      labelKey: 'profile.timeZone',
      value: timeZoneCity(zone, locale),
      editable: false,
    },
  ];
}
```

The `language: 'system'` and `theme` values are i18n keys rather than names (`profile.system`, `profile.dark`,
`profile.light`); the page resolves them, so this stays free of a translator. Say so in a comment.
