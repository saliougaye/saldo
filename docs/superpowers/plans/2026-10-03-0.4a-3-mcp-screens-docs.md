# 0.4a-3 — «Connettori», `/oauth/consent`, `/admin/mcp`, strings and docs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The three MCP screens of spec §17.4.3 exist on the chosen variants — Profilo › Connettori (`/profile/connectors`), the consent page (`/oauth/consent`) and Admin › MCP (`/admin/mcp`) — with their empty, filled, switched-off, locked, refused and invalid states, every string in the seven locales, and the docs of §17.4.4 (`SECURITY.md` «MCP e connettori», `docs/self-hosting.md` «Collegare un client MCP»).

## Decisions (recorded here, as the roadmap asks)

1. **No component tests.** `apps/web/vitest.config.mts` runs `node` and only `*.test.ts`; every earlier web screen is tested through its pure view model. This plan does the same: `connectorsView`, `consentView`, `mcpView`, the icon set and the i18n parity are tested; pages and client components are covered by typecheck, lint and the manual check (Task 12).
2. **Profilo entry «Connettori» after Passkey** (spec), not at the end of the list as the mockup's `PROFILE_ITEMS` draws it — the spec wins (AGENTS.md). Icon `plug`.
3. **The client tile is the client's initial**, on rows, panel and consent card alike. The mockup guessed a `terminal`/`bot` icon from the name; a self-registered name says nothing reliable about the kind of client, and the consent card already uses the initial.
4. **Phone width.** The web shell already handles it: below 1024px the sub-navigation wraps above the section and `Panel` (not `sheet`) covers the screen. The selected connector's panel is that full screen — `bare`, with the tile and the client's name as its heading — which is the «pushed screen titled with the client's name» of §17.4.3. No new push header.
5. **«Ultimo uso»** reads «usato oggi» / «usato ieri» / «usato il 28 set» / «mai usato» on a row (the user's zone, `wallClock`), and «oggi» / «ieri» / the long date / «mai» in the panel. The web has no relative-time formatter and «2 min fa» would go stale on a page that is not re-rendered.
6. **«Chiamate»** is `plural(…'web.connectors.calls'…)`: «148 chiamate dal 3 ottobre 2026», the date being the authorization's (the count of `mcp_usage` starts with the consent).
7. **The «MCP switched off» notice** has three bodies: a member (`offBody`), an admin (`offAdminBody`, «L'hai spento tu in Admin › MCP», as the spec says) and an admin on an instance where `MCP_ENABLED=false` locks it (`offAdminEnvBody`, which names the variable — «you switched it off» would be untrue). Each ends «I connettori già autorizzati restano in lista e riprendono quando…». The two admin bodies carry the link to `/admin/mcp`. The notice is an `Alert` with `quiet` (no `role="alert"`: it is there on load, not in answer to an action).
8. **«Collega» tabs** reuse `Segmented` (a radio group: one tab stop, arrows). The Claude Code line and the `mcp-remote` line are `CopyField`s, like the endpoint, so each has its own «Copia».
9. **Consent and signing in (0.4a-2 decision 10).** The plugin sends a browser with no session to `/login?{signed query}`, and `/login` resumes through the authorize endpoint (`oauthResumePath`, already in place) — which keeps the plugin's «remembered consent». This plan does not touch `/login`. Should `/oauth/consent` see a signed-out visitor (session lost between redirects), it redirects to `/login?{the same signed query}` and that resume takes over. When MCP is off the page says so **before** asking anyone to sign in.
10. **Consent answers** go through `submitConsentAction`, which returns `{ ok: true, redirectTo }`; the client component navigates with `window.location.assign(redirectTo)` — the authorize endpoint (which issues the code and redirects to the client), the client's own redirect URI with `access_denied`, or the consent page again (which then shows why). On «Nega» the page shows «Accesso negato» while the browser leaves for the client; it stays on screen only if that navigation does not replace the page. The mockup's «Accesso negato … il client è stato avvisato» is therefore true: the redirect *is* the notice.
11. **Scopes on consent** are native checkboxes in `<label>` rows (no `role="checkbox"` on a `div`): «Leggere i tuoi dati» checked and disabled with «richiesto»; «Aggiungere e modificare» only when `write` was requested, ticked by default; unticked, the primary button reads «Autorizza solo la lettura». `read` is always sent; `parseChosenScopes` refuses a list without it. `offline_access` (refresh tokens, 0.4a-2 decision 3) is never shown: `submitConsent` grants it whenever it was requested.
12. **«Non sei tu?»** is `SignOutButton` (row variant) with a new `redirectTo` prop: sign out, then `/login?{the same signed query}`, so signing in as the right person resumes the same request.
13. **Admin switch** saves as it is flipped (no «Salva», variant C). Switching **on** writes at once; switching **off** shows the inline confirmation with the counts and writes on «Spegni». Locked: a line «Impostato dall'ambiente: `MCP_ENABLED=false`» with the lock icon, and the switch disabled (`Switch` gains `disabled`). The off sentence is pluralised on users and nests the pluralised connectors: «3 utenti hanno 5 connettori autorizzati: smetteranno di rispondere alla prossima chiamata. Le autorizzazioni restano e riprendono quando lo riaccendi.»; none authorized → «In questo momento nessun connettore è autorizzato: non si ferma niente.»
14. **The three numbers** — «Utenti con connettori» (su N), «Connettori autorizzati», «Usati negli ultimi 7 giorni» — are plain integers (household-sized counts). Aggregates only (§17.4.3).
15. **«Cosa dare a un client»**: the endpoint (`CopyField`), a line «I client scoprono il resto da soli, da questi due documenti…» with `/.well-known/oauth-protected-resource` and `/.well-known/oauth-authorization-server` as `<code>` (both served by 0.4a-2, with their path-aware twins), and the HTTPS note. When `PUBLIC_URL` is plain `http` on a host that is not loopback, an extra `Alert` says the clients will refuse it (cheap, and it is the misconfiguration the docs warn about).
16. **Two icons added**, Lucide 1.47.0 `copy` and `lock`, the way `server` was added (`packages/ui/src/icons.ts`, covered by the existing THIRD-PARTY note for that block). `plug`, `eye`, `pencil`, `check`, `info`, `x`, `chevR` already exist.
17. **Docs headings**: the two docs are English; the sections are titled with the Italian names and an English gloss — `## MCP e connettori (MCP and connectors)` and `## Collegare un client MCP (connecting an MCP client)` — so a search for either finds them.
18. **Not here:** `/login` and its resume (0.4a-2); the ROADMAP «0.4a done» line (whoever closes 0.4a writes it once); write tools (0.4b).

Create `apps/web/src/ui/CopyField.tsx`:

```tsx
'use client';

import { useEffect, useRef, useState } from 'react';
import styles from './CopyField.module.css';
import { Icon } from './Icon';
import { VisuallyHidden } from './VisuallyHidden';

/** How long «Copiato» stays before the button says «Copia» again (as `MintInvite`). */
const COPIED_MS = 2000;

interface Props {
  /** What is copied, shown as it is: an address, a command line. */
  value: string;
  copyLabel: string;
  copiedLabel: string;
}

/**
 * Something to give to another program — the MCP endpoint, the `claude mcp add` line — in monospace,
 * selectable by hand, with «Copia» beside it. A clipboard refused by the browser changes nothing:
 * the value is still there to select.
 */
export function CopyField({ value, copyLabel, copiedLabel }: Props) {
  const [copied, setCopied] = useState(false);
  const timer = useRef<ReturnType<typeof setTimeout>>(undefined);
  useEffect(() => () => clearTimeout(timer.current), []);

  const copy = async () => {
    try {
      await navigator.clipboard.writeText(value);
    } catch {
      return;
    }
    setCopied(true);
    clearTimeout(timer.current);
    timer.current = setTimeout(() => setCopied(false), COPIED_MS);
  };

  return (
    <div className={styles.field}>
      <code className={styles.value}>{value}</code>
      <button type="button" className={styles.copy} onClick={() => void copy()}>
        <Icon name={copied ? 'check' : 'copy'} size={16} />
        {copied ? copiedLabel : copyLabel}
      </button>
      <span role="status">
        <VisuallyHidden>{copied ? copiedLabel : ''}</VisuallyHidden>
      </span>
    </div>
  );
}
```

```ts
 */
export function lastUsed(at: Date | null, now: Date, timeZone: string): LastUsed {
```

```ts
import type { ConsentRequest } from '../../server/mcp/consent';

// `/oauth/consent` (§17.4.1, §17.4.3, variant C). Imports types only, so the consent form — a client
// component — can use it. Rebuilding the signed query is 0.4a-2's `consentSearchParams`.

/**
 * Not signed in (a session lost between redirects): `/login` with the same signed query, which
 * `/login` verifies and resumes through the authorize endpoint (0.4a-2 decision 10). No `next`.
 */
export function loginRedirect(query: string): string {
  return `/login?${query}`;
}

/** «Aggiungere e modificare» is a row only when the client asked for `write`. */
export function offersWrite(requested: readonly ToolScope[]): boolean {
  return requested.includes('write');
}

/**
 * What the user chose, as `submitConsent` takes it: `read` always («richiesto»), `write` when asked
 * and left ticked. `offline_access` is not a choice: `submitConsent` adds it when it was requested.
 */
export function chosenScopes(requested: readonly ToolScope[], writeTicked: boolean): ToolScope[] {
  return offersWrite(requested) && writeTicked ? ['read', 'write'] : ['read'];
}

/** The primary button reads «Autorizza solo la lettura» once `write` is unticked. */
export function authorizeReadOnly(requested: readonly ToolScope[], writeTicked: boolean): boolean {
  return offersWrite(requested) && !writeTicked;
}

/** Under the client's name on its card, after «torna a {host}». */
export type ClientNote =
  | { key: 'web.consent.registeredNow' }
  | { key: 'web.consent.authorizedBefore'; dateIso: string };

export function clientNote(
  request: Pick<ConsentRequest, 'fresh' | 'previouslyAuthorizedAt'>,
): ClientNote | null {
  if (request.fresh) return { key: 'web.consent.registeredNow' };
  if (request.previouslyAuthorizedAt !== null) {
    return {
      key: 'web.consent.authorizedBefore',
      dateIso: request.previouslyAuthorizedAt.toISOString(),
    };
  }
  return null;
}

const SCOPES: readonly ToolScope[] = ['read', 'write'];

/**
 * What the browser sent as the chosen scopes, checked: each a known scope, once, `read` among
 * them, returned read-first. Anything else is `null` and the action answers no.
 */
export function parseChosenScopes(raw: unknown): ToolScope[] | null {
  if (!Array.isArray(raw)) return null;
  const seen = new Set<ToolScope>();
  for (const value of raw as unknown[]) {
    const scope = SCOPES.find((candidate) => candidate === value);
    if (scope === undefined || seen.has(scope)) return null;
    seen.add(scope);
  }
  if (!seen.has('read')) return null;
  return SCOPES.filter((scope) => seen.has(scope));
}
```

`apps/web/app/(app)/profile/connectors/actions.ts`:

```ts
'use server';

import { revalidatePath } from 'next/cache';
import { requireWebUser } from '../../../../src/server/auth/currentUser';
import { log, shortId } from '../../../../src/server/log';
import { revokeConnector } from '../../../../src/server/mcp/connectors';

export type RevokeConnectorResult = { ok: true } | { ok: false };

/** Longer than any id the provider mints; anything longer is not one of ours. */
const MAX_CLIENT_ID_LENGTH = 255;

/**
 * §17.4.1: revoking deletes the consent and every token of this user–client pair; the client's next
 * call is a 401. `revokeConnector` scopes by the signed-in user, so an id from elsewhere revokes
 * nothing of anybody else's.
 */
export async function revokeConnectorAction(clientId: unknown): Promise<RevokeConnectorResult> {
  const user = await requireWebUser();
  if (
    typeof clientId !== 'string' ||
    clientId.length === 0 ||
    clientId.length > MAX_CLIENT_ID_LENGTH
  ) {
    return { ok: false };
  }
  try {
    await revokeConnector(user.id, clientId);
  } catch (error) {
    log('mcp', 'revoking a connector failed', {
      user: shortId(user.id),
      error: error instanceof Error ? error.name : 'unknown',
    });
    return { ok: false };
  }
  revalidatePath('/profile/connectors');
  return { ok: true };
}
```

```tsx
'use client';

import { useRouter } from 'next/navigation';
import { useState, useTransition } from 'react';
import { Alert } from '../../../../src/ui/Alert';
import { Button } from '../../../../src/ui/Button';
import { type RevokeConnectorResult, revokeConnectorAction } from './actions';
import styles from './connectors.module.css';

interface Props {
  clientId: string;
  /** The list without a selection: where the page goes once the connector is gone. */
  closeHref: string;
  strings: {
    revoke: string;
    title: string;
    body: string;
    confirm: string;
    cancel: string;
    busy: string;
    failed: string;
  };
}

/**
 * «Revoca accesso» at the foot of the panel, with the inline confirmation of §17.4.3 («Revocare
 * {client}? Smetterà di funzionare alla prossima chiamata») rather than a dialog: the panel is
 * already the place of this one connector.
 */
export function RevokeConnector({ clientId, closeHref, strings }: Props) {
  const router = useRouter();
  const [confirming, setConfirming] = useState(false);
  const [failed, setFailed] = useState(false);
  const [pending, startTransition] = useTransition();

  const revoke = () => {
    if (pending) return;
    setFailed(false);
    startTransition(async () => {
      let result: RevokeConnectorResult;
      try {
        result = await revokeConnectorAction(clientId);
      } catch {
        result = { ok: false };
      }
      if (!result.ok) {
        setFailed(true);
        return;
      }
      router.replace(closeHref);
    });
  };

  if (!confirming) {
    return (
      <div className={styles.panelActions}>
        <Button variant="secondary" icon="trash" onClick={() => setConfirming(true)}>
          {strings.revoke}
        </Button>
      </div>
    );
  }

  return (
    <div className={styles.confirm}>
      <Alert title={strings.title} body={strings.body} />
      <div className={styles.panelActions}>
        <Button variant="secondary" disabled={pending} onClick={() => setConfirming(false)}>
          {strings.cancel}
        </Button>
        <Button variant="secondary" busy={pending} busyLabel={strings.busy} onClick={revoke}>
          {strings.confirm}
        </Button>
      </div>
      {failed ? (
        <p className={styles.hint} role="alert">
          {strings.failed}
        </p>
      ) : null}
    </div>
  );
}
```

```ts
'use server';

import { parseChosenScopes } from '../../../../src/features/consent/consentView';
import { currentUser } from '../../../../src/server/auth/currentUser';
import { log, shortId } from '../../../../src/server/log';
import { submitConsent } from '../../../../src/server/mcp/consent';

export type ConsentActionResult = { ok: true; redirectTo: string } | { ok: false };

/**
 * «Autorizza» / «Nega» (§17.4.1). Thin: the session, the browser's input checked, then
 * `submitConsent`, which verifies the signed query again and answers with where to go — the
 * authorize endpoint (which issues the code), the client's redirect with `access_denied`, or this
 * page again when the query no longer holds. The browser goes there itself (Decision 10).
 */
export async function submitConsentAction(
  query: unknown,
  accept: unknown,
  scopes: unknown,
): Promise<ConsentActionResult> {
  const user = await currentUser();
  if (user === null || typeof query !== 'string' || typeof accept !== 'boolean') {
    return { ok: false };
  }
  const chosen = accept ? parseChosenScopes(scopes) : [];
  if (chosen === null) return { ok: false };
  try {
    const { redirectTo } = await submitConsent({
      searchParams: new URLSearchParams(query),
      userId: user.id,
      accept,
      scopes: chosen,
    });
    return { ok: true, redirectTo };
  } catch (error) {
    log('mcp', 'a consent answer failed', {
      user: shortId(user.id),
      error: error instanceof Error ? error.name : 'unknown',
    });
```

````markdown
## MCP e connettori (MCP and connectors)

From 0.4 an instance serves a [Model Context Protocol](https://modelcontextprotocol.io) endpoint at
`{PUBLIC_URL}/mcp`, so an MCP client a user already runs (Claude Code, Claude's custom connectors, any MCP client)
reads — and, if allowed, changes — that user's data. What bounds it:

- **The only credential is an OAuth 2.1 token the user granted.** Saldo is its own authorization server (endpoints
  under `/api/auth/oauth2/*`, issuer `{PUBLIC_URL}/api/auth`). The client registers itself (public clients only, PKCE
  S256, `https://` or loopback redirect URIs, exact match, one registration a minute per IP) and sends the user's
  browser to sign in with their passkey and to `/oauth/consent`, where they choose what the client may do. Nothing is
  pasted, nothing is shared out of band, and there are no personal access tokens. A registration on its own grants
  nothing.
- **What a token is.** An opaque string, stored hashed and checked against the database on every call — not a JWT, so
  a revocation has nothing to wait for. It is bound to `{PUBLIC_URL}/mcp` as its audience and refused anywhere else. It
  is accepted only in the `Authorization` header, never in a URL, and never logged.
- **What a token is not.** It is not the user's session: it does not open the web app, change a passkey, reach
  `/admin` or read another user's rows. It carries no identity claims — no OpenID Connect, no id token.
- **Two scopes.** `read` reads what the user sees in the app; `write` adds and changes transactions, accounts,
  categories, tags, budgets and goals. The consent page lets the user refuse `write`. A `read` token is never even
  shown the write tools, and a write call without the scope is refused.
- **Revocation is immediate.** Profilo › Connettori lists every authorized connector with its scopes and last use;
  «Revoca accesso» deletes the consent and every token of that user–client pair, and the client's next call is a 401.
- **Lifetimes.** An access token lives one hour. A refresh token exists only when the client asked for the technical
  `offline_access` scope (MCP clients do: the server advertises it; the consent page never shows it). It is rotated on
  every use, and an authorization not refreshed for 180 days lapses on its own — the same bound as the phone's
  session.
- **A write is the web's write.** A write tool goes through the same server functions as the web forms: the same rules
  from `@saldo/core`, the same per-user scoping, the same check against an edit the phone made meanwhile. The client is
  what asks the person to confirm a write; the server adds no second confirmation.
- **The server never calls a model.** The model runs in the user's client. In this milestone Saldo holds no AI key and
  answers only the calls it is sent.
- **An admin can switch it off** at `/admin/mcp`, or with `MCP_ENABLED=false` in the environment, which locks the
  switch. Off, `/mcp`, the discovery documents, registration and authorization answer 404 and the consent page
  refuses, so no client reads or writes anything. Refreshing and revoking a token keep working (a refreshed token is
  still refused by `/mcp`), so a connector that kept its refresh token works again when MCP is back on.
- The endpoint is rate limited per token (120 requests a minute) and takes bodies of at most 1 MB; like the other
  limiters, per server process.

What it cannot protect against: a client the user authorized can do what its scopes allow, so a `write` grant to a
client that misbehaves is a client that writes. Grant `write` only to a client you would let type into the app.

````

````markdown
## Collegare un client MCP (connecting an MCP client)

The server exposes a [Model Context Protocol](https://modelcontextprotocol.io) endpoint, so each user can point their
own MCP client — Claude Code, Claude's custom connectors, Cursor, any client that speaks Streamable HTTP and OAuth —
at their data on this instance. There is no key to hand out: the client discovers the rest and sends the user to sign
in with their passkey.

- **The endpoint is `{PUBLIC_URL}/mcp`**, e.g. `https://saldo.example.com/mcp`. Every user finds it, with the exact
  line for their client, in Profilo › Connettori. For Claude Code:

  ```bash
  claude mcp add --transport http saldo https://saldo.example.com/mcp
  ```

  The first call opens the browser on `/oauth/consent`: the user signs in, chooses read only or read and write, and the
  client is connected. A terminal with no browser can go through `npx mcp-remote https://saldo.example.com/mcp`.
- **`PUBLIC_URL` has to be `https://`.** MCP clients refuse to authorize against plain `http` anywhere but on the same
  machine (`http://localhost`). The documents a client reads to find the rest —
  `/.well-known/oauth-protected-resource` and `/.well-known/oauth-authorization-server` (each also at its path-aware
  form) — are served on this host; the issuer they name is `{PUBLIC_URL}/api/auth`, and the OAuth endpoints are under
  `/api/auth/oauth2/`. So `PUBLIC_URL` must be the address clients actually reach, and a reverse proxy has to pass
  `/mcp`, `/.well-known/` and `/api/auth/` through like the rest. `/admin/mcp` shows the two documents and warns when
  `PUBLIC_URL` is plain `http` on another host.
- **Switching it off.** It is on by default. An admin switches it off at `/admin/mcp`, which also shows how many users
  have connectors; `MCP_ENABLED=false` does the same from the environment and locks the switch (`true` locks it
  on). Off, `/mcp`, the `.well-known` documents, registration and authorization answer 404 and the consent page
  refuses; refreshing and revoking tokens keep working, so authorized connectors resume when it is back on. Nothing is
  deleted.
- **What a client may do** — tokens, scopes, revocation, the 180-day lapse — is in [`SECURITY.md`](../SECURITY.md),
  «MCP e connettori».

````
