# 0.4b — MCP write tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The 14 write tools of spec §17.4.2 (`save_transaction`, `delete_transaction`, `save_account`, `archive_account`, `save_category`, `archive_category`, `save_tag`, `merge_tags`, `delete_tag`, `save_budget`, `delete_budget`, `save_goal`, `move_goal_money`, `close_goal`), described in `@saldo/core` and served by `apps/web` through the existing write functions, so an MCP client with scope `write` can change exactly what the web's forms can — and can never overwrite an edit the phone made after the client read the row.

**Architecture:** The specs (names, English descriptions, Zod input/output, annotations) and the pure input resolvers ("MCP input + the row as stored → the write function's form input") live in `packages/core/src/assistant/write/`, with unit tests, and fill 0.4a-1's `writeTools`. The handlers in `apps/web/src/server/mcp/write/` read the user's data, call a core resolver, call the **existing** function in `apps/web/src/server/write/*` (rules in core, `writeInTransaction`, `basis`), and turn its refusal codes into a model-readable message through core's `refusalMessage`. The only server-side change to the write functions is plumbing: an optional `expectedUpdatedAt` precondition (checked inside the write's own transaction) and a `null` account balance buffer meaning "keep the opening balance".

**Tech Stack:** TypeScript strict, Zod 4, Vitest 5, PGlite + Drizzle (server tests), `@modelcontextprotocol/server` / `@modelcontextprotocol/client` v2 (the scope and sync tests), Biome.

## Decisions taken in this plan

1. **The version check: the model sends back the `updatedAt` it read, and the write function checks it inside its own transaction.**
   - Why not "the handler reads current state": the write functions already do that — every one of them re-reads the row inside `writeInTransaction` and carries it as `basis`. But `basis` only covers the gap between *that* read and the row lock (milliseconds). The gap that matters for an assistant is between the model's `list_transactions` and its `save_transaction` — seconds to minutes, during which the phone can push an edit. A handler that re-reads would silently build its write on top of the phone's edit and overwrite it (exactly what the web form does today: see step 3 of `apps/web/src/server/write/pull.test.ts`). Only a version the model itself read can tell.
   - So every tool that changes or removes an existing row takes `updatedAt` (`sourceUpdatedAt` for `merge_tags`), required whenever `id` is given. The handler passes it to the write function as `expectedUpdatedAt`; inside `build`, right after the row is found, `movedSince(row, expectedUpdatedAt)` answers `conflict` if the stored stamp differs. Because the check runs on the same transaction as the read that becomes `basis`, there is no window left: model read → write-function read is covered by `expectedUpdatedAt`, write-function read → row lock by `basis`.
   - HLC stamps on a row only grow, so a handler may also read the row first to merge a partial update (decision 2): if the handler's read differs from what the model sent, the write function's check refuses too.
   - **Field the read tools must expose:** `updatedAt` (the row's HLC string, unchanged) on every entity `list_transactions`, `list_accounts` (accounts **and** their `pockets`), `list_categories`, `list_tags`, `list_budgets` and `list_goals` return. Plan 0.4a-1 (`2026-10-03-0.4a-1-mcp-core-catalogue.md`) exposes ids but no `updatedAt`, so **Task 0b adds it** to those six tools.
2. **Updates are partial.** On update the model sends `id`, `updatedAt` and only the fields it wants to change; the core resolver starts from the stored row (through the forms' own `formFromTransaction`, `accountFormFrom`, `categoryFormFrom`, `budgetFormFrom`, `goalFormFrom`) and overrides what was given. A model asked to "move this to Ristoranti" should not have to restate the amount, date and tags — and could get them wrong.
3. **Keeping an account's balance on update** needs `buffer: null` in `saveAccount`: the web form always sends the *current* balance, which the server turns into an opening balance over the ledger it reads. A handler that computed the current balance from its own earlier read would, if a phone pushed a transaction in between, shift the opening balance by that amount. `null` keeps `openingBalance` as stored (and is `0` for a new account). The web form is unchanged: it always sends a string.
4. **Amounts are integers in minor units, at most `MAX_TOOL_MINOR` = 99,999,999** (the keypad's 8 significant digits, §5.1); the resolver turns them into the keypad buffer with `minorToAmountBuffer`, so the server's existing keypad checks still run. Dates are `YYYY-MM-DD`.
5. **Not exposed:** icons and colours (an unknown icon name would render broken; new rows take the forms' defaults, edits keep what they had), the note, recurrences, attachments, «Registra la spesa» (closing a goal with an expense), restoring a closed goal, reordering categories, the 10-minute «Annulla» of a delete. Each is a product question for later, listed in the report.
6. **`save_tag` creates through `createTag`** (the transaction form's «Crea «X»»): an existing name returns that tag with `created: false`, which makes the tool idempotent and lets a model "make sure the tag exists" before tagging. Renaming goes through `renameTag`.
7. **`move_goal_money` is a transfer through `saveTransaction`**, parent → goal («Metti da parte») or goal → parent («Preleva»), exactly what the web's links prefill (`apps/web/src/features/accounts/goalLinks.ts`); description defaults to the goal's name, as there.
8. **Refusals are values.** A write function's `{ ok: false, error }` / `{ ok: false, missing }` becomes `{ ok: false, message }` through core's `refusalMessage(subject, refusal)`, which names the read tool to call next. The message texts live in core next to the descriptions: one place says what a model is told (§17.4.2, D38).
9. **Annotations.** `destructiveHint: true` for `delete_transaction`, `archive_account`, `archive_category`, `merge_tags`, `delete_tag`, `delete_budget`, `close_goal`. `idempotentHint: true` for those seven and for `save_tag` (creating an existing name or renaming to the same name writes nothing). `readOnlyHint: false`, `openWorldHint: false` everywhere.

```ts
/** The stamp a row carries now: what a read tool hands an MCP client as `updatedAt`. */
export async function stampOf(
  db: ServerDatabase,
  userId: string,
  entity: EntityName,
  id: string,
): Promise<string> {
  const found = await loadRow(db, userId, entity, id);
  if (found.status !== 'found') throw new Error(`no ${entity}/${id}`);
  return found.row.updatedAt;
}

/**
 * Another device edits the row — `patch` applied, a newer stamp — as a phone's push leaves it.
 * Returns the new stamp.
 */
export async function bumpRow(
  db: ServerDatabase,
  userId: string,
  entity: EntityName,
  id: string,
  patch: Record<string, unknown> = {},
): Promise<string> {
  const found = await loadRow(db, userId, entity, id);
  if (found.status !== 'found') throw new Error(`no ${entity}/${id}`);
  await writeChanges(
    db,
    userId,
    [{ entity, id, data: { ...unstamped(found.row), ...patch, deletedAt: found.row.deletedAt } }],
    FIXTURE_NOW,
  );
  return stampOf(db, userId, entity, id);
}
```

```ts
export async function closeGoal(
  db: ServerDatabase,
  userId: string,
  goalId: string,
  now: Date,
  /** §17.4.2: the version an MCP client read; the web's button sends none. */
  expectedUpdatedAt?: string,
): Promise<AccountResult> {
  try {
    return await writeInTransaction<AccountResult>(db, userId, now, async (tx) => {
      const data = await readUserData(tx, userId);
      const pocket = data.accounts.find((row) => row.id === goalId);
      if (pocket !== undefined && movedSince(pocket, expectedUpdatedAt)) {
        return { writes: [], result: { ok: false, error: 'conflict' } };
      }
      const { today } = todayFor(readSettings(data.settings), env().defaultTimeZone, now);
      const writes = closeGoalWrites(data, goalId, today, now);
      if (writes === null) return { writes: [], result: { ok: false, error: 'notFound' } };
      return { writes, result: { ok: true } };
    });
  } catch (error) {
    if (error instanceof WriteRefused) return { ok: false, error: error.reason };
```

```ts
  if (input.id !== undefined && input.updatedAt === undefined) {

  }
  if (input.id === undefined && input.updatedAt !== undefined) {

  }
  return null;
}
```

```ts
 * stays in `saveTransaction`; this only refuses what no form could express.
 */
export function resolveTransactionInput(
  input: SaveTransactionInput,
  existing: Transaction | null,
  today: LocalDate,
  minorDigits: MinorDigits,
): ResolveResult<TransactionWriteValues> {
  const pairing = versionPairing(input);
  if (pairing !== null) return { ok: false, message: pairing };
  const kind = input.kind ?? existing?.kind;
  if (kind === undefined) {
    return {
      ok: false,
      message: 'To create a transaction, pass kind: expense, income or transfer.',
    };
  }
  if (kind === 'transfer' && given(input.categoryId)) {
    return { ok: false, message: 'A transfer has no category: leave categoryId out.' };
  }
  if (kind !== 'transfer' && given(input.toAccountId)) {
    return {
      ok: false,
      message: 'Only a transfer has toAccountId: leave it out for an expense or an income.',
    };
  }
  const start: TransactionFormValues =
    existing === null ? emptyForm(today, null) : formFromTransaction(existing, minorDigits);
  const base = start.kind === kind ? start : changeKind(start, kind);
  return {
    ok: true,
    value: {
      id: existing?.id ?? null,
      kind,
      buffer:
        input.amountMinor === undefined
          ? base.buffer
          : minorToAmountBuffer(input.amountMinor, minorDigits),
      date: input.date ?? base.date,
      accountId: input.accountId ?? base.accountId,
      toAccountId: kind === 'transfer' ? provided(input.toAccountId, base.toAccountId) : null,
      categoryId: kind === 'transfer' ? null : provided(input.categoryId, base.categoryId),
      description: input.description ?? base.description,
      tagIds: input.tagIds ?? base.tagIds,
      excludeFromTotals: input.excludeFromTotals ?? base.excludeFromTotals,
      expectedUpdatedAt: input.updatedAt,
    },
  };
}
```

```ts
  name: string;
  categoryIds: string[];
  buffer: string;
  period: BudgetPeriod;
  alertThreshold: number | null;
  rollover: boolean;
  icon: string;
  expectedUpdatedAt?: string;

/**
 * The model's input as the budget form (§6.18). The name is required to create: the form's
 * automatic name joins categories with a word of the user's language, which core does not hold.
 */
export function resolveBudgetInput(
  input: SaveBudgetInput,
  existing: Budget | null,
  categories: readonly Category[],
  minorDigits: MinorDigits,
): ResolveResult<BudgetWriteValues> {
  const pairing = versionPairing(input);
  if (pairing !== null) return { ok: false, message: pairing };
  if (existing === null && input.name === undefined) {
    return { ok: false, message: 'To create a budget, pass name.' };
  }
  const base = existing === null ? emptyBudgetForm() : budgetFormFrom(existing, minorDigits);
  const categoryIds = input.categoryIds ?? base.categoryIds;
  // A new budget takes its first category's icon, as on the phone (§6.18).
  const icon =
    base.icon ?? categories.find((category) => category.id === categoryIds[0])?.icon ?? 'tag';

    ok: true,
    value: {
      id: existing?.id ?? null,
      name: input.name ?? base.name,
      categoryIds,
      buffer:
        input.amountMinor === undefined
          ? base.buffer
          : minorToAmountBuffer(input.amountMinor, minorDigits),
      period: input.period ?? base.period,
      alertThreshold: provided(input.alertThreshold, base.alertThreshold),
      rollover: input.rollover ?? base.rollover,
      icon,
      expectedUpdatedAt: input.updatedAt,
    },
  };
}
```

```ts
/** The stamp a live row carries now: the `updatedAt` a client sends back to change it again. */
export async function currentStamp(
  userId: string,
  entity: EntityName,
  id: string,
): Promise<string | null> {
  const found = await loadRow(getDb(), userId, entity, id);
  return found.status === 'found' && !found.deleted ? found.row.updatedAt : null;
}

/** A save's answer: the id and the version the write left, so the next edit can name it. */
export async function saved(
  subject: WriteSubject,
  entity: EntityName,
  userId: string,
  id: string,
  created: boolean,
): Promise<ToolResult<SavedOutput>> {
  const updatedAt = await currentStamp(userId, entity, id);
  if (updatedAt === null) return refuse(subject, { error: 'notFound' });
  return { ok: true, value: { id, updatedAt, created } };
}

/** An archive or restore's answer: the state the row is in now, and its version. */
export async function archivedState(
  subject: 'account' | 'category',
  userId: string,
  id: string,
): Promise<ToolResult<ArchivedOutput>> {
  const found = await loadRow(getDb(), userId, subject, id);
  if (found.status !== 'found' || found.deleted) return refuse(subject, { error: 'notFound' });
  return {
    ok: true,
    value: { id, archived: found.row.archivedAt !== null, updatedAt: found.row.updatedAt },
  };
}
```

```ts
import {
  type DeleteTransactionInput,
  deleteTransactionTool,
  type RemovedOutput,
  resolveTransactionInput,
  type SavedOutput,
  type SaveTransactionInput,
  saveTransactionTool,
} from '@saldo/core';
import { getDb } from '../../db/client';
import { readUserData } from '../../userData/read';
import * as writes from '../../write/transactions';
import type { WriteToolHandler } from '../types';
import { type Clock, minorDigitsOf, refuse, saved } from './shared';

/**
 * §17.4.2: `save_transaction` and `delete_transaction` on `saveTransaction` / `deleteTransaction`,
 * the functions the web's form calls. The handler reads only to merge a partial update; every rule
 * is the write function's, and the version the model read is checked inside its transaction.
 */
export function transactionHandlers(clock: Clock) {
  const saveTransaction: WriteToolHandler<SaveTransactionInput, SavedOutput> = {
    spec: saveTransactionTool,
    async handle(principal, input, ctx) {
      const data = await readUserData(getDb(), principal.userId);
      const existing =
        input.id === undefined
          ? null
          : (data.transactions.find((row) => row.id === input.id) ?? null);
      if (input.id !== undefined && existing === null) {
        return refuse('transaction', { error: 'notFound' });
      }
      const resolved = resolveTransactionInput(input, existing, ctx.today, minorDigitsOf(data));
      if (!resolved.ok) return resolved;
      const values: writes.TransactionInput = resolved.value;
      const result = await writes.saveTransaction(getDb(), principal.userId, values, clock());
      if (!result.ok) return refuse('transaction', result);
      return saved('transaction', 'transaction', principal.userId, result.id, existing === null);
    },
  };

  const deleteTransaction: WriteToolHandler<DeleteTransactionInput, RemovedOutput> = {
    spec: deleteTransactionTool,
    async handle(principal, input) {
      const result = await writes.deleteTransaction(
        getDb(),
        principal.userId,
        input.id,
        clock(),
        input.updatedAt,
      );
      if (!result.ok) return refuse('transaction', result);
      return { ok: true, value: { id: input.id } };
    },
  };

  return { saveTransaction, deleteTransaction };
}
```

```ts
/** §17.4.2: `save_account` and `archive_account` on the account form's write functions. */
export function accountHandlers(clock: Clock) {
  const saveAccount: WriteToolHandler<SaveAccountInput, SavedOutput> = {
    spec: saveAccountTool,
    async handle(principal, input) {
      const data = await readUserData(getDb(), principal.userId);
      const existing =
        input.id === undefined ? null : (data.accounts.find((row) => row.id === input.id) ?? null);
      if (input.id !== undefined && existing === null) {
        return refuse('account', { error: 'notFound' });
      }
      const resolved = resolveAccountInput(input, existing, minorDigitsOf(data));
      if (!resolved.ok) return resolved;
      const values: writes.AccountInput = resolved.value;
      const result = await writes.saveAccount(getDb(), principal.userId, values, clock());
      if (!result.ok) return refuse('account', result);
      return saved('account', 'account', principal.userId, result.id, existing === null);
    },
  };

  const archiveAccount: WriteToolHandler<ArchiveAccountInput, ArchivedOutput> = {
    spec: archiveAccountTool,
    async handle(principal, input) {
      const write = input.action === 'archive' ? writes.archiveAccount : writes.restoreAccount;
      const result = await write(getDb(), principal.userId, input.id, clock(), input.updatedAt);
      if (!result.ok) return refuse('account', result);
      return archivedState('account', principal.userId, input.id);
    },
  };

  return { saveAccount, archiveAccount };
}
```

```ts
          targetId: input.targetId,
          expectedUpdatedAt: input.sourceUpdatedAt,

        principal.userId,
        input.id,
        clock(),
        input.updatedAt,
```

```ts
  type CloseGoalInput,
  closeGoalTool,
  type MoveGoalMoneyInput,
  type MoveGoalMoneyOutput,
  moveGoalMoneyTool,
  type RemovedOutput,
  resolveGoalInput,
  resolveGoalTransfer,
  type SavedOutput,
  type SaveGoalInput,
  saveGoalTool,
} from '@saldo/core';
import { getDb } from '../../db/client';
import { readUserData } from '../../userData/read';
import * as goalWrites from '../../write/goals';
import * as transactionWrites from '../../write/transactions';
import type { WriteToolHandler } from '../types';
import { type Clock, currentStamp, minorDigitsOf, refuse, saved } from './shared';

/**
 * §17.4.2: `save_goal` and `close_goal` on the goal writes; `move_goal_money` is the transfer
 * «Metti da parte» / «Preleva» prefill, saved through `saveTransaction` like any transfer.
 */
export function goalHandlers(clock: Clock) {
  const saveGoal: WriteToolHandler<SaveGoalInput, SavedOutput> = {
    spec: saveGoalTool,
    async handle(principal, input) {
      const data = await readUserData(getDb(), principal.userId);
      const existing =
        input.id === undefined ? null : (data.accounts.find((row) => row.id === input.id) ?? null);
      if (input.id !== undefined && existing === null) {
        return refuse('goal', { error: 'notFound' });
      }
      const resolved = resolveGoalInput(input, existing, minorDigitsOf(data));
      if (!resolved.ok) return resolved;
      const values: goalWrites.GoalInput = resolved.value;
      const result = await goalWrites.saveGoal(getDb(), principal.userId, values, clock());
      if (!result.ok) return refuse('goal', result);
      return saved('goal', 'account', principal.userId, result.id, existing === null);
    },
  };

  const moveGoalMoney: WriteToolHandler<MoveGoalMoneyInput, MoveGoalMoneyOutput> = {
    spec: moveGoalMoneyTool,
    async handle(principal, input, ctx) {
      const data = await readUserData(getDb(), principal.userId);
      const goal = data.accounts.find((row) => row.id === input.goalId);
      if (goal === undefined) return refuse('goal', { error: 'notFound' });
      const resolved = resolveGoalTransfer(goal, input, ctx.today, minorDigitsOf(data));
      if (!resolved.ok) return resolved;
      const values: transactionWrites.TransactionInput = resolved.value;
      const result = await transactionWrites.saveTransaction(
        getDb(),
        principal.userId,
        values,
        clock(),
      );
      if (!result.ok) return refuse('goal', result);
      const updatedAt = await currentStamp(principal.userId, 'transaction', result.id);
      if (updatedAt === null) return refuse('transaction', { error: 'notFound' });
      return { ok: true, value: { transactionId: result.id, updatedAt } };
    },
  };

  const closeGoal: WriteToolHandler<CloseGoalInput, RemovedOutput> = {
    spec: closeGoalTool,
    async handle(principal, input) {
      const result = await goalWrites.closeGoal(
        getDb(),
        principal.userId,
        input.id,
        clock(),
        input.updatedAt,
      );
      if (!result.ok) return refuse('goal', result);
      return { ok: true, value: { id: input.id } };
    },
  };

  return { saveGoal, moveGoalMoney, closeGoal };
}
```
