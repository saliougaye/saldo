# 0.4a-1 — The MCP tool catalogue in core (read tools) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `@saldo/core` gains `src/assistant/`: the eleven read tools of spec §17.4.2 (`get_preferences`, `list_accounts`, `list_categories`, `list_tags`, `list_transactions`, `get_period_summary`, `spending_by_category`, `list_budgets`, `list_goals`, `list_upcoming`, `get_forecast`) — each a name, an English description, Zod input and output schemas, MCP annotations and a pure `run(data, ctx, input)` — plus the period input and its resolution, the `Money` shape, `assistantInstructions`, the write-spec types that 0.4b fills, and parity tests proving each tool says the same numbers as the page it mirrors.

**Architecture:** One file per tool under `packages/core/src/assistant/tools/`, each exporting a typed `ReadTool<I, O>`; `catalogue.ts` erases their types with `defineReadTool` (whose erased `run` re-parses the input with the tool's own schema) into `readTools`, and exports an empty `writeTools` for 0.4b. No figure is computed here: every number is an existing core function called with the page's own arguments — `summarizePeriod`, `committedSpend`, `spendingByCategory` + `rollupToParents`, `accountBalances` + `bankBalance` / `netWorth` / `spendableTotal`, `budgetViews`, `goalViews`, `nextOccurrence` + `recurringMonthlyTotals`, `forecastPeriods`, `filterTransactions` + `totalsOf`. A parity test in `apps/web` runs the tools against the pages' view functions (`statsView`, `accountsView`, `budgetsView`, `homeView`, `navigatorForecast`, `listView`) on the same data.

**Tech Stack:** TypeScript strict (`noUncheckedIndexedAccess`), Zod 4.6 (`z.toJSONSchema` checks that every schema is an MCP-readable object schema), Vitest 5. No MCP SDK, no server code, no React: core imports none of them.

**Spec:** §17.4.2 (the endpoint and the tools — the source of truth), §17.1.2 (`UserData`), §17.1.5 («today» on the server), D37, D38, D40. Roadmap 0.4, step 0.4a.

**One deviation from the brief's sketch:** `ToolPeriodInput` is a single flat object, not the union `{ period? } | { from; to }` (Decision 2). Every value of the union is still a valid `ToolPeriodInput`, so callers are unaffected; the "both or neither, not with `period`" rule moves into `checkToolPeriod`.

A `ZodError` thrown by `run` is a tool error, not a 500. `initialize.instructions` is `assistantInstructions(data, ctx)`.

## Decisions (recorded here, as AGENTS.md asks)

1. **Core does not import `@saldo/i18n`.** `@saldo/i18n` depends on `@saldo/core`, so the reverse would be a cycle. `toMoney` uses core's own `formatMinorUnits` (`packages/core/src/money.ts`, the function §17.4.2 names) with `getCurrency(code).minorDigits` from `currencies.generated.ts`; a code this build does not know falls back to two digits.
2. **The period input is one flat object** `{ period?, from?, to? }` checked by `checkToolPeriod` (a `superRefine`), not a union. An MCP tool's `inputSchema` must be a JSON object schema, and a top-level union becomes `anyOf` with no `"type": "object"`; tools also put their own fields beside the period. Each tool builds `z.object({ ...toolPeriodShape, ...ownFields }).superRefine(checkToolPeriod)` — never `.extend()` on a refined schema.
3. **A date in `period` is not clamped** to the current period. The web clamps `?p=` (`periodFromParam`) because a hand-typed URL must not show a page a click could not reach; a model asking what is scheduled next month should get those rows. Resolution is `periodContaining` / `shiftPeriod` from `period.ts`, as §17.4.2 says.
4. **`get_period_summary.previous`** is the period before when the input names one app period (`isWholePeriod`), and `null` for an explicit `from`/`to` range: "the range of the same length before" would be a calculation no page makes.
5. **`list_budgets` takes `period` only.** A budget is measured per app period or per calendar window; an arbitrary range has no limit to measure against.
6. **`list_transactions` reads the period's own bounds.** On the *current* period the Transazioni list also reaches into the next period (its «In arrivo» horizon, `upcomingUntil`); the tool stops at the period, so "this month" means this month, and rows dated after today come back marked `upcoming`. `totals` is `totalsOf` over the matching rows dated up to today — the list's own line above the rows, excluded rows included. Parity with `listView` is asserted on a closed period, where both read the same rows.
7. **`list_upcoming` is the phone's «Ricorrenti» (§6.33):** each recurrence that has not ended, with `nextOccurrence(recurrence, today)`, soonest first, and `recurringMonthlyTotals` of those. The web has no recurrences screen in 0.3, so this tool's test is in core only.
   **Changed by the user on 2026-10-03:** `list_upcoming` also lists the one-off transactions dated after today (not only recurrences), merged with the occurrences and sorted soonest first, each item saying which kind it is. Task 8 is adjusted at execution time to cover this (test first).
8. **`list_tags` returns `id` and `name`, by name**, no usage counts (YAGNI: a model counts with `list_transactions({ tagId })`).
9. **Two figures repeat a page's own one-line expression** because the page computes them outside core: the summary's `discretionary` is `Math.max(0, spent − committed)` and `spending_by_category`'s `total` is the sum of the rolled-up map, both exactly as `statsView` writes them. The parity test pins each to the page.
10. **The erased `run` re-parses its input.** The MCP SDK validates arguments before the handler, but 0.5 will call `readTools` in-process holding `unknown`; an invalid input throws a `ZodError`.
11. **The parity tests live in `apps/web/src/features/assistant/parity.test.ts`.** The pages' view functions are in `apps/web`, and packages never import apps. The test imports only pure `features/*` view functions — no server, no route — so it needs no database.
12. **Settings are read with `readSettings`** (`toolUser`), as `pageState` does: before onboarding the defaults stand in (calendar month, EUR) and every tool still answers; `get_preferences.onboarded` and the instructions say so.
13. **Dates in schemas** are `toolDateSchema`: a `YYYY-MM-DD` regex (so the JSON Schema carries a pattern) refined with core's `isLocalDate`.
14. **A new fixture**, `assistant/__fixtures__/userData.ts`: core's `__tests__/fixtures.ts` is `LedgerTx`-level, with no full `UserData`. The new one goes through the entity schemas, as `apps/web/src/features/test/fixtures.ts` does.

```ts
import type { z } from 'zod';
import type { LocalDate } from '../dates';
import type { UserData } from '../userData';

/** The OAuth scope a tool needs (§17.4.1, D40): a `read` token never even lists a write tool. */
export type ToolScope = 'read' | 'write';

/**
 * What a tool is told besides the data: the user's «today», in the user's own zone (§17.1.5, D37).
 * The server derives it with `todayFor`; core never reads a clock.
 */
export type ToolContext = { today: LocalDate; timeZone: string };

/** The MCP tool annotations (§17.4.2). Saldo never reaches outside the user's own data. */
export type ToolAnnotations = {
  readOnlyHint: boolean;
  destructiveHint: boolean;
  idempotentHint: boolean;
  openWorldHint: false;
};

/** Every read tool's annotations: it changes nothing, and asking twice answers the same. */
export const READ_ANNOTATIONS: ToolAnnotations = {
  readOnlyHint: true,
  destructiveHint: false,
  idempotentHint: true,
  openWorldHint: false,
};

/**
 * One tool of the catalogue (§17.4.2): what the model is told about it — name, English description,
 * the Zod schemas of its input and output — and how an MCP client should treat it.
 */
export type ToolSpec<I, O> = {
  name: string;
  title: string;
  description: string;
  scope: ToolScope;
  input: z.ZodType<I>;
  output: z.ZodType<O>;
  annotations: ToolAnnotations;
};

/** A read tool answers from the data alone: a pure function, so the MCP route and 0.5 share it. */
export type ReadTool<I, O> = ToolSpec<I, O> & {
  scope: 'read';
  run(data: UserData, ctx: ToolContext, input: I): O;
};

/** A write tool's description only: the server maps it onto `apps/web/src/server/write/*` (0.4b). */
export type WriteToolSpec<I, O> = ToolSpec<I, O> & { scope: 'write' };

/** A read tool with its types erased, so tools of different shapes share one array. */
export type AnyReadTool = ReadTool<unknown, unknown>;

/** A write spec with its types erased, for `writeTools`. */
export type AnyWriteToolSpec = WriteToolSpec<unknown, unknown>;

/**
 * Erases a read tool's types **safely**: the erased `run` parses its input with the tool's own
 * schema before calling the typed one, so a caller holding `unknown` (the MCP route, 0.5's prompt
 * builder) cannot hand it a shape it was not written for. An invalid input throws a `ZodError`.
 */
export function defineReadTool<I, O>(tool: ReadTool<I, O>): AnyReadTool {
  return {
    ...tool,
    run: (data, ctx, input) => tool.run(data, ctx, tool.input.parse(input)),
  };
}

/** Erases a write spec's types; the handler that parses its input lives on the server (0.4b). */
export function defineWriteToolSpec<I, O>(spec: WriteToolSpec<I, O>): AnyWriteToolSpec {
  return spec;
}
```

`ReadTool<I, O>` is assignable to `AnyReadTool` only because Zod 4 declares `ZodType<out Output>` covariant and `run` is a method; `defineReadTool` is what makes the erasure *safe* (it parses). Do not push tools into `readTools` without it.

```ts
import { z } from 'zod';
import {
  CURRENCY_CODES,
  type CurrencyCode,
  formatMinorUnits,
  getCurrency,
  type MinorDigits,
} from '../money';

/**
 * An amount as a tool returns it (§17.4.2): the integer the app stores, its currency, and the same
 * value as a plain decimal the model can read. Arithmetic goes back to `minor`.
 */
export type Money = { minor: number; currency: string; amount: string };

export const moneySchema = z.object({
  minor: z
    .number()
    .int()
    .describe('The amount in integer minor units (cents for EUR). Do arithmetic on this.'),
  currency: z.string().describe('ISO 4217 currency code.'),
  amount: z
    .string()
    .describe('The same amount as a plain decimal string, e.g. "123.45". Read this one.'),
});

/** Two decimals for a code this build does not know: what most currencies use. */
const FALLBACK_MINOR_DIGITS: MinorDigits = 2;

function isCurrencyCode(value: string): value is CurrencyCode {
  return (CURRENCY_CODES as readonly string[]).includes(value);
}

/** `12345, 'EUR'` → `{ minor: 12345, currency: 'EUR', amount: '123.45' }` (`formatMinorUnits`). */
export function toMoney(minor: number, currency: string): Money {
  const digits = isCurrencyCode(currency)
    ? getCurrency(currency).minorDigits
    : FALLBACK_MINOR_DIGITS;
  return { minor, currency, amount: formatMinorUnits(minor, digits) };
}
```

```ts
import { z } from 'zod';
import type { DateRange } from '../cycle';
import type { LocalDate } from '../dates';
import { type PeriodDef, periodContaining, shiftPeriod } from '../period';
import type { UserData } from '../userData';
import { toolDateSchema } from './schemas';
import type { ToolContext } from './types';
import { toolUser } from './user';

/** `"current"`, `"previous"`, or a date inside the period wanted — the web's `?p=`. */
export type ToolPeriodRef = 'current' | 'previous' | LocalDate;

/**
 * The period a tool reads (§17.4.2): `period`, or an explicit `from`/`to` pair, never both. One
 * flat object rather than a union, because an MCP tool's input schema has to be a JSON object
 * schema and tools add their own fields beside these three; `checkToolPeriod` enforces the rest.
 */
export type ToolPeriodInput = { period?: ToolPeriodRef; from?: LocalDate; to?: LocalDate };

const periodRef = z
  .union([z.enum(['current', 'previous']), toolDateSchema])
  .describe(
    'The app period to read: "current", "previous", or any YYYY-MM-DD date inside the period wanted. Defaults to "current".',
  );

/** The three period fields, for a tool to spread into its own input object. */
export const toolPeriodShape = {
  period: periodRef.optional(),
  from: toolDateSchema
    .optional()
    .describe('Start of an explicit date range, inclusive. Needs `to`; replaces `period`.'),
  to: toolDateSchema.optional().describe('End of an explicit date range, inclusive. Needs `from`.'),
};

/** The rules a flat object cannot say: both ends or neither, not with `period`, in order. */
export function checkToolPeriod(value: ToolPeriodInput, ctx: z.RefinementCtx): void {
  const hasFrom = value.from !== undefined;
  const hasTo = value.to !== undefined;
  if (hasFrom !== hasTo) {
    ctx.addIssue({
      code: 'custom',
      message: 'Give both from and to, or neither',
      path: [hasFrom ? 'to' : 'from'],
    });
    return;
  }
  if (hasFrom && value.period !== undefined) {
    ctx.addIssue({
      code: 'custom',
      message: 'Use either period or from/to, not both',
      path: ['period'],
    });
  }
  if (value.from !== undefined && value.to !== undefined && value.to < value.from) {
    ctx.addIssue({ code: 'custom', message: 'to must not be before from', path: ['to'] });
  }
}

export const toolPeriodInput: z.ZodType<ToolPeriodInput> = z
  .object(toolPeriodShape)
  .superRefine(checkToolPeriod);

/**
 * The range a period input names, through `period.ts` (§17.4.2). A date is not clamped to the
 * current period as the web's `periodFromParam` clamps `?p=`: the web has nothing to show ahead,
 * while a model asking what is scheduled next month should get those rows.
 */
export function resolveToolPeriod(
  input: ToolPeriodInput,
  data: UserData,
  ctx: ToolContext,
): DateRange {
  if (input.from !== undefined && input.to !== undefined) {
    return { start: input.from, end: input.to };
  }
  const { def } = toolUser(data);
  const current = periodContaining(def, ctx.today);
  const ref = input.period ?? 'current';
  if (ref === 'current') return current;
  if (ref === 'previous') return shiftPeriod(def, current, -1);
  return periodContaining(def, ref);
}

/** Whether `range` is exactly one of the app's periods, so «the previous period» means something. */
export function isWholePeriod(def: PeriodDef, range: DateRange): boolean {
  const period = periodContaining(def, range.start);
  return period.start === range.start && period.end === range.end;
}
```

```ts
/** Plain code-unit order: what SQLite's BINARY collation gives the phone's `ORDER BY name`. */
export function binary(a: string, b: string): number {
  if (a < b) return -1;
  if (a > b) return 1;
  return 0;
}

/** The order the user set, the name breaking a tie. */
export function bySortOrder(
  a: { sortOrder: number; name: string },
  b: { sortOrder: number; name: string },
): number {
  return a.sortOrder - b.sortOrder || binary(a.name, b.name);
}
```

```ts
export const listCategoriesTool: ReadTool<ListCategoriesInput, ListCategoriesOutput> = {
  name: 'list_categories',
  title: 'Categories',
  description:
    'The categories, expense ones then income ones, each top-level category followed by its children (categories are two levels deep; `parentId` names the parent). Totals per category roll children up into their parent. Archived categories only with includeArchived.',
  scope: 'read',
  input,
  output,
  annotations: READ_ANNOTATIONS,
  run(data, _ctx, { includeArchived }) {
    const tree = (['expense', 'income'] as const).flatMap((direction) =>
      topLevelCategories(data.categories, direction).flatMap((parent) => [
        parent,
        ...childCategories(data.categories, parent.id),
      ]),

    const listed = new Set(tree.map((category) => category.id));
    // Whatever the tree did not reach: archived rows on request, and a live child whose parent is
    // archived, which `topLevelCategories` never walks into.

      .filter(
        (category) => !listed.has(category.id) && (includeArchived || category.archivedAt === null),
      )
      .sort(bySortOrder);
    return {
      categories: [...tree, ...rest].map((category) => ({
        id: category.id,
        name: category.name,
        direction: category.direction,
        parentId: category.parentId,
        archived: category.archivedAt !== null,
```

```ts
    limit: z.number().int().min(1).max(MAX_TRANSACTIONS_LIMIT).default(50),
    offset: z.number().int().min(0).default(0),

  tagNames: z.array(z.string()),
  excludeFromTotals: z.boolean(),
  recurring: z.boolean(),
  upcoming: z.boolean().describe('Dated after today: scheduled, not counted yet.'),
});

  total: z.number().int().describe('How many rows match, over every page.'),
  offset: z.number().int(),
  limit: z.number().int(),
  totals: z
    .object({ expense: moneySchema, income: moneySchema, count: z.number().int() })

    ),

export type ListTransactionsOutput = z.infer<typeof output>;

export const listTransactionsTool: ReadTool<ListTransactionsInput, ListTransactionsOutput> = {
  name: 'list_transactions',
  title: 'Transactions',
  description:

  output,
  annotations: READ_ANNOTATIONS,

    const accounts = new Map(data.accounts.map((account) => [account.id, account]));
    const categories = new Map(data.categories.map((category) => [category.id, category]));
    const tags = new Map(data.tags.map((tag) => [tag.id, tag]));

      categoryId: input.categoryId ?? null,

    const matched = filterTransactions(inRange, filters, lookup);
    const totals = totalsOf(splitUpcoming(matched, ctx.today).settled);
    return {
      period: range,
      total: matched.length,
      offset: input.offset,
      limit: input.limit,
      totals: {
        expense: user.money(totals.expense),
        income: user.money(totals.income),
        count: totals.count,
      },
      transactions: matched.slice(input.offset, input.offset + input.limit).map((tx) => ({
        id: tx.id,
        date: tx.date,
        kind: tx.kind,
        amount: user.money(tx.amount),
        description: tx.description,
        note: tx.note,
        accountId: tx.accountId,

        tagIds: tx.tagIds,
        tagNames: tx.tagIds.flatMap((id) => {
          const found = tags.get(id);
          return found === undefined ? [] : [found.name];
        }),
        excludeFromTotals: tx.excludeFromTotals,
        recurring: tx.recurrenceId !== null,
        upcoming: isUpcoming(tx, ctx.today),
      })),
    };
  },
```

```ts
/** What both kinds of item say, named as list_transactions names them. */
const itemFields = {
  id: z.string(),
  transactionKind: transactionKindSchema.describe(
    'Which way the money goes: an expense, an income or a transfer (`kind` in list_transactions).',
  ),
  amount: moneySchema,
  description: z.string(),
  accountId: z.string(),
  accountName: z.string().nullable(),
  toAccountId: z.string().nullable(),
  toAccountName: z.string().nullable(),
  categoryId: z.string().nullable(),
  categoryName: z.string().nullable(),
};

  kind: z.literal('recurrence'),
  date: toolDateSchema.describe('The next date the recurrence fires, after today.'),
  ...itemFields,
  frequency: recurrenceFrequencySchema,
  interval: z.number().int().describe('Every `interval` units of `frequency`.'),
  startDate: toolDateSchema,
  endDate: toolDateSchema.nullable(),
});

const transactionItem = z.object({
  kind: z.literal('transaction'),
  date: toolDateSchema.describe('The date it is scheduled for, after today.'),
  ...itemFields,
  note: z.string().nullable(),
  excludeFromTotals: z.boolean(),
});

const output = z.object({
  monthly: z
    .object({ expense: moneySchema, income: moneySchema })
    .describe('What the live recurrences add up to in an average month.'),
  items: z
    .array(z.discriminatedUnion('kind', [recurrenceItem, transactionItem]))
    .describe(
      'Soonest first. `kind` "recurrence": a recurring transaction, at its next date; "transaction": a one-off transaction dated after today.',
    ),
});

export type ListUpcomingInput = z.infer<typeof input>;
export type ListUpcomingOutput = z.infer<typeof output>;
type UpcomingItem = ListUpcomingOutput['items'][number];

export const listUpcomingTool: ReadTool<ListUpcomingInput, ListUpcomingOutput> = {
  name: 'list_upcoming',
  title: 'Upcoming transactions',
  description:
    'What is scheduled after today, soonest first: each recurring transaction that has not ended, at the next date it fires (`kind` "recurrence"), and each one-off transaction dated after today (`kind` "transaction"). Also what the recurrences add up to in an average month. Recurrences that already ended are left out; an occurrence of a recurrence is listed once, as the recurrence.',
  scope: 'read',
  input,
  output,
  annotations: READ_ANNOTATIONS,
  run(data, ctx) {
    const user = toolUser(data);
    const accounts = new Map(data.accounts.map((account) => [account.id, account.name]));
    const categories = new Map(data.categories.map((category) => [category.id, category.name]));
    const accountName = (id: string) => accounts.get(id) ?? null;
    const toAccountName = (id: string | null) => (id === null ? null : accountName(id));
    const categoryName = (id: string | null) => (id === null ? null : (categories.get(id) ?? null));
    // The phone's «Ricorrenti» (§6.33): `nextOccurrence` after today, for the live ones.
    const live = data.recurrences.flatMap((recurrence) => {
      if (recurrence.deletedAt !== null) return [];
      const next = nextOccurrence(recurrence, ctx.today);
      return next === null ? [] : [{ recurrence, next }];
    });
    const monthly = recurringMonthlyTotals(live.map((entry) => entry.recurrence));
    const recurrences = live.map(({ recurrence, next }): UpcomingItem => {
      const { template } = recurrence;
      return {
        kind: 'recurrence',
        id: recurrence.id,
        date: next,
        transactionKind: template.kind,
        amount: user.money(template.amount),
        description: template.description,
        accountId: template.accountId,
        accountName: accountName(template.accountId),
        toAccountId: template.toAccountId,
        toAccountName: toAccountName(template.toAccountId),
        categoryId: template.categoryId,
        categoryName: categoryName(template.categoryId),
        frequency: recurrence.frequency,
        interval: recurrence.interval,
        startDate: recurrence.startDate,
        endDate: recurrence.endDate,
      };
    });
    // One-off rows only (decided 2026-10-03): a materialised occurrence is the recurrence's own,
    // already listed above at its next date.
    const oneOff = data.transactions
      .filter(
        (tx) => tx.deletedAt === null && tx.recurrenceId === null && isUpcoming(tx, ctx.today),
      )
      .map(
        (tx): UpcomingItem => ({
          kind: 'transaction',
          id: tx.id,
          date: tx.date,
          transactionKind: tx.kind,
          amount: user.money(tx.amount),
          description: tx.description,
          note: tx.note,
          accountId: tx.accountId,
          accountName: accountName(tx.accountId),
          toAccountId: tx.toAccountId,
          toAccountName: toAccountName(tx.toAccountId),
          categoryId: tx.categoryId,
          categoryName: categoryName(tx.categoryId),
          excludeFromTotals: tx.excludeFromTotals,
        }),
      );
    return {
      monthly: { expense: user.money(monthly.expense), income: user.money(monthly.income) },
      items: [...oneOff, ...recurrences].sort(
        (a, b) => binary(a.date, b.date) || binary(a.kind, b.kind) || binary(a.id, b.id),
      ),
    };
```

```ts
import { getCurrency } from '../money';
import { type PeriodDef, periodContaining, shiftPeriod } from '../period';
import type { UserData } from '../userData';
import type { ToolContext } from './types';
import { toolUser } from './user';

function periodWords(def: PeriodDef): string {
  switch (def.kind) {
    case 'month':
      return 'calendar month';
    case 'week':
      return 'ISO week (Monday to Sunday)';
    case 'year':
      return 'calendar year';
    case 'cycle':
      return `pay cycle starting on day ${def.startDay} of each month`;
  }
}

/**
 * The text the server sends in `initialize.instructions` (§17.4.2): what a period is and how the
 * cycle day moves it, how amounts come, how categories nest, the user's currency, and that «today»
 * is the user's, in the user's zone (D37). English: it speaks to the model, not to the user.
 */
export function assistantInstructions(data: UserData, ctx: ToolContext): string {
  const user = toolUser(data);
  const current = periodContaining(user.def, ctx.today);
  const previous = shiftPeriod(user.def, current, -1);
  const digits = getCurrency(user.currency).minorDigits;
  const paragraphs = [
    "These tools read the user's personal finances from Saldo, on the user's own server.",
    user.onboarded
      ? null
      : 'The user has not finished setting up Saldo yet: the lists are empty and the defaults below stand in for their settings.',
    `Today is ${ctx.today} in ${ctx.timeZone}, the user's time zone. "Today", "this month" and every period are the user's, not yours or the server's.`,
    `Periods. The user tracks spending by ${periodWords(user.def)}. The current period runs from ${current.start} to ${current.end}; the previous one from ${previous.start} to ${previous.end}. Tools that take a period accept \`period\`: "current", "previous", or any YYYY-MM-DD date inside the period wanted; or an explicit \`from\`/\`to\` pair, both ends inclusive.`,
    user.def.kind === 'cycle'
      ? `A cycle starts on day ${user.def.startDay} of a month (on the last day of a shorter month) and ends the day before the next one starts.`
      : null,
    `Money. The user keeps their money in ${user.currency}. Every amount is an object { minor, currency, amount }: \`minor\` is an integer in minor units (${digits} decimal digits for ${user.currency}) and \`amount\` is the same value as a plain decimal string. Read \`amount\`; do arithmetic on \`minor\`. Transaction amounts are positive and \`kind\` says which way the money went.`,
    "Totals. Transfers move money between the user's own accounts and are never income or expenses. A transaction with `excludeFromTotals` still moves its account's balance but stays out of every total, budget and statistic. A transaction dated after today is scheduled (`upcoming`) and does not count yet. Do not recompute totals the tools return: get_period_summary and spending_by_category give the numbers of the app's Statistics screen.",
    "Categories are two levels deep: a top-level category may have children, and totals per category roll children up into their parent. Account, category and tag names are the user's own words: quote them as they are. Every entity carries its id; pass ids back unchanged to filter by them.",
  ];
  return paragraphs.filter((paragraph) => paragraph !== null).join('\n\n');
}
```

```ts
import {

  categorySchema,

  getForecastTool,

  listBudgetsTool,

// §17.4.2 and §17.4.5: «the answer matches Statistiche to the cent». Each test runs a read tool of
// `@saldo/core` and the view function the page renders from, on the same data, and asks them for
// the same numbers. A tool that drifted from its page fails here, not in front of a user.

const CTX: ToolContext = { today: '2026-09-15', timeZone: 'Europe/Rome' };

const SETTINGS = settingsSchema.parse({
  id: 'settings',
  createdAt: '2026-01-01T00:00:00.000Z',
  updatedAt: '2026-01-01T00:00:00.000Z-0000-web',
  deletedAt: null,

  direction: 'income',

const POCKET = account({

  name: 'Vacanze',
  type: 'pocket',
  includeInSpendable: false,
  parentAccountId: ACCOUNT.id,
  goalTarget: 100000,
  goalStartDate: '2026-06-01',

function budget(over: Partial<Budget> & Pick<Budget, 'id' | 'categoryIds'>): Budget {
  return budgetSchema.parse({
    name: 'Budget',
    amount: 10000,
    period: 'period',
    alertThreshold: 80,
    rollover: false,
    icon: 'cart',

/** Three used months, then September with an excluded row, a transfer and a row ahead of today. */
function data(): UserData {

const DEF: PeriodDef = { kind: SETTINGS.periodKind, startDay: SETTINGS.cycleStartDay };

describe('the read tools say what the pages say', () => {
  it.each([undefined, '2026-08-10'])('get_period_summary matches Statistiche (?p=%s)', (param) => {
    const period = periodFromParam(DEF, CTX.today, param);
    const stats = statsView({
      data: data(),
      def: DEF,
      today: CTX.today,
      period,
      direction: 'expense',
    });
    const tool = getPeriodSummaryTool.run(data(), CTX, { period: param });
    expect(tool.income.minor).toBe(stats.figures.income);
    expect(tool.expenses.minor).toBe(stats.figures.spent);
    expect(tool.balance.minor).toBe(stats.figures.net);
    expect(tool.committed.amount.minor).toBe(stats.committed.amount);
    expect(tool.committed.sharePercent).toBe(stats.committed.share);
    expect(tool.committed.discretionary.minor).toBe(stats.committed.discretionary);
  });

    'spending_by_category matches the split of Statistiche (%s)',
    (direction) => {
      const period = periodFromParam(DEF, CTX.today, undefined);
      const stats = statsView({ data: data(), def: DEF, today: CTX.today, period, direction });
      const tool = spendingByCategoryTool.run(data(), CTX, { direction });
      expect(tool.total.minor).toBe(stats.split.total);
      expect(
        tool.categories.map((row) => [row.categoryId, row.amount.minor, row.sharePercent]),
      ).toEqual(stats.split.rows.map((row) => [row.categoryId, row.amount, row.share]));
    },
  );

  it('list_accounts matches Conti', () => {
    const page = accountsView({ data: data(), today: CTX.today, def: DEF });
    const tool = listAccountsTool.run(data(), CTX, { includeArchived: false });
    expect(tool.netWorth.minor).toBe(page.netWorth);
    expect(tool.spendable.minor).toBe(page.spendable);
    for (const row of [...page.spending, ...page.savings]) {
      const mirrored = tool.accounts.find((candidate) => candidate.id === row.account.id);
      expect(mirrored?.balance.minor).toBe(row.balance);
      expect(mirrored?.free.minor).toBe(row.free);
      expect(mirrored?.pockets.map((pocket) => [pocket.id, pocket.saved.minor])).toEqual(
        row.pockets.map((pocket) => [pocket.account.id, pocket.saved]),
      );
    }
  });

  it.each([undefined, '2026-08-10'])('list_budgets matches Budget (?p=%s)', (param) => {
    const period = periodFromParam(DEF, CTX.today, param);
    const page = budgetsView({ data: data(), today: CTX.today, def: DEF, period });
    const tool = listBudgetsTool.run(data(), CTX, { period: param });
    expect(
      tool.budgets.map((row) => [row.id, row.spent.minor, row.limit.minor, row.ratio]),
    ).toEqual(page.items.map((view) => [view.budget.id, view.spent, view.limit, view.ratio]));
  });

  it('list_goals matches the goals of Home', () => {
    const period = periodFromParam(DEF, CTX.today, undefined);
    const page = homeView({ data: data(), today: CTX.today, def: DEF, period });
    const tool = listGoalsTool.run(data(), CTX, {});
    expect(
      tool.goals.map((goal) => [goal.id, goal.saved.minor, goal.state, goal.perPeriod?.minor]),
    ).toEqual(
      page.goals.items.map((view) => [
        view.account.id,
        view.progress.saved,
        view.progress.state,
        view.progress.perPeriod ?? undefined,
      ]),
    );
  });

  it('get_forecast matches the forecast columns of Statistiche', () => {
    const page = navigatorForecast({ data: data(), def: DEF, today: CTX.today });
    const tool = getForecastTool.run(data(), CTX, {});
    expect(page).not.toBeNull();
    expect(tool.available).toBe(true);
    expect(
      tool.periods.map((period) => [
        period.start,
        period.end,
        period.income.minor,
        period.expenses.minor,
        period.expensesMin.minor,
        period.expensesMax.minor,
        period.balance.minor,
      ]),
    ).toEqual(
      (page ?? []).map((period) => [
        period.range.start,
        period.range.end,
        period.income,
        period.expenses,
        period.expensesMin,
        period.expensesMax,
        period.balance,
      ]),
    );
  });

  it('list_transactions matches Transazioni on a closed period', () => {
    // A closed period: the list's «In arrivo» horizon is the period's own end, so both read the
    // same rows. (On the current period the list also reaches into the next one; the tool stops
    // at the period, by decision.)
    const period = periodFromParam(DEF, CTX.today, '2026-08-10');
    for (const filters of [EMPTY_FILTERS, { ...EMPTY_FILTERS, categoryId: CATEGORY.id }]) {
      const page = listView({ data: data(), filters, today: CTX.today, def: DEF, period });
      const tool = listTransactionsTool.run(data(), CTX, {
        period: '2026-08-10',
        categoryId: filters.categoryId ?? undefined,
        limit: 200,
        offset: 0,
      });
      expect(tool.transactions.map((row) => row.id)).toEqual(
        page.days.flatMap((day) => day.rows.map((row) => row.id)),
      );
      expect(tool.totals.expense.minor).toBe(page.totals.expense);
      expect(tool.totals.income.minor).toBe(page.totals.income);
      expect(tool.totals.count).toBe(page.totals.count);
    }
  });
});
```
