# 0.3i — Mail through a provider's SMTP relay (docs only)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a self-hoster who wants Saldo to send real mail knows, from `docs/self-hosting.md` alone, which five values
to type for Resend, Postmark, Amazon SES, Mailgun or Brevo — as `SMTP_*` lines or into `/admin/settings?edit=smtp` —
what the provider wants from the domain first (SPF, DKIM, DMARC where asked), which ports Saldo's `transportSecurity`
accepts, and how to prove it works («Manda un'email di prova»).

**Architecture:** no code, no spec change (roadmap decision of 2026-10-01: mail stays SMTP, a provider is used through
its SMTP relay; no native API driver). One new subsection in `docs/self-hosting.md` under «Server settings», before
«Local development». The shortened Resend example goes into the commented `SMTP_*` block of `apps/web/.env.example`
and into the comments of `apps/web/docker/docker-compose.yml`, both pointing at the doc section for the others.

**Tech stack:** Markdown. Provider facts checked against the providers' own documentation on 2026-10-03; where a page
could not be read, the doc says what to look up rather than guessing a value.

**Sources of truth in the repo:** `apps/web/src/server/mail/mailer.ts` (`transportSecurity`: 465 is implicit TLS, any
other port requires STARTTLS, a plain connection only to `localhost`/`127.0.0.1`/`::1`); `apps/web/src/server/env.ts`
(`SMTP_PORT` defaults to 587, `SMTP_FROM` required with `SMTP_HOST`, user and password together or not at all);
`packages/i18n/src/locales/it.ts` → `web.admin.settings.smtp` for the panel's labels (Server, Porta, Utente,
Password, Mittente, «Manda un'email di prova»).
