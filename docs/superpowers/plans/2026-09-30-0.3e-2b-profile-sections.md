# 0.3e-2b — Profilo: Categorie, Budget and Obiettivi as their own sections

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Categorie, Budget and Obiettivi each get their own page under Profilo (`/profile/categories`,
`/profile/budgets`, `/profile/goals`), reached from the sub-navigation, and each lets the user create, edit and (for
categories and goals) archive and restore. Categories are new on the web (they were 0.3e-3's); budgets and goals move
here from 0.3e-2's first placement (`/budgets`, Conti's panel).

**Architecture:** as 0.3e-1/0.3e-2. Rules in `@saldo/core` (already there for budgets and goals; categories' reorder and
usage are in `categories.ts`), writes through `writeInTransaction` in `apps/web/src/server/write/`, forms as client
components in the trailing panel. Profilo's panel does not sit beside the list as a sibling: the layout has an empty
`#profile-panel` slot and `PasskeyList` renders its `Panel` into it with `createPortal`. A small `ProfilePanel` wrapper
does that once for every section.

**Tech Stack:** as 0.3e-2.

**Scope cut from the request (2026-09-30):** the URLs are `/profile/…`, the convention of spec §17.1.7, not `/account/…`.
Tags, Dati and Preferenze stay 0.3e-3.

---

## Decisions

1. **Sub-navigation** gains Categorie (`categories.title`), Budget (`budgets.title`) and Obiettivi (`goals.title`), after
   Preferenze and before Passkey. `/profile/account` goes back to name and email only.
2. **Budgets move to `/profile/budgets`.** `/budgets` becomes a redirect that keeps the query string (`?new`, `?b=`).
   Home's links, the budget form's `closeHref`/`afterSave`, `DeleteBudget`'s redirect and `nav.ts`'s `OWNED_BY` entry
   follow. Home stays lit while the user is on `/profile/budgets`? No: the profile pages belong to the avatar, so the
   `OWNED_BY` entry for `/budgets` is removed and `isCurrent`'s test updated.
3. **Goals: one place for create and edit.** `/profile/goals` lists open goals (ring, saved of target) and, under
   «Obiettivi chiusi», closed ones with «Ripristina». `?new` and `?g={id}` open `GoalForm` in the panel. Conti's goal
   panel keeps the money movements (Accantona, Preleva, Chiudi) and its «Modifica» links to `/profile/goals?g={id}`;
   Conti's own `?newGoal` and `?g={id}&edit` form code is deleted. Home's «Crea un obiettivo» and the empty-state link
   point to `/profile/goals?new`.
4. **Categories follow §5.11**: Uscite / Entrate sections, children indented, usage «N voci» (`rollUpCategoryUsage` over
   live transaction counts), reorder within a sibling group (`reorderSiblings`, up/down buttons — drag is the phone's),
   no delete, archive with an optional «Sposta le transazioni in» target (same direction, not itself), archived list with
   «Ripristina», and the category form's «Budget mensile» toggle + amount (§5.11, §6.19).
5. **Category rules re-checked on the server**, mirroring the phone's `CategoryForm`, `adminService.archiveCategory` and
   `restoreCategory`: a child cannot have children (`parentId` must be a live top-level category of the same
   direction, and a category that has children cannot get a parent); the parent is not itself; archiving a parent
   archives its children; moving rewrites `categoryId` on every live transaction and recurrence template that uses it and
   the `categoryIds` of every budget (deduplicated), all in **one** write; the move target is live, same direction,
   not the archived category nor one of its children.
6. **«Budget mensile»** on the category form: enabled with an amount > 0 creates a single-category `period` budget named
   after the category (alert 90, no rollover, the category's icon) when none exists for it, or updates that budget's
   amount; disabled leaves an existing budget alone (as the phone). Read `apps/mobile/app/category/edit/[id].tsx` for the
   exact edit behaviour and copy it.
7. **Errors**: `CategoryWriteError = WriteError | 'parentInvalid' | 'moveInvalid'`; thrown actions keep the draft
   (0.3e-1 I1).

## File structure

- `apps/web/app/(app)/profile/ProfilePanel.tsx` — portal wrapper around `Panel` into `#profile-panel`.
- `apps/web/app/(app)/profile/{categories,budgets,goals}/…` — pages, forms, actions.
- `apps/web/app/(app)/budgets/page.tsx` — redirect only; `BudgetForm.tsx`, `DeleteBudget.tsx`, `actions.ts`,
  `budgets.module.css` move to `profile/budgets/`.
- `apps/web/src/server/write/categories.ts` (+ test) — `saveCategory`, `archiveCategory`, `restoreCategory`,
  `reorderCategory`.
- `apps/web/src/features/categories/{categoriesView,formView,archiveView}.ts` (+ tests).
- `packages/core/src/views/categoryForm.ts` (+ test) — the phone's `CategoryFormValues`, `emptyCategoryForm`,
  `categoryFormFrom`, `categoryMissingForSave` moved to core (`icon: string`), phone repointed; add
  `categoryParentCandidates(categories, direction, editingId)` and `movableTargets(categories, category)`.
- `apps/web/src/features/profile/nav.ts` or the layout — the three new links.
