# 0.8b — The docs library — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the Markdown guides and the in-app Guide as pages of `apps/site`, under `/docs/`, with search, and with the Markdown files as the source of truth.

**Architecture:** Starlight, the docs framework of Astro, in the same app as the landing page. A `glob()` loader reads `docs/self-hosting.md`, `docs/building-android.md`, `docs/building-ios.md`, `SECURITY.md` and `CONTRIBUTING.md` in place, from the repository root. A wrapper gives Starlight the title (the first `#` heading) and the GitHub edit link. One Sätteri plugin removes the first heading and rewrites relative `.md` links. The Guide page renders from `guide.*` in the English catalog; its list of concepts moves from `apps/mobile` to `@saldo/ui`. Four Starlight overrides put the `@saldo/ui` tokens, the Rocky title and the theme key of the landing page on the docs pages.

**Tech Stack:** Astro 7.4, `@astrojs/starlight` 0.42.6 (Pagefind 1.5, Expressive Code 0.44), `@astrojs/markdown-satteri` 0.4.4, `@astrojs/sitemap` 3.7.4. TypeScript 6 for `astro check` (D51). Node ≥ 22.22 for the site (`PATH=/opt/homebrew/bin:$PATH` on the maintainer's machine); the default Node 22 for `pnpm test`.

**Sources of truth:** `docs/superpowers/specs/2026-10-20-docs-library.html` (D53–D60). It extends the 0.8a spec, `docs/superpowers/specs/2026-10-18-marketing-site.html`.

**How this plan was checked.** A spike on 2026-10-20 (in `/tmp`, Starlight 0.42.6 and Astro 7.4.1) proved the loader, the title wrapper and the link plugin before the spec. Every file below was then built in this worktree: `astro check` (0 errors), `astro build`, `biome check` clean, the internal link check clean, Lighthouse mobile ≥ 99. The site has no automated tests (D52). If a library behaves differently on the day you run this, follow the library's docs and fix this plan in the same commit (AGENTS.md).

- [x] **Step 4: The link plugin.** Create `apps/site/src/lib/repoLinks.ts`. A plugin factory gets the file URL; it returns `null` for every file that is not in `DOC_FILES`. It rewrites every relative link to a file (`.md` or not, such as `../LICENSE`), and keeps the query and the anchor.

```ts
import { posix, relative, sep } from 'node:path';
import { fileURLToPath } from 'node:url';
import type { SatteriProcessorOptions } from '@astrojs/markdown-satteri';
import { DOC_FILES, docPath, isDocFile } from './docs';
import { blobUrl } from './links';

type MdastPluginEntry = NonNullable<SatteriProcessorOptions['mdastPlugins']>[number];

/**
 * A relative link to a file, with an optional query or anchor: `./self-hosting.md#configuration`,
 * `../LICENSE`. Not a URL with a scheme, not an anchor alone, not a root-relative path.
 */
const RELATIVE_LINK = /^(?![a-z][a-z0-9+.-]*:|[#/])([^?#]+)([?#].*)?$/i;

/**
 * Spec 0.8b §04 (D54): the Markdown files keep relative links, so they work on GitHub. On the
 * site, a link to a file of the library goes to its page, and a link to any other file goes to
 * GitHub. The first `#` heading goes too: Starlight shows the title as the page `h1`.
 *
 * `root` is the repository root as a file URL. The plugin leaves every other Markdown file alone.
 */
export const repoLinks =
  (root: URL): MdastPluginEntry =>
  ({ fileURL }) => {
    if (!fileURL) return null;
    const from = relative(fileURLToPath(root), fileURLToPath(fileURL)).split(sep).join('/');
    if (!isDocFile(from)) return null;
    return {
      name: 'saldo-repo-links',
      heading(node, ctx) {
        if (node.depth === 1) ctx.removeNode(node);
      },
      link(node, ctx) {
        const match = RELATIVE_LINK.exec(node.url);
        if (!match?.[1]) return;
        const target = posix.normalize(posix.join(posix.dirname(from), match[1]));
        const rest = match[2] ?? '';
        const url = isDocFile(target) ? docPath(DOC_FILES[target]) : blobUrl(target);
        ctx.setProperty(node, 'url', `${url}${rest}`);
      },
    };
  };
```

```ts
import { defineCollection } from 'astro:content';
import { readFile } from 'node:fs/promises';
import { docsSchema } from '@astrojs/starlight/schema';
import { glob, type Loader } from 'astro/loaders';
import { DOC_FILES, isDocFile } from './lib/docs';
import { editUrl } from './lib/links';

/**
 * Spec 0.8b §03 (D53): the `docs` collection reads the Markdown files of `lib/docs.ts` where they
 * are, from the repository root. The files have no frontmatter (GitHub shows it as a table), so the
 * wrapper gives Starlight the title from the first `#` heading, and the GitHub edit link.
 */
const files = glob({
  base: '../..',
  pattern: Object.keys(DOC_FILES),
  generateId: ({ entry }) => (isDocFile(entry) ? `docs/${DOC_FILES[entry]}` : entry),
});

const repoMarkdown: Loader = {
  name: 'saldo-repo-markdown',
  load: (context) =>
    files.load({
      ...context,
      parseData: async (props) => {
        const file = new URL(props.filePath ?? '', context.config.root);
        const path = Object.keys(DOC_FILES).find((each) => file.pathname.endsWith(`/${each}`));
        // Skip fenced code first: a shell comment such as `# macOS` is not the title.
        const text = (await readFile(file, 'utf8')).replace(/^(```|~~~)[\s\S]*?^\1/gm, '');
        const title = /^# (.+)$/m.exec(text)?.[1]?.trim();
        if (!path || !title) throw new Error(`${file}: not in lib/docs.ts, or no "# " heading.`);
        return context.parseData({
          ...props,
          data: { ...props.data, title, editUrl: editUrl(path) },
        });
      },
    }),
};

export const collections = {
  docs: defineCollection({ loader: repoMarkdown, schema: docsSchema() }),
};
```

Create `apps/site/src/scripts/docs-theme.ts`:

```ts
/**
 * Spec 0.8b §06 (D57): the theme toggle of the docs pages. It shares `saldo-site-theme` with the
 * landing page (spec 0.8a §08). `ThemeProvider.astro` already applied the choice before the first
 * paint. Starlight needs `data-theme` to be `light` or `dark`, so «System» follows the media query.
 */
export {};

const KEY = 'saldo-site-theme';
const cycle = { system: 'light', light: 'dark', dark: 'system' } as const;
type Choice = keyof typeof cycle;

const root = document.documentElement;
const light = matchMedia('(prefers-color-scheme: light)');

const current = (): Choice => {
  const choice = root.dataset.themeChoice;
  return choice === 'light' || choice === 'dark' ? choice : 'system';
};

const buttons = document.querySelectorAll<HTMLButtonElement>('[data-docs-theme]');

function apply(choice: Choice): void {
  root.dataset.themeChoice = choice;
  root.dataset.theme = choice === 'system' ? (light.matches ? 'light' : 'dark') : choice;
  for (const button of buttons) {
    button.setAttribute('aria-label', button.getAttribute(`data-label-${choice}`) ?? choice);
  }
}

apply(current());
light.addEventListener('change', () => {
  if (current() === 'system') apply('system');
});

for (const button of buttons) {
  button.addEventListener('click', () => {
    const choice = cycle[current()];
    apply(choice);
    try {
      if (choice === 'system') localStorage.removeItem(KEY);
      else localStorage.setItem(KEY, choice);
    } catch {
      // Private mode: the choice lasts for this page only.
    }
  });
}
```

}));
