# End-to-end tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cover the flows listed in `TODO.md` («End-to-end tests») with Playwright for the web app and Maestro for the phone.

**Architecture:** The web suite runs one PGlite database (served over a socket) and one `next start` server for the whole run. The `setup` project walks the first-run wizard once and saves the admin session. Every other spec creates its own member (invite, passkey, onboarding, optional seed) so specs never share rows. The phone suite adds Maestro flows next to the two that exist.

**Tech Stack:** `@playwright/test` (Chromium, virtual WebAuthn authenticator through CDP), `@electric-sql/pglite-socket`, `tsx`, Maestro.

Rules for every spec (they come from `AGENTS.md`):

- Test flows, not copy. Read every visible string from the catalog through the `t` fixture: `t('home.title')`. Never write a literal.
- Prefer roles and labels (`getByRole`, `getByLabel`). Add a `data-testid` only when no role or label is stable.
- Assert behaviour: URL, a row that appears, a total that changes. Do not assert styling.
- A test starts from state it creates itself. Use `createMember` (see Task 0). Do not rely on the order of other specs.
- When a flow shows a real bug, write the failing test, tell the user, and fix the bug in a separate commit.

## Task 0: Web harness (done)

**Files:**
- Create: `apps/web/playwright.config.ts`, `apps/web/e2e/env.ts`, `apps/web/e2e/dbServer.ts`, `apps/web/e2e/fixtures.ts`
- Create: `apps/web/e2e/support/authenticator.ts`, `state.ts`, `onboarding.ts`, `members.ts`

- Modify: `apps/web/package.json` (scripts `e2e`, `e2e:install`), `.github/workflows/ci.yml`

What exists after this task:

- `pnpm --filter web e2e` builds the app, starts the database and the server, and runs the specs. `E2E_SKIP_BUILD=1` reuses `.next`. `E2E_DEV=1` uses `next dev`. `E2E_PORT` and `E2E_DB_PORT` move the ports, so two checkouts can run at once.
- `test` and `expect` come from `e2e/fixtures.ts`. The fixtures are `t` (translator for the project locale) and `authenticator` (a virtual passkey device on `page`).
- `createMember(browser, t, { name, email, seed?, skipOnboarding? })` returns `{ id, name, email, context, page, authenticator }`. It mints an invite, registers with a virtual passkey and completes onboarding. With `seed: true` it runs `scripts/seed.ts`. Close `member.context` at the end of the test.
- `mintInvite(label?)` returns an invite code. `ADMIN_STORAGE` is the admin session file; `ADMIN` has the admin's name, email and instance name.
- The `setup` project (`01-setup.spec.ts`) creates the admin and finishes the admin's onboarding. It runs first. The `chromium` project depends on it.

## Web tasks

Each task adds one spec file in `apps/web/e2e/`, named as shown. For each task:

1. Read the pages and components that the flow touches, to find labels and roles.
2. Write the spec. Run it with `E2E_SKIP_BUILD=1 rtk proxy pnpm --filter web exec playwright test <file> --reporter=line`.
3. Run it three times in a row. A flaky test is a failed test: fix the wait, not the timeout.
4. Run `pnpm lint` and `pnpm --filter web typecheck`. Read the output for `lint/` lines.
5. Do not edit `TODO.md` yet. Remove the item when the whole list is done.
6. Commit: `test(web): e2e <area>`.
