# 0.3e-1 — The web writes: the write path, the transaction form and onboarding

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a user adds, edits and deletes a transaction from the web and it reaches the phone on its next pull; a
web-first account onboards at `/onboarding` and gets the §4.2 seed.

**Architecture:** the server becomes a sync client (§17.1.3). A write is a Server Action that loads the `UserData`,
builds the entity with the **same `@saldo/core` functions the phone's form uses**, stamps it with a **server HLC**
(one clock per instance, a single-row table advanced under a row lock) and hands it to **`applyPush`**, the upsert
`POST /api/sync/push` already runs — inside the push route's own epoch share lock. Nothing writes `sync_rows` any other
way. The form is a client component inside the existing trailing `Panel`; the URL still carries the state
(`?new`, `?t={id}&edit`, `?deleted={id}`).

**Tech Stack:** Next 16 App Router (Server Components, Server Actions called from client components), Drizzle over
Postgres (PGlite in tests), Base UI (`@base-ui/react`) for the dialog, the select and the toast, CSS Modules over the
token custom properties, `@saldo/core` for every rule, `@saldo/i18n` for every string. Tests: Vitest in `apps/web`
and `packages/core`, Jest in `apps/mobile` for the refactors.

The roadmap's 0.3e row is five things: the server HLC, Server Actions through the push upsert, the
transaction/account/category/budget forms, web onboarding and the seed. Written as one plan it would be three times
0.3d's. It is three plans, each shippable on its own, executed in order on the branch `phase/0.3e-writes`:

| Plan | Content |
|---|---|
| **0.3e-1 (this one)** | server clock, `writeChanges`, the transaction form (new, edit, delete, undo), «Nuova transazione» in the top bar and the FAB, the keyboard (N, E, ↑ ↓, Esc, ⌘↵), `/onboarding` and the seed with deterministic ids, a **temporary** dev sign-in route |

## Decisions taken while writing this plan

1. **Deterministic ids for the seed categories** (§17.1.3 left it to the plan; «the lead option»). A seed category's
   id is `seed-category-{nameKey}` on the phone *and* the web, so a phone that onboarded offline and a web
   onboarding of the same account converge on one row per category by LWW instead of doubling every category. The
   **first account keeps a random id**: two onboardings that named two different accounts described two accounts,
   and merging them would lose one. `settings` already converges (`id: 'settings'`).
2. **The seed moves into `@saldo/core`** (`seed.ts`), `icon: string` instead of `IconName` (core imports no other
   workspace package), as `transactionRow` did in 0.3d. The phone's `seedFromOnboarding` becomes a loop over what core
   returns. A mobile test keeps every seed icon a real `IconName`.
3. **The transaction form's rules move into `@saldo/core`** (`views/transactionForm.ts`): `TransactionFormValues`,
   `emptyForm`, `formFromTransaction`, `missingForSave`, `canSave`, `toTransactionInput`, `changeKind`, `dateChoices`,
   `tagSuggestions`, `canCreateTag`. They are pure and core-only already. The three `details*` helpers stay in
   `apps/mobile`: the «Dettagli» disclosure is the phone's layout, not a rule.
4. **The transfer preview runs on balances, not on the ledger.** The client cannot receive every transaction to call
   `transferBalancePreview`. Core gains `previewFromBalances` and `fillsFromBalances`, which take today's balances
   (computed on the server by `accountBalances`, the edited row left out) and the draft; `transferFillAmounts` is
   refactored onto `fillsFromBalances`, and a parity test pins `previewFromBalances` to `transferBalancePreview`.
5. **A write never loses to a device's future clock.** A phone's HLC may be up to 24h ahead of the server (§8.2). If
   the server stamped an edit with `hlcNow` alone, the upsert's `setWhere updated_at < excluded.updated_at` would call
   the edit `stale` and silently drop it. The clock therefore **receives** the row's current `updated_at` first
   (`hlcReceive`), so the stamp is always after it. A write that still comes back anything but `applied` throws, and
   the transaction rolls back.
6. **Client components may import `@saldo/i18n/format` and `@saldo/i18n/translate`, never `@saldo/i18n`.** The root
   entry imports all seven catalogs. The form formats a balance while the user types, so 0.3d's decision 8 («no
   number is formatted in a client component») is relaxed for these two subpaths, which import no catalog, and a test
   in `apps/web` refuses a `'use client'` file that imports the root.
7. **The form gets its strings as a slice of the catalog** (`txForm`, `transactions`, `common`, `kinds`) and builds
   its own `t` with `makeTranslator` from `@saldo/i18n/translate`. Three namespaces, not the catalog.
8. **The URL of the form.** `?new` opens «Nuova transazione» in the panel; `?t={id}&edit` turns the detail into the
   form; after a delete the page is `?deleted={id}`, which renders the undo toast. «Nuova transazione» in the top bar
   and the FAB are links to `/transactions?new` from any page.
9. **Delete tombstones the transaction and nothing else**, exactly as the phone's `repos.transactions.remove` (its
   attachments rows stay, as on the phone). «Annulla» writes the same row back with `deletedAt: null` and a new stamp.
10. **An occurrence of a recurrence is edited as that one row** (the phone's «Solo questa»). The web does not edit a
    series (§17.1.9): the form keeps `recurrenceId` and says under «Ripeti» that recurrences are managed on the phone.
    Deleting an occurrence says `transactions.deleteRecurringBody`, as the phone does.
11. **`/onboarding` has three steps**, the phone's fresh path without the device-only ones: (1) the period (kind, and
    the cycle day when the kind is `cycle`), (2) the first account (name, type, currency, current balance), (3) the
    categories. «Inizia» writes everything in one `writeChanges`. The time zone is the browser's
    `Intl.DateTimeFormat().resolvedOptions().timeZone` (§17.1.5). Language and theme are `system`, as on the phone.
    There is no web mockup for onboarding: the layout is the auth pages' one open column with the `Steps` segments,
    which is what the chosen auth variant («4 · Un passo alla volta») already borrows from the phone's onboarding.
12. **The dev sign-in route is temporary.** `GET /api/dev/sign-in?email=…` answers 404 unless
    `NODE_ENV === 'development'` or `'test'`, creates a session for an existing user and sets the Better Auth cookie.
    It exists so the UI can be checked in a browser (sign-in is passkey-only). It is deleted in 0.3e-3's last task,
    and 0.3e is not done while it exists.

## Rules every task follows (the lessons 0.3d wrote down)

- **Grep before you use.** Every i18n key: `grep -n "keyName" packages/i18n/src/locales/it.ts`. Every CSS custom
  property: it must be one `tokensCss()` emits (`packages/ui/src/css.ts`); `--color-surface-raised` does not exist, the
  token is `--color-raised`. Every core function: open it and read its signature.
- **A new key goes into all seven catalogs** (`it en fr de sv es pt`); `locales.test.ts` compares key sets,
  `{{variables}}` and emptiness.
- **Fixtures go through the schema** (`accountSchema.parse(...)`, `transactionSchema.parse(...)`), never a cast.
- **Stage files by full path**, never a directory; check `git status` before committing; one implementing agent at a
  time on this working tree.
- **Gates are read, not trusted:** `rtk proxy pnpm lint` is clean only with no `lint/…` lines and no
  `× Some errors were emitted`. Same for `rtk proxy pnpm typecheck` and `rtk proxy pnpm test`.
- No `any`, no `!`, no hex/rgb colours or literal `font-size`/`border-radius` lengths in `.module.css`
  (`cssTokens.test.ts` enforces the last two).
- Every page under `(app)` and `onboarding` exports `runtime = 'nodejs'` and `dynamic = 'force-dynamic'`.

```ts
/**
 * `transferBalancePreview` for a caller that holds balances rather than the ledger: the web's form,
 * which cannot ship every transaction to the browser (§17.1.3). `balances` must be `accountBalances`
 * over the ledger **without** the row being edited, as the ledger version filters it out itself. A
 * parity test keeps the two answering the same.
 */
export function previewFromBalances(
  balances: ReadonlyMap<string, MinorUnits>,
  draft: TransferDraft,
  today: LocalDate,
): { from: BalancePreview | null; to: BalancePreview | null } {
  const moves =
    draft.fromAccountId !== null &&
    draft.toAccountId !== null &&
    draft.amount > 0 &&
    draft.date <= today;
  const preview = (accountId: string | null, delta: MinorUnits): BalancePreview | null => {
    if (accountId === null) return null;
    const now = balances.get(accountId);
    if (now === undefined) return null;
    return { now, after: moves ? now + delta : now };
  };
  return {
    from: preview(draft.fromAccountId, -draft.amount),
    to: preview(draft.toAccountId, draft.amount),
  };
}
```

```ts
export function fillsFromBalances(
  accounts: readonly (Pick<AccountRef, 'id' | 'type' | 'archivedAt'> & { goalTarget?: MinorUnits | null })[],
  balances: ReadonlyMap<string, MinorUnits>,
  draft: Pick<TransferDraft, 'fromAccountId' | 'toAccountId'>,
): TransferFill[] {
  if (draft.fromAccountId === null) return [];
  const destination = accounts.find((account) => account.id === draft.toAccountId);
  if (destination?.type === 'credit_card') return [];
  const balance = balances.get(draft.fromAccountId) ?? 0;
  if (balance <= 0) return [];
  const fills: TransferFill[] = [{ key: 'balance', minor: balance }];
  if (
    destination !== undefined &&
    destination.type === 'pocket' &&
    destination.archivedAt === null &&
    typeof destination.goalTarget === 'number'
  ) {
    const missing = destination.goalTarget - (balances.get(destination.id) ?? 0);
    if (missing > 0 && missing < balance) fills.push({ key: 'missing', minor: missing });
  }
  return fills;
}
```

```ts
import { type HlcState, type HlcString, hlcNow, hlcReceive, isHlc } from '@saldo/core';
import { eq } from 'drizzle-orm';
import { serverClock } from '../db/schema';
import type { ServerDatabase } from '../db/types';

const CLOCK_ROW = 1;

/**
 * One stamp per row about to be written (§17.1.3). `seen[i]` is the `updated_at` that row has now,
 * or null for a new row: the clock **receives** it first, so the stamp is after it even when the
 * phone that wrote it runs ahead of the server. Otherwise the upsert's LWW would call the web's
 * edit stale and drop it without a word.
 *
 * Runs inside the caller's transaction and holds the clock row's lock until it ends, so two writes
 * never mint the same stamp.
 */
export async function advanceClock(
  tx: ServerDatabase,
  now: Date,
  seen: readonly (HlcString | null)[],
): Promise<HlcString[]> {
  await tx
    .insert(serverClock)
    .values({ id: CLOCK_ROW, deviceId: `server-${crypto.randomUUID()}`, wallMs: 0, counter: 0 })
    .onConflictDoNothing();
  const [row] = await tx
    .select()
    .from(serverClock)
    .where(eq(serverClock.id, CLOCK_ROW))
    .for('update');
  if (row === undefined) throw new Error('server_clock has no row');
  let state: HlcState = { wallMs: row.wallMs, counter: row.counter, deviceId: row.deviceId };
  const stamps: HlcString[] = [];
  for (const previous of seen) {
    const step =
      previous !== null && isHlc(previous)
        ? hlcReceive(state, previous, now.getTime())
        : hlcNow(state, now.getTime());
    state = step.state;
    stamps.push(step.hlc);
  }
  await tx
    .update(serverClock)
    .set({ wallMs: state.wallMs, counter: state.counter })
    .where(eq(serverClock.id, CLOCK_ROW));
  return stamps;
}
```

```ts
import {
  type EntityName,
  type PushResult,
  SYNC_SCHEMA_VERSION,
  type SyncChangeEnvelope,
} from '@saldo/core';
import { and, eq } from 'drizzle-orm';
import { syncRows } from '../db/schema';
import type { ServerDatabase } from '../db/types';
import { lockEpoch } from '../sync/epoch';
import { applyPush } from '../sync/push';
import { advanceClock } from './clock';

/**
 * One row the server writes: every field of the entity **except** `updatedAt`, which the clock
 * stamps. `deletedAt` set to an instant makes it a tombstone (§7).
 */
export interface EntityWrite {
  entity: EntityName;
  id: string;
  data: Record<string, unknown> & { deletedAt: string | null };
}

/** A write the upsert did not apply. It rolls the whole batch back: half a write is worse than none. */
export class WriteRefused extends Error {
  constructor(readonly results: readonly PushResult[]) {
    super(
      `write refused: ${results
        .filter((result) => result.status !== 'applied')
        .map((result) => `${result.entity}/${result.id} ${result.status} ${result.error ?? ''}`)
        .join('; ')}`,
    );
  }
}

/**
 * §17.1.3: **the one way the server writes a row.** The web writes as a sync client: every row gets
 * a stamp from the instance's clock and goes through `applyPush`, the same upsert and validation as
 * `POST /api/sync/push`, under the same epoch share lock — so a deletion of the account's data can
 * never interleave with a web write, and a phone receives the row on its next pull like any other.
 */
export async function writeChanges(
  db: ServerDatabase,
  userId: string,
  writes: readonly EntityWrite[],
  now: Date,
): Promise<void> {
  if (writes.length === 0) return;
  await db.transaction(async (tx) => {
    await lockEpoch(tx, userId);
    const seen: (string | null)[] = [];
    for (const write of writes) {
      const [row] = await tx
        .select({ updatedAt: syncRows.updatedAt })
        .from(syncRows)
        .where(
          and(
            eq(syncRows.userId, userId),
            eq(syncRows.entity, write.entity),
            eq(syncRows.id, write.id),
          ),
        )
        .limit(1);
      seen.push(row?.updatedAt ?? null);
    }
    const stamps = await advanceClock(tx, now, seen);
    const changes: SyncChangeEnvelope[] = writes.map((write, index) => {
      const stamp = stamps[index];
      if (stamp === undefined) throw new Error('advanceClock returned too few stamps');
      return {
        entity: write.entity,
        id: write.id,
        updatedAt: stamp,
        deletedAt: write.data.deletedAt,
        data: { ...write.data, id: write.id, updatedAt: stamp },
      };
    });
    const results = await applyPush(
      tx,
      userId,
      { schemaVersion: SYNC_SCHEMA_VERSION, deviceId: 'server', changes },
      now,
    );
    if (results.some((result) => result.status !== 'applied')) throw new WriteRefused(results);
  });
}
```

```ts
  userId: string,
  entity: E,
  id: string,
): Promise<RowLookup<E>> {
  const [row] = await db
    .select({ data: syncRows.data, deletedAt: syncRows.deletedAt })
    .from(syncRows)
    .where(and(eq(syncRows.userId, userId), eq(syncRows.entity, entity), eq(syncRows.id, id)))
    .limit(1);
  if (row === undefined) return { status: 'missing' };
  const parsed = entitySchemas[entity].safeParse(row.data);
  if (!parsed.success) return { status: 'invalid' };
  return {
    status: 'found',
    row: parsed.data as z.infer<(typeof entitySchemas)[E]>,
    deleted: row.deletedAt !== null,
```

```ts
/**
 * TEMPORARY — deleted by 0.3e-3's last task. Sign-in is passkey-only, so a browser driven by an
 * agent cannot sign in to check the UI. This signs the browser in as an existing account
 * (`?email=`, or the oldest account) by writing the session row Better Auth would write and setting
 * its signed cookie. It does not exist outside `next dev` and the tests.
 */
export async function GET(request: Request): Promise<Response> {
  if (process.env.NODE_ENV !== 'development' && process.env.NODE_ENV !== 'test') {
    return new Response('Not found', { status: 404 });
  }
  const email = new URL(request.url).searchParams.get('email');
  const db = getDb();
  const [account] =
    email === null
      ? await db.select().from(user).orderBy(asc(user.createdAt)).limit(1)
      : await db.select().from(user).where(eq(user.email, email.toLowerCase())).limit(1);
  if (account === undefined) return new Response('No such user', { status: 404 });

  const token = crypto.randomUUID().replaceAll('-', '');
  await db.insert(session).values({
    id: crypto.randomUUID(),
    userId: account.id,
    token,
    expiresAt: new Date(Date.now() + 7 * 24 * 3600 * 1000),
    updatedAt: new Date(),
  });

  // Better Auth's signed cookie: `token.base64(HMAC-SHA256(secret, token))`, URI-encoded.
  const { secret, authCookies } = await auth().$context;
  const key = await crypto.subtle.importKey(
    'raw',
    new TextEncoder().encode(secret),
    { name: 'HMAC', hash: 'SHA-256' },
    false,
    ['sign'],
  );
  const mac = await crypto.subtle.sign('HMAC', key, new TextEncoder().encode(token));
  const signature = Buffer.from(mac).toString('base64');
  const value = encodeURIComponent(`${token}.${signature}`);
  const name = authCookies.sessionToken.name;

  return new Response(null, {
    status: 303,
    headers: {
      location: new URL('/home', request.url).toString(),
      'set-cookie': `${name}=${value}; Path=/; HttpOnly; SameSite=Lax`,
    },
  });
}
```

```ts
  canCreateTag,
  getCurrency,
  type MissingField,
  missingForSave,

  previewFromBalances,
  readSettings,
  type Tag,
  type TransactionFormValues,
  toTransactionInput,
  touchesClosedGoal,
  transactionKindSchema,
  transferOverdrawsSource,
  type UserData,
} from '@saldo/core';
import { z } from 'zod';
import type { ServerDatabase } from '../db/types';
import { loadRow } from '../userData/row';
import { readUserData } from '../userData/read';
import { todayFor } from '../userData/today';
import { env } from '../env';
import { writeChanges } from './writeChanges';

/** What the form sends. Parsed here, because a Server Action's argument is whatever a client posts. */
export const transactionInputSchema = z.object({
  /** Null for «Nuova transazione». */
  id: z.string().min(1).nullable(),
  kind: transactionKindSchema,
  /** The amount as the field holds it: `sanitizeAmountInput`'s buffer, `.` as the separator. */
  buffer: z.string().max(32),
  date: z.string(),
  accountId: z.string().min(1).nullable(),
  toAccountId: z.string().min(1).nullable(),
  categoryId: z.string().min(1).nullable(),
  description: z.string().max(120),
  tagIds: z.array(z.string().min(1)).max(50),
  excludeFromTotals: z.boolean(),
});

export type TransactionInput = z.infer<typeof transactionInputSchema>;

export type WriteError = 'invalid' | 'notFound' | 'closedGoal';

export type SaveResult =
  | { ok: true; id: string }
  | { ok: false; missing: MissingField }
  | { ok: false; error: WriteError };

export type Result = { ok: true } | { ok: false; error: WriteError };

const live = <T extends { archivedAt: string | null }>(rows: readonly T[], id: string | null) =>
  id !== null && rows.some((row) => row.id === id && row.archivedAt === null);

/**
 * The phone's `missingForSave` (§6.16), with the two checks only a server has to make: every id the
 * form names must be one of **this user's** live rows, and a transfer must not overdraw its source
 * (`transferOverdrawsSource` over today's balances, the edited row left out — as the phone's form).
 */
function missing(data: UserData, values: TransactionFormValues, editingId: string | null, today: string): MissingField | null {
  const { minorDigits } = getCurrency(readSettings(data.settings).currency);
  const basic = missingForSave(values, minorDigits);
  if (basic !== null) return basic;
  if (!live(data.accounts, values.accountId)) return 'account';
  if (values.kind === 'transfer') {
    if (!live(data.accounts, values.toAccountId)) return 'destination';
    const balances = accountBalances(
      data.accounts,
      data.transactions.filter((tx) => tx.id !== editingId),
      today,
    );
    const preview = previewFromBalances(
      balances,
      {
        id: editingId ?? 'draft',
        amount: toTransactionInput(values, minorDigits).amount,
        date: values.date,
        fromAccountId: values.accountId,
        toAccountId: values.toAccountId,
      },
      today,
    );
    const source = data.accounts.find((account) => account.id === values.accountId);
    return transferOverdrawsSource(source, preview.from) ? 'insufficientFunds' : null;
  }
  return live(data.categories, values.categoryId) ? null : 'category';
}

export async function saveTransaction(
  db: ServerDatabase,
  userId: string,
  raw: unknown,
  now: Date,
): Promise<SaveResult> {
  const parsed = transactionInputSchema.safeParse(raw);
  if (!parsed.success) return { ok: false, error: 'invalid' };
  const input = parsed.data;
  const data = await readUserData(db, userId);
  const settings = readSettings(data.settings);
  const { today } = todayFor(settings, env().defaultTimeZone, now);
  const existing =
    input.id === null ? null : (data.transactions.find((tx) => tx.id === input.id) ?? null);
  if (input.id !== null && existing === null) return { ok: false, error: 'notFound' };
  if (existing !== null && touchesClosedGoal(existing, data.accounts)) {
    return { ok: false, error: 'closedGoal' };
  }
  const values: TransactionFormValues = { ...input, recurrence: null };
  const gap = missing(data, values, existing?.id ?? null, today);
  if (gap !== null) return { ok: false, missing: gap };
  const tagIds = input.tagIds.filter((id) => data.tags.some((tag) => tag.id === id));

  const { minorDigits } = getCurrency(settings.currency);
  const fields = { ...toTransactionInput(values, minorDigits), tagIds };
  const id = existing?.id ?? newId();
  const row =
    existing === null
      ? { ...fields, id, recurrenceId: null, createdAt: now.toISOString(), deletedAt: null }
      : // The note and the recurrence are not on the web's form (§17.1.9): an edit keeps them.
        { ...existing, ...fields, note: existing.note, recurrenceId: existing.recurrenceId };
  const { updatedAt: _stamp, ...unstamped } = row as typeof row & { updatedAt?: string };
  await writeChanges(db, userId, [{ entity: 'transaction', id, data: unstamped }], now);
  return { ok: true, id };
}

/** A tombstone (§7), as the phone's `repos.transactions.remove`: its attachments stay as they are. */
export async function deleteTransaction(
  db: ServerDatabase,
  userId: string,
  id: string,
  now: Date,
): Promise<Result> {
  const data = await readUserData(db, userId);
  const existing = data.transactions.find((tx) => tx.id === id);
  if (existing === undefined) return { ok: false, error: 'notFound' };
  if (touchesClosedGoal(existing, data.accounts)) return { ok: false, error: 'closedGoal' };
  const { updatedAt: _stamp, ...row } = existing;
  await writeChanges(db, userId, [{ entity: 'transaction', id, data: { ...row, deletedAt: now.toISOString() } }], now);
  return { ok: true };
}

/** «Annulla» in the toast (§5.12): the row as it was, alive again, with a newer stamp. */
export async function restoreTransaction(
  db: ServerDatabase,
  userId: string,
  id: string,
  now: Date,
): Promise<Result> {
  const found = await loadRow(db, userId, 'transaction', id);
  if (found.status !== 'found' || !found.deleted) return { ok: false, error: 'notFound' };
  const { updatedAt: _stamp, ...row } = found.row;
  await writeChanges(db, userId, [{ entity: 'transaction', id, data: { ...row, deletedAt: null } }], now);
  return { ok: true };
}

/** «Crea «X»» in the tag field (§5.10): a new tag, or the one that already has the name. */
export async function createTag(
  db: ServerDatabase,
  userId: string,
  rawName: string,
  now: Date,
): Promise<{ ok: true; tag: Pick<Tag, 'id' | 'name'> } | { ok: false; error: 'invalid' }> {
  const name = rawName.trim();
  if (name.length === 0 || name.length > 40) return { ok: false, error: 'invalid' };
  const data = await readUserData(db, userId);
  if (!canCreateTag(data.tags, name)) {
    const existing = data.tags.find((tag) => tag.name.trim().toLowerCase() === name.toLowerCase());
    if (existing !== undefined) return { ok: true, tag: { id: existing.id, name: existing.name } };
  }
  const id = newId();
  await writeChanges(db, userId, [{ entity: 'tag', id, data: { id, name, createdAt: now.toISOString(), deletedAt: null } }], now);
  return { ok: true, tag: { id, name } };
}
```

```ts
import {
  accountBalances,
  accountChoices,
  type AccountType,
  childCategories,
  emptyForm,
  formFromTransaction,
  getCurrency,
  isPocket,
  type LocalDate,
  type MinorDigits,
  topCategories,
  topLevelCategories,
  type TransactionFormValues,
  type UserData,
} from '@saldo/core';

export interface FormAccount {
  id: string;
  name: string;
  icon: string;
  colorIndex: number;
  type: AccountType;
  pocket: boolean;
  archived: boolean;
  /** Today's balance in minor units, the edited row left out (so the preview does not count it twice). */
  balance: number;
  goalTarget: number | null;
}

export interface FormCategory {
  id: string;
  name: string;
  icon: string;
  colorIndex: number;
  direction: 'expense' | 'income';
  child: boolean;
}

export interface FormView {
  mode: 'new' | 'edit';
  id: string | null;
  initial: TransactionFormValues;
  recurring: boolean;
  today: LocalDate;
  minorDigits: MinorDigits;
  accounts: FormAccount[];
  top: { expense: string[]; income: string[] };
  categories: FormCategory[];
  tags: { id: string; name: string }[];
}

/**
 * Everything the web's transaction form reads (§6.16, §17.1.7), computed on the server by the same
 * core functions the phone's form calls, and handed to the client as data.
 */
export function formView(input: {
  data: UserData;
  today: LocalDate;
  currency: Parameters<typeof getCurrency>[0];
  mode: 'new' | 'edit';
  id: string | null;
}): FormView | null {
  const { data, today } = input;
  const { minorDigits } = getCurrency(input.currency);
  const editing = input.mode === 'edit' ? data.transactions.find((tx) => tx.id === input.id) : undefined;
  if (input.mode === 'edit' && editing === undefined) return null;

  const others = data.transactions.filter((tx) => tx.id !== editing?.id);
  const balances = accountBalances(data.accounts, others, today);
  const used = new Set([editing?.accountId, editing?.toAccountId]);
  const visible = data.accounts.filter((account) => account.archivedAt === null || used.has(account.id));
  const accounts = accountChoices(visible, { includePockets: true, keepId: editing?.accountId ?? null }).map(
    (account): FormAccount => ({
      id: account.id,
      name: account.name,
      icon: account.icon,
      colorIndex: account.colorIndex,
      type: account.type,
      pocket: isPocket(account),
      archived: account.archivedAt !== null,
      balance: balances.get(account.id) ?? 0,
      goalTarget: account.goalTarget ?? null,
    }),
  );

  const firstAccount = accounts.find((account) => !account.pocket && !account.archived)?.id ?? null;
  const initial =
    editing === undefined ? emptyForm(today, firstAccount) : formFromTransaction(editing, minorDigits);

  const live = data.categories.filter((category) => category.archivedAt === null);
  const categories: FormCategory[] = [];
  for (const direction of ['expense', 'income'] as const) {
    for (const parent of topLevelCategories(live, direction)) {
      categories.push({ ...pick(parent), child: false });
      for (const child of childCategories(live, parent.id)) categories.push({ ...pick(child), child: true });
    }
  }

  const usage = new Map<string, number>();
  for (const tx of data.transactions) for (const id of tx.tagIds) usage.set(id, (usage.get(id) ?? 0) + 1);
  const tags = [...data.tags]
    .sort((a, b) => (usage.get(b.id) ?? 0) - (usage.get(a.id) ?? 0) || a.name.localeCompare(b.name))
    .map((tag) => ({ id: tag.id, name: tag.name }));

  const upToToday = data.transactions.filter((tx) => tx.date <= today);
  return {
    mode: input.mode,
    id: editing?.id ?? null,
    initial,
    recurring: editing?.recurrenceId != null,
    today,
    minorDigits,
    accounts,
    top: {
      expense: topCategories(data.categories, upToToday, 'expense', { today }).map((c) => c.id),
      income: topCategories(data.categories, upToToday, 'income', { today }).map((c) => c.id),
    },
    categories,
    tags,
  };
}

function pick(category: UserData['categories'][number]) {
  return {
    id: category.id,
    name: category.name,
    icon: category.icon,
    colorIndex: category.colorIndex,
    direction: category.direction,
  };
}
```

  != null` uses `!=` on purpose to catch `undefined`; if Biome's `noDoubleEquals` refuses it, write

```tsx
'use client';

import { type KeyboardEvent, useRef } from 'react';
import styles from './Segmented.module.css';

interface Props<V extends string> {
  label: string;
  value: V;
  options: readonly { value: V; label: string }[];
  onChange: (value: V) => void;
}

/** The phone's segmented control (§6.16) as a radio group: one tab stop, arrows move within it. */
export function Segmented<V extends string>({ label, value, options, onChange }: Props<V>) {
  const refs = useRef<(HTMLButtonElement | null)[]>([]);
  const onKeyDown = (event: KeyboardEvent, index: number) => {
    const step = event.key === 'ArrowRight' || event.key === 'ArrowDown' ? 1 : event.key === 'ArrowLeft' || event.key === 'ArrowUp' ? -1 : 0;
    if (step === 0) return;
    event.preventDefault();
    const next = (index + step + options.length) % options.length;
    const option = options[next];
    if (option === undefined) return;
    onChange(option.value);
    refs.current[next]?.focus();
  };
  return (
    <div className={styles.group} role="radiogroup" aria-label={label}>
      {options.map((option, index) => (
        <button
          key={option.value}
          ref={(node) => {
            refs.current[index] = node;
          }}
          type="button"
          role="radio"
          aria-checked={option.value === value}
          tabIndex={option.value === value ? 0 : -1}
          className={styles.option}
          onClick={() => onChange(option.value)}
          onKeyDown={(event) => onKeyDown(event, index)}
        >
          {option.label}
        </button>
      ))}
    </div>
  );
}
```

```ts
import {
  accountTypeSchema,
  amountBufferToMinor,
  CURRENCY_CODES,
  getCurrency,
  onboardingSeed,
  periodKindSchema,
  SEED_CATEGORIES,
} from '@saldo/core';
import { type AppLocale, catalogs, makeTranslator } from '@saldo/i18n';
import { z } from 'zod';
import type { ServerDatabase } from '../db/types';
import { readUserData } from '../userData/read';
import { writeChanges } from './writeChanges';
import { ACCOUNT_TYPE_ICONS } from '../../features/accounts/accountTypeIcon';

const SEED_KEYS = new Set(SEED_CATEGORIES.map((category) => category.nameKey));

export const onboardingDraftSchema = z.object({
  periodKind: periodKindSchema,
  cycleStartDay: z.number().int().min(1).max(31),
  currency: z.enum(CURRENCY_CODES),
  accountName: z.string().max(60),
  accountType: accountTypeSchema.exclude(['pocket']),
  balanceBuffer: z.string().max(32),
  selectedCategoryKeys: z.array(z.string().refine((key) => SEED_KEYS.has(key))).max(20),
  timeZone: z.string().min(1).max(64),
});

export type OnboardingDraft = z.infer<typeof onboardingDraftSchema>;

/**
 * «Inizia» on the web (§17.1.3): settings, the first account and the §4.2 seed in **one**
 * `writeChanges`, built by the same `onboardingSeed` the phone calls. An account that already has
 * settings is left alone — a phone may have onboarded it meanwhile, and its rows win (§8.3).
 */
export async function finishWebOnboarding(
  db: ServerDatabase,
  userId: string,
  raw: unknown,
  locale: AppLocale,
  now: Date,
): Promise<{ ok: true } | { ok: false; error: 'invalid' | 'alreadyOnboarded' }> {
  const parsed = onboardingDraftSchema.safeParse(raw);
  if (!parsed.success) return { ok: false, error: 'invalid' };
  const draft = parsed.data;
  if ((await readUserData(db, userId)).settings !== null) return { ok: false, error: 'alreadyOnboarded' };

  const t = makeTranslator(catalogs[locale]);
  const { minorDigits } = getCurrency(draft.currency);
  const name = draft.accountName.trim();
  const seed = onboardingSeed({
    periodKind: draft.periodKind,
    cycleStartDay: draft.cycleStartDay,
    currency: draft.currency,
    language: 'system',
    theme: 'system',
    completedAt: now.toISOString(),
    timeZone: draft.timeZone,
    account: {
      name: name.length > 0 ? name : t('seed.firstAccount'),
      type: draft.accountType,
      openingBalance: amountBufferToMinor(draft.balanceBuffer, minorDigits),
      icon: ACCOUNT_TYPE_ICONS[draft.accountType],
    },
    selectedCategoryKeys: draft.selectedCategoryKeys,
    translate: (key) => t(`seed.${key}`),
  });
  const meta = { createdAt: now.toISOString(), deletedAt: null };
  const accountId = crypto.randomUUID();
  await writeChanges(
    db,
    userId,
    [
      { entity: 'settings', id: 'settings', data: { ...seed.settings, ...meta } },
      ...(seed.account === null ? [] : [{ entity: 'account' as const, id: accountId, data: { ...seed.account, ...meta } }]),
      ...seed.categories.map((category) => ({ entity: 'category' as const, id: category.id, data: { ...category, ...meta } })),
    ],
    now,
  );
  return { ok: true };
}
```

  `IconName`, and `@saldo/ui` may import core types) as `accountTypeIcons`, repoint the phone, and import it here from
